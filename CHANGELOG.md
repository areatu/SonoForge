# CHANGELOG — SonoForge

Все значимые изменения проекта. Формат записи: `[feat/fix/refactor/perf/docs/chore]: описание` (коммит-конвенция).

## Как устроен файл

* **`Unreleased`** — всё, что уже в `main`, но ещё не выпущено. Новые записи добавляются сюда, в начало.
* **`changelog/YYYY-MM.md`** — история по месяцам. При выпуске релиза его раздел переезжает
  в файл своего месяца, а в `Unreleased` остаётся только строка «выпущено в vX.Y.Z».
  Так `CHANGELOG.md` остаётся читаемым, а история — полной (S3-03, issue 312).
* Один PR = одна запись в `Unreleased`, с номерами issue/спеки и результатами прогонов.

### Security

- `feat(security)`: QH-2b срез 1 — чистый evaluator транспортной политики `application/transport_policy.py` (S-08, спека QH §6.2; без сети, Qt, настроек и клиентов — только stdlib). Решение по *распарсенному* endpoint: HTTPS/DIMSE-TLS с проверкой peer — `allow`; plaintext HTTP / clear DIMSE / TLS без проверки к loopback-литералу (`127/8`, `::1`, IPv4-mapped loopback) или ровно `localhost` — `allow-loopback`; к чему угодно ещё, включая RFC1918/CGNAT/link-local/ULA («частная сеть — не доказательство доверия»), — `block-plaintext-remote` / `block-dimse-clear-remote` / `block-tls-unverified` до явного **scoped** исключения (`InsecureException`: транспорт + хост + порт + TLS-flavour; смена любого поля — новое решение; глобального «HTTP разрешён» выразить нельзя), после которого решение `allow-by-exception` несёт постоянную метку `insecure`. Look-alike не loopback: `localhost.attacker.example`, `127.0.0.1.nip.io`, `127.1`, `0177.0.0.1`, `2130706433`, `0x7f.0.0.1`, `user@127.0.0.1`. Некорректные адреса (`0.0.0.0`/`::`, без схемы, `ftp://`, userinfo в URL, порт вне 1–65535, невалидное имя) — `block-invalid-endpoint`, исключением не снимается, адрес эвристически не чинится. Redirect: HTTPS→HTTP — `block-redirect-downgrade` всегда; цель оценивается сама по себе (доверие loopback на удалённый `Location` не распространяется); credentials/секретные заголовки идут дальше только при той же authority (схема+хост+порт) — `forward_credentials`. `evaluate_profile()` судит корень QIDO/WADO, STOW-override и DIMSE по отдельности. Findings и `Decision.summary()` не содержат userinfo, query, UID, путей и секретов. Тесты: `tests/security/test_transport_policy.py` (112) — все сценарии §6.3 «unit tests pure evaluator»; само-утверждающие `TestHttpUrlWarning`/`test_http_default_gets_marked` в `test_https_enforcement.py` заменены на `TestHttpUrlPolicy` и проверку дефолтного профиля через настоящий evaluator (A-09 на уровне решения), циклы проверки `verify=`/`timeout` стали невакуумными (≥2 построенных `httpx.Client`). Оба файла — в манифесте обязательных security-тестов. **Не входит** (срез 2): подключение к `OrthancDicomWebClient`/`PynetdimseClient`/диалогу настроек, миграция профилей с `needs_confirmation`, тест «0 сетевых запросов», RU/EN-предупреждение; `SECURITY.md` это явно оговаривает.
