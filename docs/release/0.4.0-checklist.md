# SonoForge 0.4.0 — release checklist

This is a preparation checklist, not evidence that 0.4.0 has been published.
The [package matrix](package-matrix.md) is the source of truth for artifact
names, smoke tests, SBOMs and known acceptance gaps.

1. Merge the release preparation, run CI and review the screenshots for patient
   information. Masking burned-in text is not a guarantee of anonymization.
2. On the actual release date, set `date-released` in `CITATION.cff` and archive
   the `Unreleased` changelog fragments according to `CHANGELOG.md`. Do not
   fabricate a date or a version-specific DOI before publication.
3. Run the Release workflow with `verify_only` on the release commit. Verify the
   platform smoke results, especially the `.deb` first-run bootstrap, and perform
   the remaining manual acceptance checks in the package matrix.
4. Tag the release commit `v0.4.0`. Both Release and Presenter workflows run
   on this tag. Wait for **both** workflows to succeed: the full release is
   published first, and Presenter attaches its assets only after the full
   workflow succeeds. A green full workflow alone is not a complete release.
5. Check the published release includes:
   - `sonoforge_0.4.0_amd64.deb`, Windows `SonoForge-Setup-0.4.0-x64.exe`
     and `SonoForge-0.4.0-portable.exe`, and `SonoForge-0.4.0-macos-arm64.dmg`;
   - `sonoforge-0.4.0.tar.gz`, `SonoForgePresenter-0.4.0.exe` and
     `SonoForge-Presenter-0.4.0-x86_64.AppImage`;
   - `SHA256SUMS`, `SHA256SUMS-presenter.txt`, `latest.json`, build records and
     platform SBOMs. An optional `SHA256SUMS.asc` requires the configured GPG key.
6. Download the published files and run `sha256sum -c SHA256SUMS` and
   `sha256sum -c SHA256SUMS-presenter.txt`. Review the workflows' downloaded-byte
   verification evidence, attestations and `latest.json`. Re-run or repair a
   failed workflow before announcing the release.

Windows/macOS OS code signing and notarization are not provided; Presenter USB
acceptance, the Debian bootstrap and clinical acceptance remain explicit gaps in
the matrix. SonoForge is for research and education, not clinical decisions.
