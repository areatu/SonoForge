именно это — вызов мока не произошёл, состояние не изменилось, в лог ушла запись,
сигнал не испущен, ресурс закрыт. Никаких `assert x is not None` ради гейта.

## 2. Находки

1. **Имя лжёт.** `test_wider_band_raises_on_empty` принимал «либо успех, либо
   исключение — оба допустимы» и на своём входе фактически **успешно отрабатывал**,
   то есть не мог упасть ни при каком поведении. Теперь это два детерминированных
   теста: одинокий пиксель → `ValueError("cannot locate mitral annulus with wider
   band")`; маленькое центрированное пятно → три точки в ожидаемых границах.
2. **«No crash = pass».** `TestMaybePromptEsAuto` ничего не проверял; фактическая
   логика — подсказка про систолу показывается только после ED, в строку
   статуса и в оверлей. Теперь проверено и «только после ED», и текст.
3. **Тест называется по тому, чего он не делает.** `test_does_not_raise` для
   `invalidate_norm_cache()` не говорил, что сброс вообще происходит; теперь
   проверяется, что следующий доступ перечитывает нормы, а до сброса кэш общий.
4. **Дубли.** `test_print_summary_disabled` существовал в двух файлах, слабая
   копия в `test_infrastructure_extended.py` теперь проверяет то же, что сильная.
5. **Приёмка «принято» без проверки результата.** Для `validate_dicom_header`
   возврат `None` — часть контракта; изменение его на флаг или список теперь
   заметят оба набора тестов.

## 3. Новая категория гейта: ручные диагностики

`@pytest.mark.interactive` (ручная диагностика: печатает отчёт для человека,
`addopts` не запускает её ни по умолчанию, ни в CI) считается отдельной строкой
«manual» и долгом не является — как измерения `benchmark`. Лазейка дорогая: помеченный
так тест не запускается нигде и виден в диффе. Под правило попал единственный
такой тест, `tests/interactive/test_cine_segment_diagnostics.py`. Правило записано
в скрипте, `CONTRIBUTING.md` и `tests/README*.md`.

## 4. Ratchet на приватный доступ в тестах viewer

`ViewerWidget` — 9,4 тыс. строк, 236 приватных атрибутов; тесты читают и пишут их
напрямую, поэтому декомпозиция (#305, #307) сломает сотни тестов, которые ничего не
говорят о поведении. Из 222 приватных имён в `test_viewer_widget.py` только у 5
есть одноимённый публичный аналог, то есть «перевести на публичный контракт» без
изменения самого виджета невозможно. Поэтому срез делает движение к нулю
**односторонним**, а не пытается переписать 600 обращений.

`scripts/check_test_private_access.py` (stdlib, шаг job `lint`, сводка в Checks →
lint → Summary):

- считает обращения `obj._name` (не `self`/`cls`, без dunder и голого `_`) и
  строковые формы `getattr`/`setattr`/`hasattr`/`delattr(obj, "_name")`,
  `monkeypatch.setattr(obj, "_name", …)`, `patch.object(obj, "_name")`;
- область — `tests/unit/test_*viewer*.py` (10 файлов с обращениями): лимит — **сумма**
  по области, поэтому перенос тестов между viewer-файлами ничего не меняет, а новый
  файл с `viewer` в имени начинает с нулевого допуска;
- рост валит проверку и называет файл с приростом; **меньшее** число, не записанное
  в `scripts/test_private_access_baseline.json`, тоже валит её — улучшение нельзя
  потратить повторно; `--fix` только снижает и отказывает при росте;
- `--list` печатает список работ: файлы и самые частые приватные имена
  (`_current_frame` ×36, `_doppler` ×35, `_debug_overlay_visible` ×18,
  `_contour_stage` ×17, …).

Первый результат: **794 → 783** — 11 обращений заменены эквивалентными публичными:
чтение через `ghost_mode`, `magnetic_snap_enabled()`, `despeckle_enabled()`,
`results_overlay_custom_position()`; запись через `set_ghost_mode(...)`; вызов
`refresh_dicom_tags_overlay()` вместо приватного двойника.
