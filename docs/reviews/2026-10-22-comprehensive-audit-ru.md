## 1. Резюме для владельца (TL;DR)

**Что это за продукт по факту.** Не «просмотрщик DICOM» и не «платформа», а **специализированная
эхо-станция количественного анализа**: контуры ЛЖ/ЛП/ПП/ПЖ, Simpson, Teichholz, LVM/RWT, допплер
(PSV/EDV/VTI/PISA/continuity/MS), M-режим с калибровкой по пикселям, STE-стрейн с AHA-17 и bullseye,
AI-сегментация (EchoNet-Dynamic ONNX), PACS (DICOMweb + DIMSE C-FIND/C-GET/C-MOVE/C-STORE + TLS),
PDF-отчёт с нормами ASE, де-идентификация, портативная сборка Presenter. Это **не** 3D/4D-станция,
не worklist-клиент и не регулируемый медизделием продукт — и в коде, и в `SECURITY.md` это сказано честно.

**Сильные стороны (редкие для проекта такого масштаба):**

1. **Домен действительно чистый.** Ноль импортов `domain → infrastructure/application/presentation`
   (не декларация, а ratchet-тест `tests/unit/test_architecture_boundaries.py` + `test_qh3_boundary.py`).
2. **Инженерная дисциплина вокруг денег и пациентов.** Транспортная политика (запрет plaintext/TLS-без-проверки
   для не-loopback, scoped-исключения, hop-by-hop проверка редиректов, срез `Authorization` при смене authority),
   атомарное хранилище измерений с блокировкой и квотами, SHA-256 моделей, санитайзер логов, `safe_diagnostics`
   без утечки текста исключений, де-идентификация с верификацией.
3. **Тестовая культура.** 8 698 тестовых функций (129 тыс. строк тестов при 139 тыс. строк кода — соотношение ~0.93:1),
   88 % покрытия домена, anti-skip гейт по «обязательным» тестам, baseline-гейт количества тестов,
   3-OS логическая матрица, 4 шарда GUI, e2e-бенч 720p как блокирующий тест.
4. **Доказанная производительность.** 30.9 FPS на 720p-цине (p95 межкадрового интервала 33.3 мс, render 0.57 мс,
   Play→первый кадр 59 мс) на 2 vCPU — с зафиксированным «сломанным» baseline, от которого тест защищает.
5. **Честная документация рисков.** `SECURITY.md` прямо перечисляет отсутствие шифрования at-rest, отсутствие
   RBAC/аудита, неподписанные бинарники, ограничения санитайзера. Это редкость и большой плюс.

**Главные слабости:**

1. **Сопровождаемость просела под весом фич.** 3 god-объекта (`ViewerWidget` 8 863 строки/456 методов,
   `MainWindow` 5 941/403, `AppController` 4 281/164), 17 функций > 200 строк (одна — 1 004),
   290 широких `except Exception` (53 из них молча), 4 107 строк мёртвого кода в 18 модулях,
   дубли (два M-mode-калипера, три форматтера отчёта, копия `styled_dialogs`).
2. **Расхождение «обещано / сделано».** README на двух языках дважды обещает **DICOM SR** и «сохранение отчёта в PACS» —
   в коде этого нет (`report_mode/export.py`: «DICOM SR and «В PACS» stay hidden until their own spec»).
   Для клинического продукта это вопрос доверия, а не косметики.
3. **Дистрибуция не воспроизводит lock.** CI гоняется на `uv.lock`, а конечный пользователь `.deb` при первом
   запуске получает `pip install` **без версий**; встроенный установщик зависимостей содержит несуществующие
   пакеты `cv2`/`yaml`; лаунчер и `.deb` допускают Python 3.10+/3.12+, а пакет требует `>=3.11,<3.12`.
4. **Клинически значимая несогласованность:** AI-контуры «на проверке» (`review_pending`) исключаются из расчёта
   **ЛЖ**, но **не исключаются** из расчёта ЛП/ПП/ПЖ — объём ЛП от непринятого контура попадает в оверлей и отчёт.
5. **Гейты недожаты:** покрытие собирается, но не гейтится; GUI-тесты только Linux; наборы
   `tests/regression` (116), `tests/migration` (65), `tests/system` (26), `tests/compat` (21), `tests/integration` (10)
   **не запускаются ни в одном workflow**; `hypothesis`-фаззинг вне CI; нет `mypy`/`pyright` при 84 % аннотаций;
   `ruff` игнорирует `F821` (undefined name) и `F841` (unused local).
6. **Замороженный численный стек.** `numpy>=1.26,<2.0` (последняя 1.x — 1.26.4, 2024) и `requires-python <3.12`
   блокируют Python 3.12/3.13 и любые будущие исправления numpy; причина — дрейф бенчмарков, то есть
   проблему валидации решили пином, а не пере-базлайном.

**Итоговая оценка: 7.1/10** — «сильный специализированный инструмент с инженерной культурой выше среднего,
но с долгом в UI-слое, дистрибуции и в согласованности обещаний/гейтов».

## 4. Насколько приложение сложное по сравнению с конкурентами

### 4.1 Позиционирование

SonoForge занимает нишу **«эхо-количественный анализ на ноутбуке, офлайн, без регуляторики»**.
Это не конкурент PACS-вьюеров (OHIF/Weasis) и не конкурент платформ (3D Slicer): он ближе к
**модулю 2D/strain коммерческой станции**, вынутому из станции и получившему собственный UI.

### 4.3 Инженерная сложность

| Проект | Язык | Объём | Комментарий |
|---|---|---|---|
| 3D Slicer | C++/Python | ~2 млн строк, 140 МБ | платформа; SonoForge — примерно **1/10** |
| OHIF Viewers | TypeScript | 535 МБ репо | веб-вьюер; нет количественного эхо |
| Weasis | Java | 40 МБ | вьюер; нет эхо-квантификации |
| SlicerHeart | Python-расширение | расширение поверх Slicer | 3D/4D-анализ, переиспользует платформу |
| **SonoForge** | Python/PySide6 | **139 тыс. строк src + 129 тыс. тестов** | собственный UI, собственная квантификация, собственный PACS-стек |

Сложность SonoForge **выше, чем у вьюера**, и **сопоставима со специализированным модулем эхо-анализа**:
собственный движок трекинга пятна (NCC + пирамиды + субпиксельное уточнение), собственные калибраторы
допплера/M-режима (включая детектор тиков Samsung), собственный DICOM-стек (WADO/QIDO/STOW + DIMSE + Storage SCP),
собственный де-идентификатор с верификацией. При этом 46 % кода — UI, что типично для desktop-станции:
сложность здесь не в алгоритмах, а в интеграции Qt + медицинских данных.

**Честная формулировка:** по инженерной сложности это «одна станция среднего размера», а не «платформа».
По функциональной амбиции — «рабочая станция кардиолога без 3D и без автоматики».

## 5. Архитектура: насколько она «правильная»

### 5.1 Что действительно хорошо (с доказательствами)

**1. Домен изолирован — не на словах.** `tests/unit/test_architecture_boundaries.py` обходит AST и падает
на любом новом импорте `domain → infrastructure/application/presentation`; проверяются также относительные
и пакетные импорты. Аналогичный ratchet — `test_qh3_boundary.py` (контроллеры viewer не имеют права
импортировать `MainWindow` или I/O-модули). Мой независимый обход подтверждает: **0 рёбер** `domain → infra`.

**2. Порты и адаптеры — там, где это важно.** `domain/ports.py` (`IDicomReader`, `IStudyScanner`, `IVideoReader`,
`IOnnxSegmenter`), `domain/calculations/*` — чистые функции без Qt, `imaging/` — отдельное чистое ядро
(пиксельные утилиты, детектор тиков), куда запрещены импорты слоёв.

**3. Домен приносит реальную пользу тестам.** Логика формул проверяется независимыми синтетическими оракулами
(`tests/unit/test_qh1e_formulas.py`: аналитический полуэллипсоид для Simpson, rel=1e-10 для скаляров),
а не снимками своей же реализации.

**4. Транспортная политика — образцовая для desktop-медицины.** Чистый вычислитель (`application/transport_policy.py`)
без сокетов и Qt: loopback разрешён, RFC1918 — нет, TLS-без-верификации — нет, редирект hop-by-hop,
запрет downgrade `https→http`, срез `Authorization` при смене authority, scoped-исключения, привязанные к
`(transport, host, port, secure, verify)`. Есть 542 строки тестов только на сам вычислитель.

**5. Хранилище измерений.** Атомарная замена (uuid-temp + fsync + rename), `flock`/`msvcrt.locking`,
защита от symlink/junction, лимит 32 МиБ на документ и 1 ГиБ на хранилище, «повреждённая запись блокирует
перезапись», режимы 0700/0600 на POSIX. Это уровень выше среднего для локального desktop-приложения.

**6. Практики вокруг производительности.** `decode_gate.py` — single-flight с приоритетами (INTERACTIVE >
NEIGHBORS > PLAYBACK > BACKGROUND), чтобы кадр, который ждёт пользователь, не стоял за prefetch-батчем;
`frame_cache.py` — forward-arc eviction и emergency trim; `dicom_session.py` — один разделяемый сеанс на файл
с честным объяснением, почему `threading.local()` не работал на пулах PySide6.

**7. Приватность логов.** `safe_diagnostics.py` (только allowlist `operation/code/error_type`, никогда — текст
исключения), `logging/sanitizer` с редактированием UID/путей/URL/полей авторизации, `_SanitizingFileFormatter`,
`faulthandler` в отдельный файл. Плюс тест-«продюсерский ratchet» на отсутствие `logger.exception`/`exc_info`.

### 5.2 Где архитектура нарушена

| Нарушение | Масштаб | Комментарий |
|---|---|---|
| `presentation → infrastructure` | **241** импорт (123 — i18n, 21 — safe_diagnostics, 21 — profile, 15 — user_preferences) | Из оставшихся **48** — это `server_settings`, `orthanc_cache`, `dicom_session`, `dimse_client`, `dicom_deidentifier`, `measurement_report_pdf`, `samsung_calibration_builder`, `measurement_codec`. То есть UI читает DICOM, ходит в PACS и пишет PDF. |

### 5.3 Качество кода «внутри» архитектуры

- **Средняя сложность низкая (3.92)** — это правда хороший показатель; проблема не в «умных» функциях,
  а в **длинных** (17 > 200 строк) и в **широких** `except`.
- **290 широких перехватов**, 53 из них молча (`pass`/`return None`). В UI это часто оправдано
  (не падать из-за одного виджета), но в `measurement_persistence` и `viewer/overlay_controller`
  молчание скрывает дефекты сохранности данных.
- **`ruff` отключает `F821` (undefined name) и `F841` (unused local)** — это скрывает целый класс
  реальных ошибок (NameError в редкой ветке, мёртвые вычисления). `bandit` при этом находит 17 подтверждённых
  мусорных переменных (`vulture`), что подтверждает: `F841` выключен не «на всякий случай».
- **`filterwarnings = ignore::DeprecationWarning`** глобально — deprecation-сигналы Qt/API не видны.

### 5.4 Вердикт по архитектуре

**6.5/10: «чистое ядро, грязный край».** Домен и транспортно-безопасностный слой спроектированы лучше, чем у
большинства desktop-проектов; application-слой — крепкий, но говорит с инфраструктурой напрямую;
presentation — это концентрация всей сложности (46 % кода), с god-объектами и прямым I/O.
Архитектура **не «неправильная»** — она **не доведена до конца**: направление зависимостей соблюдено
на границе домена и нарушено на границе UI↔I/O, а мёртвый код и дубли размывают карту системы.

### 7.2 Механизмы, которые действительно работают

- **Один разделяемый DICOM-сеанс на файл** (`dicom_session.py`) вместо повторного чтения 332 МБ на каждый батч;

- **Кэш LUT** для window/level, чтобы не пересчитывать кадр на каждое движение слайдера.
- **Prefetch** воспроизведения и фоновая загрузка превью с приоритетами.

## 8. Удобство использования

**Сильное:**

- **Клавиатура как первый класс:** реестр сокращений с проверкой конфликтов, контексты (`main-window`,
  `constructor`), подсказки в подсказках и в HELP — единый источник.
- **Палитра команд** (`command_palette.py`) и радиальные меню — быстрый доступ к инструментам.
- **i18n с живым переключением** RU/EN, 2 639 ключей, паритет проверяется тестом.
- **Темы:** 4 палитры, токены, ratchet на «сырые» hex-литералы, проверка контраста пар, скриншот-база.
- **Протоколы исследования** (TP-3): пошаговый сценарий с прогрессом, «поделиться» результатом между шагами,
  подсказки «что делать дальше» — реально снижает когнитивную нагрузку.
- **Настройки под задачу:** масштаб интерфейса 100–250 %, размер шрифта, раскладка (5 режимов),
  состав панели инструментов с undo/redo для самой панели.
- **Ошибки объясняются:** quality gate возвращает причину («кольцо слишком маленькое», «верхушка инвертирована»),
  а не «не удалось».

**Слабое:**

| Проблема | Детали |
|---|---|
| **Нет undo для измерений** | `Del` удаляет контур/калипер немедленно (`main_window._delete_current_contour`), автосейв фиксирует удаление; отмены нет. Для клинического инструмента — риск потери работы. |
| **Доступность** | 16 `setAccessibleName` на весь UI, 23 `setTabOrder`/`setFocusPolicy`; клавиатурная навигация по сложным виджетам (viewer, таблицы измерений) не гарантирована. |
| **Слабая обратная связь при долгих операциях** | Часть путей (PDF, экспорт DICOM, некоторые диалоги) работает синхронно в UI-потоке. |

### 9.2 Слабые места и конкретные дефекты

1. **Установка зависимостей у пользователя — вне lock и без хешей.** `build/linux/sonoforge-launcher` и
   `launcher.py` делают `pip install` списком **без версий**; `.deb` тянет их при первом запуске.
   Риск supply-chain/TOCTOU ровно там, где модель угроз наиболее реалистична (клиника, USB, чужой ноутбук).
2. **Встроенный установщик зависимостей содержит несуществующие пакеты.** `runtime_setup._REQUIRED_PACKAGES`
   включает `cv2` и `yaml`; на PyPI таких дистрибутивов нет (проверено: `pip download cv2`/`yaml` → нет версий).
   Кроме того, список неполон: нет `pylibjpeg*` (JPEG2000), нет `pymupdf`. Путь частично мёртв (его
   перекрывает проверка `check_deps()` в `main.py`), но если он срабатывает — окружение остаётся битым.
3. **Модели качаются как `tar.gz` без контрольной суммы/подписи до распаковки**; проверка SHA-256 —
   только по манифесту **после** извлечения. Защита от tar-slip есть, от подмены архива — нет.
   В манифесте у 2 из 4 моделей `sha256 = None` (в т.ч. альтернативные), и `_verify_model_integrity`
   для них молча возвращается — «непроверяемая» модель.
4. **Нет at-rest шифрования** измерений, кэша и экспортов; нет secure erase; нет RBAC/аудита —
   всё это честно описано в `SECURITY.md`, но для клинического применения остаётся блокером.
5. **Storage SCP не проверяет AE-title/источник** (loopback + эфемерный порт снижают риск, но не убирают).
6. **Нет защиты от «pixel bomb»**: лимит 500 МБ на файл не ограничивает `Rows×Columns×Frames` после
   декодирования сжатого J2K; crafted-файл может дать гигантский массив.
7. **Неподписанные бинарники** (Windows/macOS) — описано и компенсировано аттестациями/SHA256SUMS,
   но SmartScreen/Gatekeeper остаются барьером.
8. **`bandit` HIGH** — `hashlib.sha1` в `report_phrases.py:112` без `usedforsecurity=False`
   (не криптографическое использование, но шумят сканеры).
9. **Мелочь, но заметно:** `dimse_use_tls` по умолчанию `False`; политика это блокирует для remote,
   однако дефолт «plaintext» — не лучшая настройка по умолчанию.

## 14. Приложение: воспроизводимые команды

```bash
# метрики объёма
find src -name '*.py' -exec wc -l {} + | tail -1
find tests -name '*.py' -exec wc -l {} + | tail -1

# сложность и индексы поддерживаемости
radon cc src -s -a --total-average
radon mi src -s | sort -t'(' -k2 -n | head -25

# качество кода
ruff check src tests
bandit -r src -q -f json > /tmp/bandit.json
vulture src/echo_personal_tool --min-confidence 90

# архитектурные ratchet-тесты (без Qt)
pytest tests/unit/test_architecture_boundaries.py tests/unit/test_qh3_boundary.py -q

# Qt-независимое подмножество + покрытие домена
pytest tests/unit -q -m "not gui" --cov=src/echo_personal_tool/domain

# поиск мёртвых модулей: модуль не импортируется ни из одного src-модуля
# (скрипт из §3; учитывает относительные импорты и `__init__.py`)

# проверка дефекта P1-1
python - <<'PY'
from echo_personal_tool.domain.models import Contour
from echo_personal_tool.domain.calculations.chamber_simpson import calculate_chamber
import math
row = col = 0.5
pts = [((25*(1+math.cos(t)))/col, (60*(1-math.sin(t)))/row)
       for t in (math.pi - i*math.pi/1000 for i in range(1001))]
c = Contour(phase="es", view="A4C", chamber="LA", points=pts,
            mitral_annulus=((0, 60/row), (50/col, 60/row)),
            apex_landmark=(25/col, 0), review_pending=True, source="ai")
print(calculate_chamber((c,), "LA", (row, col)).max_volume_ml)  # 78.56 — как у принятого
PY
```
