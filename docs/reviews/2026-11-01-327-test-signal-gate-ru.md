## 1. Что делает гейт

`scripts/check_test_signal.py` — только stdlib (job `lint` ничего, кроме
ruff/mypy и окружения проверки типов, не ставит). Находит тесты **так, как их
собирает pytest**: функции `test*` на уровне модуля, в классах `Test*` (в том
числе вложенных) и в наследниках `unittest.TestCase`; в `tests/**/test_*.py` и
`*_test.py`; при дубликате имени побеждает последнее определение. Сверка с
`pytest --collect-only` (без параметризации): **9 082 = 9 082, расхождений
нет**. Дальше требует у каждого теста:

- **Проверочный сигнал.** `assert`, который может упасть; `pytest.raises` /
  `warns` / `deprecated_call` / `fail` (tripwire в колбэке — настоящая
  негативная проверка); `waitSignal(s)` / `waitUntil` / `waitCallback` (бросают
  по таймауту); `jsonschema.validate` и `check_schema` (бросают при
  несоответствии); любой вызов, имя которого начинается с `assert`
  (`mock.assert_called_once_with`, `np.testing.assert_allclose`,
  `self.assertEqual`, собственный `_assert_valid`).
- **Сигналом не считаются:** `assert True`, `assert 1`, `assert (cond, "msg")`
  (всегда истинны); одинокий `approx(...)`; переменная с именем `snapshot`;
  голый `validate()` — собственные валидаторы проекта
  (`SchemaValidator.validate`) возвращают находки, а не бросают.
- **Измерение, не долг:** тест с фикстурой `benchmark` существует ради времени,
  а не ради проверки (113 тестов в `tests/bench`, `tests/benchmark`).
- **Осознанное «не падает»:** `@pytest.mark.smoke` **и** запись с причиной в
  секции `smoke` файла `scripts/test_signal_baseline.json`. Маркер без записи
  валит проверку — это решение, которое ревьюят, а не бесплатный пропуск.
  Маркер `smoke` не связан с `gui_smoke` (кросс-платформенные GUI-сценарии).

**Baseline** (`scripts/test_signal_baseline.json`, version 1): `no_signal` —
216 node id поимённо, `smoke` — словарь id → причина, `metrics` — эталон для
сравнения в отчёте. Нарушения: новый тест без сигнала; `smoke` без записи;
**устаревшая запись** (тест усилили, удалили или переименовали) — список всегда
равен долгу, а починенный тест не может молча регрессировать. Коды выхода
0/1/2 как у `check_type_ignores.py`.

**`--fix`** создаёт baseline, если его нет, а дальше только убирает записи.
Если есть новый нарушитель, отказывается (код 1): иначе гейт «лечился» бы одной
командой. Переименованный legacy-тест требует ручной правки node id (это видно
в диффе и ревьюится).

**Метрики** в `$GITHUB_STEP_SUMMARY` (Checks → lint → Summary): всего, долг,
измерения, `smoke`, «≤1 `assert`», «без `assert`» — значение, эталон из
baseline и Δ; при падении там же перечислены нарушения. Две последние метрики
**не гейтятся**: лимит на них учил бы дописывать пустые `assert`. Это
индикатор для среза 2 и далее.

## 3. Находки по пути

1. **Два placebo-теста `assert True`** в `tests/unit/test_viewer_widget.py`:
   `TestCrosshair::test_update_measurement_crosshair` («Just verify no crash»)
   и `TestCaliperNodeDrag::test_apply_caliper_node_drag_no_active` («Should not
   raise»). Формально у них есть `assert`, фактически он не может упасть.
2. **Четыре теста «защищены» только словом `snapshot`:** `test_area_chamber`,
   `test_set_state`, `test_forwarding_is_noop_when_inactive`,
   `test_forward_contours_inactive_is_noop`. Регулярка issue искала snapshot
   как фикстуру syrupy; в репозитории таких тестов 0, а слово встречается 480
   раз как атрибут состояния приложения (`state_manager.snapshot`).
3. **Ложное срабатывание самого гейта, найденное сверкой и исправленное.**
   `test_current_schema_matches_codec` и `test_v3_schema_still_validates_a_v3_document`
   проверяют документ через `jsonschema.validate` и `check_schema`, которые
   бросают при несоответствии, но `assert` в них нет. Сигналом признаны полное
   имя `jsonschema.validate` и `check_schema`, но не голый `validate()`
   (см. раздел 1). Это же показывает границу подхода: имя-based гейт знает
   конечный список «бросающих» идиом, остальное закрывают `smoke` и именование
   `assert_*`.
4. **Имя обещает больше, чем проверяет.** `test_patch_is_idempotent`
   (`tests/unit/test_pyqtgraph_export.py`) дважды вызывает патч и ничего не
   сверяет; `test_verify_render_orientation_accepts_the_helper` проверяет
   «принимает» отсутствием исключения.
5. **Безопасность: 10 тестов в долге.** `tests/security/test_dicom_fuzzing.py` (6,
   фаззинг «не падает на мусоре»), `test_model_integrity.py` (3, пустой/`None`
   хеш) и `test_qh4a_diagnostics.py::test_measurement_persistence_survives_deleted_qt_receiver_callback`
   (ER-04: `RuntimeError` из колбэка удалённого Qt-получателя не должен
   выйти наружу). Последний — эталонный кандидат в `smoke`: контракт именно в
   том, что исключение не вылетает; лучше дополнить проверкой лога через
   `caplog`. Для фаззинга честнее проверять *контролируемый* отказ
   (`pytest.raises(<ожидаемое исключение>)`), а не отсутствие падения.
6. **Скрипт из раздела «Проверка» issue устарел.** Он делит текст файла по
   `def test_` и теперь принимает за тесты синтетические исходники в строковых
   литералах тестов гейта: на ветке он покажет 9 150 «тестов» и 499 «без
   сигнала» вместо 9 129 и честных 216. Это артефакт регулярки, а не рост
   долга. Источник правды — `scripts/check_test_signal.py`: он разбирает AST и
   сверен с pytest.

## 4. Чего гейт не ловит (границы)

- **Слабые проверки.** `assert w is not None` проходит гейт и ничего не защищает.
  Доля тестов с ≤1 `assert` (49.3 %) — индикатор, не лимит.
- **Тесты, проверяющие только вызов мока** без проверки результата. Статически
  не отличить от осмысленных `assert_called_once_with`.
- **`assert` в ветке, которая не выполняется**, динамически генерируемые тесты,
  тесты вне `tests/`.
- **Делегирование проверок хелперу.** Если хелпер называется не `assert*`, скан
  его не видит; правило записано в `CONTRIBUTING.md` и `tests/README*.md`.
  Автоматическое разрешение хелперов проверено и отвергнуто: оно «спасло» бы 0
  из 215 тестов, а усложнило бы гейт.
- **Качество причины в `smoke`.** Гейт требует непустую причину, но не её
  осмысленность — это работа ревьюера.

## 5. Как пользоваться

```bash
python scripts/check_test_signal.py                  # проверка (как в CI)
python scripts/check_test_signal.py --github-summary # то же + таблица метрик
python scripts/check_test_signal.py --fix            # после усиления или удаления legacy-теста
```

| Ситуация | Действие |
|---|---|
| Новый тест не прошёл гейт | Проверить поведение; не дописывать `assert x is not None` ради гейта |
| Проверки в хелпере | Назвать его `assert_*` |
| Осознанное «не падает» | `@pytest.mark.smoke` + причина в секции `smoke` baseline |
| Усилил/удалил legacy-тест | `--fix`, закоммитить baseline вместе с тестом |
| Перенёс/переименовал legacy-тест | Поправить node id в `no_signal` вручную, затем `--fix` |

Правило записано в `CONTRIBUTING.md`, `tests/README.md`, `tests/README_RU.md` и
в чек-листе шаблона PR.
