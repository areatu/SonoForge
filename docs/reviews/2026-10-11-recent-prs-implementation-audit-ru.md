## 1. Главные разрывы (функция заявлена/требуется, но работает не как требовалось)

### 1.1 Э5 «Приветственная страница» недоступна в интерфейсе — пустая вкладка показывает заглушку

**Требования:**
- Спека Э5 (§7): «Приветственная страница занимает область просмотрщика, пока во вкладке нет
  загруженного исследования… это **содержимое пустой вкладки**, поэтому `startup_mode="empty"`
  просто открывает одну пустую вкладку **со страницей**».
- Спека Э9 (§8, PR-B): «Пустая вкладка показывает заглушку вместо просмотрщика
  (**будет заменена приветственной страницей в PR-D**)».
- CHANGELOG v0.3.2 заявляет стартовую страницу как Highlight релиза.

**Факт:**
- `presentation/main_window.py`, `_update_main_stack()` (~2539–2554): при пустой вкладке
  показывается `EmptyTabPlaceholder` (`tab_bar.py`, две строки «Откройте исследование» + подсказка),
  а не `StartPage`. `StartPage` лежит внутри `_viewer_stack` → `_content_widget`, который
  показывается только когда `tab.studies` непуст — то есть страница с «Продолжить», «Местами»,
  недавними исследованиями, ссылками и статусом **не видна ни при старте, ни в пустых вкладках**.
- Гонка PR: #126 (start_page.py, PR-D по составу) слит 2026-10-09 15:06, #127 (Э9 с заглушкой,
  «будет заменена в PR-D») — 19:48. Замены не произошло ни в одном последующем PR.
- Тесты фиксируют заглушку как норму: `tests/unit/test_main_window_tabs.py::
  test_window_starts_with_one_empty_tab_and_placeholder` (и ещё 2 проверки `_empty_tab_page`),
  поэтому CI зелёный.

**Что теряется:** кнопки «Открыть папку…/Загрузить с сервера…/Продолжить», недавние места (Э3),
недавние исследования, ссылки на нормативы/документы/обратную связь/настройки/HELP, строка
статуса (версия · профиль · автосохранение) — всё, ради чего делали Э5, включая `Ctrl+O`/`Ctrl+P`
на странице.

### 1.2 Э5 §7.3 «Недавние исследования»: данные собираются, блок не работает

**Требования:** блок заполняется «записями Z2-M (если хранилище включено) и историей загрузок Z3
текущего запуска»; «клик по локальному открывает папку, по серверному — диалог загрузки с
предвыбранным исследованием»; в Presenter блок скрыт.

**Факт:**
- `application/download_history.py` (PR #127, PR-C) пишет записи (`record()` вызывается в
  `_open_server_batch`), но `records()` **не читается нигде в `src/`** — данные мертвы.
- `StartPage.set_recent_studies()` вызывается только с `()` при инициализации; из
  `main_window.py` не вызывается ни разу.
- Сигнал `StartPage.recent_study_requested` — единственный из 10 сигналов страницы,
  который **не подключён** (`main_window.py` ~354–362 подключены все остальные).
- Поведение клика (открыть папку / открыть диалог загрузки с предвыбором исследования) не
  реализовано; `_open_orthanc_dialog()` не принимает предвыбранное исследование.
- Z2-M (локальные исследования из хранилища измерений) не подключены вовсе.
- Оправдание в PR-ах: #127 (PR-C) — «Блок „Недавние исследования“ — PR-D, здесь только данные»;
  CHANGELOG `feat(start-page)` — «Сбор данных истории исследований подключается при реализации
  PR-C». Каждый PR переложил подключение на другой — в итоге не сделал никто.
- HELP_RU §: «раздел недавних исследований **при наличии истории**» — история «никогда не
  появляется», формулировка это маскирует.

### 1.3 Состояние вкладки (Э9 §3/§5): `viewer_state` не заполняется, кадр не восстанавливается

**Требования (§3, §5):** `TabSession.viewer_state_json` — «W/L, калибровки, оверлеи — то, что
сегодня в StateManager»; при возврате во вкладку состояние просмотра (кадр, W/L, позиция
оверлеев) применяется; тесты слоя — «восстановление `viewer_state_json`».

**Факт:**
- `_park_active_tab()` (`main_window.py` ~2358–2370) передаёт **`viewer_state={}` захардкожено**;
  `encode_viewer_state`/`decode_viewer_state` из `tab_session.py` используются только юнит-тестами
  модели. W/L, калибровки, оверлеи вкладка не запоминает.
- `frame_index` сохраняется, но не применяется: `_restore_tab_view()` (~2600) честно пишет
  «The frame index is kept in the tab but not applied yet».
- W/L остаётся глобальным на все вкладки.
- Это раскрыто в Known limitations PR #127 и CHANGELOG — но спека это **требование**, а не опция;
  «отдельным шагом» так и не наступил.

### 1.4 Э10 «Сравнение исследований в multiview» (PR-E) — не реализовано ни одним PR

**Требования (§6):** сравнимость по геометрии (размер кадра и частота ±5 %, `study_uid` не
требуется), бейджи панелей «вкладка N · дата · модальность/вид» (в т.ч. в Presenter-зеркале),
синхронизация по фазе МК с пометкой «без синхронизации», multiview из двух вкладок.

**Факт:**
- `domain/models/multiview.py`, `clips_are_comparable()` (~152–163) — по-прежнему требует один
  `study_uid` (комментарий в дорожной карте это подтверждает).
- Бейджей панелей, синхронизации по фазе и загрузки из двух вкладок нет.
- В #127 значится как будущее («Сравнение клипов из разных вкладок — Э10»), но PR-E не создан,
  в CHANGELOG как отменённый/отложенный не зафиксирован.

## 4. Вывод

При зелёном CI не реализованы «как требовалось» три функции:

1. **Э5 целиком** — страница-приветствие оттеснена заглушкой пустой вкладки (§1.1);
2. **Э5 §7.3 «Недавние исследования»** — сбор данных есть, UI-блок мёртв (§1.2);
3. **Э9 §3/§5 состояние вкладки** — `viewer_state` пишется пустым, кадр не восстанавливается (§1.3);
4. **Э10 (PR-E)** — не начиналась (§1.4), хотя заявлена спекой и дорожной картой.

Рекомендуемый порядок исправления: §1.1 + §1.2 (одно пересечение файлов, чинит Highlight релиза),
затем §1.3 (кадр + минимальный viewer_state: W/L и позиция оверлея), Э10 — отдельным PR.
