# Обзор: 15 пунктов отчёта от 2026-11-18

> **Снимок на 2026-11-18.** Документ фиксирует состояние на эту дату и не обновляется вслед за кодом: актуальное состояние — в коде, `README.md`, HELP и открытых issues.

Ветка `arena/e624f58c-sonoforge`. Основная партия — 11 пунктов улучшения
«Протокола эхокардиографии» — и 4 дополнительных пункта по карточке
происхождения. Все закрыты кодом и тестами; ниже — корневая причина, решение и

## 1. Автотекст из автовставки заключения

**Причина.** Автовставка заключения дописывала служебные фразы про черновик и
ранее добавленный автотекст — они попадали в клинический текст.

**Решение.** Фразы удалены из `report_conclusion.py` (domain+application),
`report_coordinator.py`, контракта и настроек (`preferences_contract.py`,
`user_preferences.py`, диалог); ключи локалей удалены из ru/en. Существующий
ключ `report.notice.draft` (шапка-баннер) не тронут. Тесты
`test_report_conclusion.py` переписаны (класс `TestStudyNotices`),
`test_presentation_user_preferences_dialog.py` — 2 теста вместо 3.

## 2. Заголовок таблицы переносится вместе с таблицей

**Причина.** При 1–2 колонках измерений заголовок таблицы оставался внизу
страницы один, а строки уезжали на следующую.

**Решение.** `infrastructure/measurement_report_pdf.py`: каждый блок группы —
`_GroupBlock` (обёртка вместо `KeepTogether`, который ломает `BalancedColumns`
с wrap=0xffffff); заголовок и первые строки склеены; зазор между блоками —
`gap_before` (хвостовой Spacer уезжает в начало колонки, `Frame._add`
подавляет `spaceBefore`). Заключение тоже собрано `KeepTogether` и получило
`Spacer(8mm)` перед «Заключение» (п.10). Тесты: `test_measurement_report_pdf.py`
(+3 layout-теста; `_flowable_text` рекурсивен по `_content`).

## 3. Режим «Все измерения» в диалоге «Показатели отчёта»

**Причина.** Диалог показывал только строки текущего исследования — настроить
скрытие/порядок показателей будущих отчётов было нечем.

**Решение.**
* `domain/services/report_value_layout.py`: `ReportRowSpec` и `all_report_rows()` —
  каталог строк, ключи которых **в точности** совпадают с ключами билдера
  (`group:parameter:0`): калиперы — `linear.<id>` (группа через тот же
  `group_for_label(caliper_label(raw))`, что и строка), каталожные строки — по
  id (явная карта `_SPEC_GROUPS` + префиксная карта + fallback), производные —
  `lv.sv_teich`, `patient.bsa_source`, индексированные строки аорты
  `linear.<id>.i`, выходы калькуляторов `calc.<id>`. 266 строк.
* `presentation/report_values_dialog.py`: переключатель «Из исследования /
  Все измерения»; дерево строится из групп документа или из каталога
  (`GROUP_ORDER`); выборы скрытия переживают переключение режима (состояние
  читается из дерева явно — сигнал `itemChanged` приходит до применения
  галки), порядок — по группам (`_moved_by_group`).
* `report_coordinator.edit_values` не менялся: `included`/`excluded`/`order`
  уже пишутся в `report_value_excluded` / `report_value_order` prefs.

**Ограничения (осознанные).** В каталог не входят строки с ключами от
произвольного текста (планиметрия `planimeter.<sha>`, именованные сосуды
`vessel.<sha>…`) и спектральные калиперы `spectral.<mode>…` — они
принадлежат конкретному исследованию; их по-прежнему можно править в режиме
«Из исследования». Закреплено тестом
`test_every_row_key_the_builder_prints_is_in_the_catalogue`.

**Тесты.** `test_report_value_layout.py` (+2: уникальность/форма ключей,
покрытие ключей реального документа каталогом),
`test_report_coordinator.py::test_all_measurements_mode_edits_rows_the_study_never_measured`.

## 4. «Аортальный клапан и аорта» + Prox Ao в таблицу аорты

**Решение.** `report.group.av` → «Аортальный клапан и аорта» / «Aortic valve
and aorta»; «Prox Ao» перенесён из «Прочих» в аортальную таблицу
(`report_builder.group_for_label`, `measurement_catalog` +13 меток).

## 5. Происхождение для всех измеренных результатов

**Причина.** ОПП, ОЛП, площади и другие производные строки не несли lineage.

**Решение.** `report_provenance.py`: `linear_caliper_union_origin`,
`ivc_pair_origin` (`IVC_CALIPER_ALIASES`), `caliper_pair_origin`;
`report_builder`: origin для LA/RA (Симпсон `simpson_origin` с методом и
фазой, планиметрия `planimeter_origin`, площадь-длина `derived_origin`),
ОПП (`MONOPLANE`), ДАП+ИКС (`ivc_pair_origin`, `LINEAR_DERIVED`), индексов
(`calculator_origin`/Симпсон по view/фазе). Методы локализованы
(`report.origin.method_*`, `_METHOD_KEYS` в карточке). Карточка честно пишет
«происхождение не записано», где lineage не сохранён (`la.lav_al` без
clips — не выдумываем источники).

## 6–7. Нормы по полу и по актуальным guidelines

**Причина.** иОПП показывал «≤39» как для ОПП; КДО/КСО, площади и другие
строки жили без норм.

**Решение.** Оба YAML (`references_structured.yaml` — источник истины для
`ReferenceDataStore()` без языка — и `_ru`-копия) дополнены и исправлены:
lvedv 62–150/46–106, lvesv 21–61/14–42, lvedvi 34–74/29–61, lvesvi 11–31/8–24
(ASE/EACVI 2015), la_area ≤20 см² (градации 21–30/31–40/≥41), `ra_vol_index`
♂≤34/♀≤27 мл/м² (СОП BJ Cardiology / PH-гайдлайны). Маппинг
`_LABEL_TO_PARAM_ID` расширен (lvedv/lvesv/lvedvi/lvesvi, la area, ra area,
ravi, ao sinus→asc_aorta, ao junction→sinotubular, prox ao→ascending_aorta,
annulus…). УО (`lv.sv`) без норм — нормативно. `ra_area` остаётся **≤18 см²**
(внутреннее решение; cardioserv показывает <19 — расхождение осознанное).

**Тесты.** `test_report_norms.py` (5): нормы КДО/КСО/иКДО/иКСО/ФВ по полу,
иОПП ≤34/≤27 с флагом патологии, смена флага патологии с полом (ФВ 53),
отсутствие ложных срабатываний, индексированные строки аорты.

## 8. Индексированные значения аорты при патологии

**Решение.** `ase_reference_norms.py`: `AO_*_INDEX_MM_M2` (аннулус ≤14,
синусы ≤20, STJ/восходящая ≤17 мм/м², fallback-ключи) +
`should_show_indexed_linear`; `report_builder._aorta_index_entry` — строка
«<Название> (индексированный)» (`domain.report.indexed_linear`), мм/м², норма
своя, появляется только при `absolute.pathological` и наличии BSA.

## 10. Отступ перед «Заключением»

## 11. Выравнивание названий таблиц по верху

## 12. Выбор измерения — в карточке происхождения (по наведению)

**Причина.** «Выбрать измерение» жило в диалоге «Показатели отчёта» —
несколько кликов на одно действие; длинные имена файлов и номера кадров
засоряли выбор.

**Решение.** В hover-карточке (`presentation/report_mode/provenance.py`)
раздел «Варианты измерений»: по одной строке на каждое измерение-кандидат —
**только показатели** (`ReportCandidate.parts`, без имени файла и кадра),
подсвеченные по норме: зелёный (в норме) / красный (патология) /
нейтральный (норма неизвестна). Щелчок закрепляет измерение в отчёте
(`choice_selected` → `preview.value_choice_changed` →
`report_coordinator.choose_value_source` → `tab.report_value_choices`), кнопка
«Авто» возвращает следованию за последним измерением; активный вариант помечен
«✓». Вердикт нормы считает билдер (`_judged_repeat`, `_readings_verdict`) —
только он знает пол пациента; `report_selection.candidate_readings` собирает
показатели (линейные калиперы, объёмы Симпсона LVEDV/LVESV/LAV/RAV) без
оценки. Контекстное меню ПКМ теперь только «Скрыть в отчёте» (п.9) — диалог
остаётся для массовой настройки.

## 13. Позиция и появление карточки

**Решение.** Верхний край карточки — на 8px выше курсора, левый — на 12px
правее (`preview._place_card`): попасть в карточку — короткий сдвиг вправо,
курсор не пересекает следующее значение. Появление — fade-in 120 мс
(`QGraphicsOpacityEffect` + `QPropertyAnimation`).

## 14. «Клипы-источники» убраны из карточки

**Решение.** Список клипов удалён (серверные имена не помещались); источник
подтверждается кнопкой «Открыть кадры». Цепочка `set_clip_label_provider`
(page→preview→card) удалена; диалог по-прежнему показывает полные имена в
своём комбо.

## 15. (Сводка 12–14.) ПКМ — скрыть, наведение — происхождение и выбор

Разделение зафиксировано тестами `test_report_preview.py` (меню — только
скрытие), `test_report_origin_card.py` (варианты без имён файлов, цвета,
эмиссия выбора, позиция карточки).

## Известные ограничения

* Спектральные калиперы и строки произвольного текста не в каталоге «Все
  измерения» (см. п.3).
* Цвет варианта в карточке — по показателям, для которых есть норма;
  показатели без нормы остаются нейтральными (никогда не «красные»).
* `ra_area` ≤18 см² — осознанное расхождение с cardioserv (<19).
* Формат «8.0–24» у малых норм сохранён by design (дробность для значений <10).
