## Зачем

`viewer_widget.py` — около 8 854 строк; `ViewerWidget` — 426 методов и публичные сигналы транспорта, инструментов и оверлеев. План предполагает вынести почти весь файл в кластеры: frame/transport (17 методов), display/lut (13), zoom/pan (20), label picker (33), контурный owner (90). Пока поведение не зафиксировано, любой такой PR проверяется только глазами: тесты покрывают отдельные методы, но не отвечают на вопрос «изменилось ли то, что видит пользователь и приложение».

QH-0 добавляет второй слой — characterization-тесты. Они описывают **текущее** поведение (включая странности), а не желаемое, и не меняют код виджета. Каждый следующий PR по кластеру обязан оставить их зелёными; если поведение действительно меняется, тест правится отдельно и явно, а не «подкручивается» до зелёного.

## Что записывает харнесс

`tests/unit/viewer_characterization.py` знает ровно два шва:

- публичный API `ViewerWidget` и его сигналы;
- `ViewerContract` — ревьюируемый адаптер для Qt-объектов (слайдеры, кнопки, метки), потому что сами виджеты не являются публичной Python-поверхностью.

Внутрь приватных полей виджета харнесс не заходит. Это осознанно: кластер может переехать в другой модуль и переименовать приватные поля, но обязан сохранить наблюдаемый контракт.

| Инструмент | Что фиксирует |
|---|---|
| `SignalRecorder` | все публичные сигналы `ViewerWidget` в порядке эмиссии, с аргументами |
| `viewer_surface()` | timeline, подпись/доступность play, счётчик кадров, FPS, hint, zoom, отображаемые пиксели, значения слайдеров, флаги инструментов, overlay, UID инстанса, число контуров |
| `instance_snapshot()` | поля, которые не должен трогать frame-переход: UID, пиксели, слайдеры, zoom, overlay |
| `contour_snapshot()` | payload `contour_completed`: камера, фаза, вид, кадр, число точек |

Пиксели снимаются с `contract.image_item.image`, а не с `getLevels()`: в текущем коде уровни применяются через `setImage(..., autoLevels=False)` и LUT, поэтому `getLevels()` возвращает `None`. Снимок угловых пикселей проверяет именно то, что видно на экране.

## Какие сценарии заперты

| Сценарий | Что проверяется |
|---|---|
| `set_state` | timeline `(0, total-1, frame)`, счётчик через `tr("viewer.frame_counter")`, FPS через `format_fps`, подпись play, отсутствие ложных сигналов |
| timeline | одно `frame_selected` на реальное изменение; повторная установка значения молчит |
| play | клик даёт ровно `play_pause_requested`, состояние не мутируется |
| zoom | цикл `fit → 100% → 200% → fit`; невалидный режим игнорируется; `zoom_around` меняет только фактор, не документ |
| Ctrl+wheel | зум без кражи кадра: нет `frame_selected`/`scroll_frame_selected`, документ не тронут |
| display levels | движение window-слайдера меняет отображаемые пиксели, но не UID/zoom/overlay; измерение не эмитится |
| overlay | `set_results_overlay_position` меняет позицию и custom-флаг молча; `reset_results_overlay_to_default` у скрытой метки снимает только флаг, коэффициенты остаются до следующей раскладки |
| контур | закрытый контур LA: 4 клика → `contour_completed` с камерой/фазой/видом/кадром/4 точками, `contours_changed`, удаление → undo → redo |
| инструменты | калибровка и линейный калипер взаимоисключающие; `cancel_active_tool()` гасит инструмент и очищает hint; переход не выглядит завершённой калибровкой |
| QH-3 inventory | три owner-scoped контроллера (`ResultsOverlayController`, `TagsOverlayController`, `MagnifierController`) и их порядок; `dispose_viewer_resources()` идемпотентен и не меняет инвентарь |

## Доказательство чувствительности

Просто зелёные тесты ничего не доказывают: они могут не реагировать на изменение поведения. Поэтому харнесс проверен двумя временными мутациями исходника, каждая — с немедленным откатом:

1. цикл zoom заменён на `fit → 100% → 150%`:
   `AssertionError: assert ['fit', '100%', '150%', 'fit'] == ['fit', '100%', '200%', 'fit']`;
2. подпись кнопки play всегда `tr("viewer.play")`:
   `AssertionError: assert 'Воспроизведение' == 'Пауза'` (в текущей локали).

Обе мутации роняют именно тот сценарий, который описывает поведение; после отката `git diff` по `viewer_widget.py` пуст. Это локальная проверка чувствительности, а не исчерпывающий mutation testing.

## Передача кластерам

Порядок из плана не меняется, по одному PR на кластер:

1. **frame/transport (17)** — опирается на сценарии `set_state`, timeline, play и снимок `instance_snapshot`; после выноса `_set_frame_counter_label`/play/timeline харнесс должен остаться без правок.
2. **display/lut (13)** — сценарий display levels: смена слайдера меняет пиксели, но не документ; `getLevels()` сознательно не используется.
3. **zoom/pan (20)** — цикл режимов, `zoom_around`, Ctrl+wheel; отдельно заперто, что зум не эмитит frame-сигналы.
4. **label picker (33)** — characterization здесь опирается на флаг `is_label_picker_visible()` и существующие тесты picker'а; меню и hover-состояния в харнесс не входят.
5. **контурный owner (90)** — `contour_snapshot`, undo/redo после удаления, `contour_completed`/`contours_changed`; выносится последним.

Если кластерный PR требует изменить существующий characterization-тест, это сигнал о смене поведения: изменение обсуждается в PR отдельно, а не маскируется правкой ожиданий.

## Что осталось за границей

- Doppler и M-mode: публичные сигналы записываются, но сценарии калибровки/колонки не добавлены — их уже покрывают `test_viewer_doppler_*`, `test_mmode_*`; харнесс расширяется перед соответствующим PR.
- Label picker: контекстные меню, hover и drag не входят; проверяется только видимость и отсутствие ложных сигналов.
- Контекстное меню viewer'а строится внутри обработчика события (`QMenu`), поэтому его пункты не снимаются харнессом.
- Гарды (`guard_snapshot`) и lifecycle 50/500 циклов остаются в прежних тестах; QH-0 их не дублирует.

## Прогон и гейты

Локально: offscreen Qt со стабами (`tools/qtstub`), `PYTHONPATH=src`.

- новые characterization-тесты — зелёные на текущем коде;
- существующие viewer-тесты не изменялись;
- class-size: `ViewerWidget` 426 методов, `viewer_widget.py` 8 854 строки, ratchet не вырос;
- function-length: без роста;
- test-signal: 0 тестов без проверяющего сигнала;
- private-access: 0 обращений к приватным именам в viewer-тестах (харнесс использует только `contract`);
- broad-excepts 280 (37 silent), doc-links, untranslated 0, ui-colors 188 — без изменений.

Ограничение: прогон локальный, без нативного GUI и без реальных DICOM-исследований; вывод о поведении ограничен offscreen Qt и синтетическими кадрами.
