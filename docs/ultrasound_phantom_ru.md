# ML.2: синтетический УЗ-фантом и локальный корпус

Реализация [#690](https://github.com/areatu/SonoForge/issues/690), продолжение
[анатомического атласа ML.1](cardiac_atlas_ru.md). Это офлайн-инструмент, не новая
клиническая модель и не изменение рабочего измерительного интерфейса.

## Что моделируется

- Геометрия связанного атласа, общие узлы МК/ТК/МЖП, фазы желудочкового цикла
  `φ∈[0,1)`, ED=0, ES≈0.38. Желудочки сокращаются, предсердия расширяются;
  в диастолу есть быстрое опорожнение (E), диастаз и меньшая поздняя компонента (A).
- Подъём клапанной плоскости к верхушке — приближение MAPSE/TAPSE; шарнирные
  створки МК/ТК открываются в диастолу, аортальные — в систолу.
- `A4C`, `RV_A4C`, `A2C`, `A3C`, `PLAX`, `PSAX`, `SUBCOSTAL` и OOD `UNKNOWN`.
  RV-focused seed шире и развёрнут; parasternal/subcostal имеют собственную позу.
- Сектор с вершиной у датчика, ограниченными углом и глубиной. Зеркальная
  составляющая стенки пропорциональна `|cos(α)|^γ`, где α — угол луча к нормали.
  При скользящем падении стенка акустически ослабевает, но её GT **не исчезает**.
- Экспоненциальное затухание, линейная/нелинейная TGC, радиальная тень ребра,
  ближнепольные реверберации, log-компрессия. PSF вычисляется в полярной сетке:
  аксиальная ширина постоянна, поперечная растёт с радиусом луча.
- Две гауссовы компоненты дают мультипликативный спекл Рэлея. Их материальное поле
  медленно обновляется по AR(1) и переносится приближённым обратным полем движения
  ткани. Это не независимый случайный шум на каждом кадре.

Численные параметры анатомии — **не нормативы**. Базовые формы и акустика
рандомизируются по seed; физические параметры фиксированы внутри клипа, чтобы не
создавать искусственное мерцание. Пользовательский `PhantomConfig.coefficients`
позволяет явно задавать моды атласа в допустимых пределах. По умолчанию
коэффициенты выбираются в пределах ±2 стандартных отклонений; топологический
контроль ML.1 остаётся включённым.

## Ограничения честности

Это **проекционный 2D-фантом с феноменологической акустикой**, не 3D-анатомия,
не волновой решатель и не клинически валидированный Sim-to-Real генератор.
`SUBCOSTAL` использует развёрнутый четырёхкамерный seed с печёночным near-field
слоем; он не выдаётся за отдельную обученную подрёберную анатомию. A3C/PLAX
наследуют упрощения соответствующих seed ML.1. `UNKNOWN` — контролируемые
суррогаты укорочения верхушки, косой деформации или сильного перекрытия ребром,
а не реальное пересечение 3D-модели плоскостью.

Перенос спекла — гладкая интерполяция смещений узлов, **не точный optical-flow GT**
и не моделирование кровотока/Допплера. Патологические варианты ограничены модами
ML.1; постинфарктные локальные дефекты и полный спектр патологии не заявляются.
Согласование гистограмм/Фурье-статистик по клиническим кадрам (опциональная часть
issue) пока не реализовано: генератор вообще не принимает пациентские изображения.
Клинические Dice/IoU/FAC, качество переноса на реальный сканер и калибровка OOD
этими unit-тестами не подтверждаются.

## Запуск

Из checkout с установленными NumPy/SciPy/pydicom и самим пакетом:

```bash
uv run python scripts/generate_synthetic_echo_corpus.py \
  --output .cache/phantom/demo --seed 42 --subjects 1

uv run python scripts/validate_view_recognition_corpus.py \
  .cache/phantom/demo/manifest.json --check-dicom
```

По умолчанию — все семь целевых видов и один UNKNOWN на субъект, 224×224,
50 FPS, 50 кадров на цикл, один цикл. Для короткой технической проверки:

```bash
uv run python scripts/generate_synthetic_echo_corpus.py \
  --output .cache/phantom/small --seed 42 --subjects 1 \
  --views A4C A2C RV_A4C UNKNOWN --size 64 --frames-per-cycle 12
```

Для использования локального статистического атласа ML.1 добавьте
`--atlas /local/models/atlas_a4c.json` (можно повторить для разных проекций).
Размер каждого JSON ограничен 8 MiB; повторные модели одного вида отвергаются.
Для SUBCOSTAL/UNKNOWN используется A4C-модель; отсутствующие модели заменяются
аналитическими seed. Чистый API также принимает `generate_cine(config, atlas_model=model)`.
Числовые модели, фактически использованные при генерации, копируются в `atlases/`;
их SHA-256, provenance и выбранные коэффициенты записываются в `generation.json`.
Это не копия исходной клинической разметки и не внешние нейросетевые веса.

Параметры: `--fps` 30..60, `--cycles` 1..3, `--frames-per-cycle` 12..120,
`--size` 48..512. Частота сердца выводится из FPS и длины цикла; крайние сочетания
допускаются для технических стресс-тестов и не объявляются физиологически обычными.
Для обычной частоты около 60–100 уд/мин выбирайте соответствующую длину цикла.
Внутренний размер cine ограничен 40 млн пикселей (маски требуют дополнительной
памяти). Рендеринг CPU/offline, без требования real-time; большие корпуса лучше
строить ограниченными партиями с разными seed.

`--unknown-kind off_axis|foreshortened|rib_occluded|cycle` управляет UNKNOWN;
по умолчанию `cycle` чередует три варианта между субъектами. При одном субъекте
получается только off-axis, для покрытия всех трёх используйте ≥3 субъектов
либо отдельные запуски с явно заданным вариантом.

Каталог **должен быть новым**, вне репозитория или Git-ignored (например `.cache/`).
Существующие каталоги и `.git` не перезаписываются. Запись идёт в staging-каталог;
итог публикуется переименованием после успешной генерации. Корпус не коммитится.
Выходные DICOM-пути абсолютные: при переносе корпуса manifest/gold надо согласованно
обновить. Отсутствие внешних датасетов не означает отсутствие доменного сдвига.

## Формат корпуса и загрузчики

```text
manifest.json        ViewRecognitionManifest v2, class_names = TTE_STANDARD_VIEWS
generation.json     параметры воспроизводимости, split, ED/ES-индексы
clips/*.dcm          uint8 MONOCHROME2 multiframe, явная маркировка SYNTHETIC
truth/*.npz          вся покадровая геометрия, маски, фазы и створки
atlases/*.json       использованные числовые модели ML.1
gold/{lv,la,rv,ra}_*.json
```

В NPZ нет pickle/object arrays. Ключи: `phases`, `sector_mask`, `contour_LV`,
`mask_LV`, `landmark_MV_septal`, `valve_MV` и аналогичные для доступных структур.
Контуры `T×N×2`, маски `T×H×W`, ориентиры `T×2`, створки `T×2×2×2`.
Координаты — `(x,y)` исходного DICOM-кадра; spacing — `(row_mm,column_mm)`.
Один affine на весь клип: нет скрытого покадрового масштабирования.

Gold содержит ED/ES и фактическую `cycle_fraction` кадра. При длине цикла,
не кратной 50, ES — ближайший отсчёт к 0.38, **без подмены фазы и временного шага**.
ED/ES обозначают фазу **желудочкового цикла**, а не собственную ED/ES предсердия;
это явно указано в `phase_reference`. Открытые дуги камер не содержат повторной
базальной точки; `PSAX` помечен как замкнутый контур. При акустическом dropout
геометрия и маски сохраняются. UNKNOWN остаётся в manifest для OOD, не входит
в gold стандартной сегментации; полная его геометрия доступна в NPZ.

Существующие потребители:
- `validate_view_recognition_corpus.py --check-dicom` проверяет manifest/источники;
- `load_la_gold` → `extract_la_samples` → `LaGoldDataset` читает A4C/A2C;
- `load_lv_samples(..., gold_dir=.../gold)` → `LVGoldDataset` читает LV;
- RV/RA-файлы проходят общий `gold_store.load_gold`. Отдельного `RVGoldDataset`
  в репозитории пока нет; его обучение/инференс — ML.3 (#691). Нельзя считать
  этот экспорт уже реализованным RV-тренером.

Все проекции одного синтетического субъекта имеют одинаковый study UID и split:
индексы `...8` — val, `...9` — test, остальные train. При <9 субъектах val может
отсутствовать. Это разбиение по субъектам, не случайный split кадров.
Segmentation-скрипты имеют собственный study-group split и не обязаны читать поле
`split` из gold; для строгого benchmark следует согласовать их входные списки
с `generation.json`. Синтетическая test-выборка **не заменяет клиническую**.
UNKNOWN не является дополнительным обучаемым индексом softmax: он служит OOD-аудиту.

## Воспроизводимость и тесты

Одинаковые seed, параметры, версия генератора и окружение дают одинаковые пиксели,
геометрию и синтетические DICOM UID. Глобальный NumPy RNG не используется.
DICOM не содержит текущих дат, случайных UID или данных реального пациента.
Битовая идентичность между различными NumPy/SciPy/BLAS не обещается.

`test_ultrasound_phantom.py` проверяет сектор, противофазность площадей,
общие интерфейсы, движение колец/створок, угловой отклик, TGC/тень, глубинную PSF,
Рэлеевскую статистику и перенос текстуры. `test_synthetic_echo_corpus.py` проверяет
реальный экспорт/декодирование DICOM, существующий валидатор, LA/LV-загрузчики,
RV/RA gold, соответствие GT и защиту выходного каталога. Оба модуля включены
в guarded pure-core lane; Qt и torch для них не нужны.
