**1. Как сейчас измеряется EDV / PSV при auto-trace в вашем проекте**

Логика находится в `doppler_overlay.py` → метод `apply_auto_trace`:

```python
psv_idx = min(range(len(ys)), key=ys.__getitem__)  # минимальный y = максимальная скорость
psv_x, psv_y = envelope[psv_idx]
edv_x, edv_y = envelope[-1]                         # последняя точка огибающей
```

**Итог:**
- **PSV** — одна точка: **глобальный максимум** скорости по всей извлечённой огибающей (внутри указанного пользователем цикла).
- **EDV** — **просто последняя точка** огибающей (конец правой границы цикла).
  Никакого поиска локального минимума в диастоле, никакого усреднения нескольких минимальных значений, никакого «конца диастолы» по физиологическим правилам.

Огибающая сама получается column-wise max-velocity (порог + медиана + Savitzky-Golay) в `doppler_envelope.extract_doppler_envelope`. После этого PSV/EDV берутся очень примитивно.

**2. Как делают коммерческие аппараты и offline-системы**

| Система / практика | PSV | EDV | Комментарий |
|--------------------|-----|-----|-------------|
| **Philips, GE, Siemens (live + offline)** | Максимум огибающей внутри выбранного цикла (или усреднение 2–3 циклов) | Значение огибающей **в конце диастолы** — обычно в точке, ближайшей к следующему систолическому подъёму / R-пику ECG, либо локальный минимум в последней трети цикла | Почти всегда есть ECG-синхронизация или автоматический beat-detection |
| **Классический «manual caliper»** | Пользователь кликает пик | Пользователь кликает конец диастолы (перед следующим подъёмом) | «Золотой стандарт» |
| **Auto-trace + multi-beat** (большинство современных) | Среднее или максимальное PSV по 3–5 циклам | Среднее EDV по тем же циклам | Снижает вариабельность |
| **Научные / robust algorithms** | Peak of max-envelope | Локальный минимум в диастолическом окне (часто 70–100 % цикла) + иногда небольшое усреднение 3–5 соседних точек | Защита от шума на самом конце |

Ключевые отличия от вашего кода:
- EDV **никогда** не берут просто как `envelope[-1]`, если только пользователь сам не поставил правую границу точно в конец диастолы.
- В коммерческих системах почти всегда есть либо ECG, либо автоматическое определение границ цикла по форме волны (подъём → пик → спад → плато).
- Часто есть опция «average of N beats».

**3. Сравнение и рекомендации по изменению**

**Сейчас у вас:**
- PSV — корректно (глобальный max).
- EDV — слишком примитивно и зависит только от того, куда пользователь поставил правую полосу. Если полоса стоит чуть раньше/позже — EDV сильно прыгает.

**Предлагаемые изменения (минимальные, в духе «простота + хорошая ручная коррекция»):**

1. **Улучшить детекцию EDV на одном цикле** (высокий приоритет):
   ```text
   - Найти глобальный PSV (как сейчас).
   - В последних 40 % сегмента после PSV найти локальный минимум скорости.
   - Проверка надёжности (по решению): если найденный минимум отличается от
     последней точки цикла менее чем на 5 % падения от PSV до конца — использовать
     последнюю точку огибающей.
   - Фолбэк: если сегмент после PSV короче 3 отсчётов — использовать последнюю точку.
   - Без сглаживания (по решению): EDV = скорость в точке минимума; маркер ставится
     в эту точку (значение измерения читается из позиции маркера).
   ```

2. **Оставить возможность ручной коррекции** (уже есть) — пользователь всегда может подвинуть caliper EDV.

3. **Позже (не в этом спринте)**:
   - Авто-определение границ цикла по форме волны (без ECG).
   - Режим «average of 2–3 cycles».

**Конкретная логика (решения зафиксированы):**

Огибающая хранится в plot-координатах `(x_px, y_px)`, где скорость растёт вверх:
**PSV = минимальный y**, **EDV (минимум скорости) = максимальный y** в поисковом окне.
Значение для измерения читается обратно из позиции маркера (`_vessel_edv_px` →
`get_vessel_values()`), поэтому функция возвращает **индексы точек** PSV/EDV,
а не скорости, и маркер EDV ставится в найденную точку минимума.

```python
def derive_psv_edv_indices(envelope: tuple[tuple[float, float], ...]) -> tuple[int, int]:
    """Индексы точек PSV и EDV огибающей (y_px: скорость растёт вверх)."""
    ys = np.asarray([p[1] for p in envelope])
    if len(ys) < 5:
        return int(np.argmin(ys)), len(ys) - 1

    psv_idx = int(np.argmin(ys))              # максимум скорости
    diastolic = ys[psv_idx:]
    if len(diastolic) < 3:
        return psv_idx, len(ys) - 1

    search_start = int(len(diastolic) * 0.6)  # последние 40 % после PSV
    local_idx = int(np.argmax(diastolic[search_start:])) + search_start
    edv_idx = psv_idx + local_idx

    # Проверка надёжности: если найденный минимум почти равен последней точке
    # (менее 5 % падения от PSV до конца цикла) — берём последнюю точку.
    psv_y = float(ys[psv_idx])
    last_y = float(ys[-1])
    edv_y = float(ys[edv_idx])
    fall_px = last_y - psv_y  # падение скорости (в px) от PSV до конца цикла
    if fall_px > 0 and (edv_y - last_y) < 0.05 * fall_px:
        edv_idx = len(ys) - 1

    return psv_idx, edv_idx
```

Реализация в `apply_auto_trace` (doppler_overlay.py): получить индексы через
`derive_psv_edv_indices`, затем `_vessel_psv_px = envelope[psv_idx]`,
`_vessel_edv_px = envelope[edv_idx]`, значения `psv/edv` в см/с — из этих точек.
Совместимость с текущими тестами: тест с 4 точками огибающей уходит в фолбэк
`len(ys) < 5` и возвращает прежние PSV/EDV.
