# WP4.2 — Рост и вес исследования

**Дата:** 2026-10-03
**Статус:** реализация начата совместно с WP4.1 по запросу пользователя; экспериментальный opt-in, не окончательная платформенная приёмка.

Связанные документы: [WP4.1](2026-10-03-wp4-1-measurement-persistence-spec-ru.md), [общий план](2026-10-01-persistence-packaging-security-plan.md).

## Контракт

- Рост (`height_cm`) и вес (`weight_kg`) относятся к **проверенному Study Instance UID**, а не пользователю, клипу или папке. Для не-DICOM действует локальная identity WP4.1.
- Значения записываются в тот же атомарный снимок, что и измерения. Отдельных несогласованных записей QSettings для пациентов нет. Экспорт/импорт собственного JSON включает рост/вес.
- Единицы хранения: сантиметры и килограммы; дробные значения не округляются для диска. На чтении/записи запрещены bool вместо чисел, NaN, Infinity, отрицательные значения и ноль. Допустимые инженерные пределы: `0 < height_cm <= 300`, `0 < weight_kg <= 700`. Это защита ввода, не клинические референсы.
- `None` означает отсутствие значения, не нулевой рост/вес. У каждого поля есть происхождение: `unset`, `dicom`, `manual`, `cleared`.
- DICOM автозаполняет только `unset` и только валидными данными. Рост и вес читаются независимо: отсутствие веса не мешает заполнить рост. Первый валидный DICOM-ввод исследования сохраняется; другой клип не перезаписывает его молча.
- Ручное применение формы роста/веса фиксирует предоставленную пару как `manual`/`cleared`. Ручной ввод и явное очищение имеют приоритет над последующими DICOM-клипами, повторным скачиванием и повторным открытием.
- Действие **«Взять рост/вес из DICOM…»** с подтверждением снимает ручные переопределения, снова читает текущий источник, оставляет отсутствующие значения пустыми и пересчитывает BSA/индексированные показатели.
- Сброс измерений/калибровки **сохраняет** рост/вес и их происхождение. Удаление полной сохранённой записи удаляет и их. После удаления открытая RAM-сессия не должна автоматически воссоздать файл.
- Отчёт не подставляет DICOM-значение вместо поля с `cleared`. BSA и индексированные показатели вычисляются заново из текущей пары; готовые BSA/индексы не сериализуются как источник истины.
- ФИО, Patient ID, пол, дата рождения, реквизиты учреждения, свободный текст отчёта и дата исследования в этот store не добавляются.

## Режимы и срок хранения

В текущем экспериментальном этапе WP4.1–4.2 включаются одной настройкой (требует перезапуска); по умолчанию выключены в Full и Presenter. Это сознательное ограничение rollout до полной проверки WP4.1, а не окончательное решение о production-default.

При включении: `<paths.data_dir()>/measurements`, в Presenter — только portable root, без host fallback. До явного удаления, без LRU/7-дневной очистки; лимиты и ошибки те же, что у WP4.1. Рост/вес и связанный UID — медицинские данные. Нет шифрования приложения и secure erase; защита профиля/тома и сроки хранения — ответственность оператора.

## Критерии приёмки

1. Ручные рост/вес переживают restart и повторное открытие; DICOM другого клипа не заменяет их.
2. Одно исследование не получает значения другого, включая одинаковый Series UID и смешанную локальную папку.
3. Рост без веса и вес без роста поддержаны; BSA не вычисляется по неполной паре.
4. Явно очищенное поле не возвращается из DICOM при переключении клипа или построении отчёта.
5. «Взять из DICOM» возвращает источники `dicom`/`unset`, не изменяет исходный файл.
6. Reset измерений сохраняет демографию; delete-record/delete-all удаляет её с диска; off/Presenter read-only не пишет в чужой профиль.
7. JSON round-trip сохраняет точность, null и provenance; повреждённые/невалидные значения отвергаются до изменения live state.
8. Импорт заменяет измерения и демографию одним снимком после подтверждения, а не частично.
