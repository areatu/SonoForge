**Текущее поведение (код):**

4. Кнопка « + » удаляется. Её функция остаётся за счёт открытия нового исследования внутри открытого (уже работает, см. `_acquire_tab_for_load`).

### Ф3. Панель инструментов: плавное раскрытие, плавные секции Inputs, начальное состояние

**Текущее поведение (код):**
- `tool_panel.py`, `sync_width()` (~стр. 367): ширина вкладки «Расчёты» анимируется `QVariantAnimation` 180 мс, на каждом кадре вызывается `setFixedWidth`. Каждый кадр перекладывает всё содержимое вкладки (~350 виджетов) → рывки.
- `calculators_panel.py`, `_on_section_toggled()` (~стр. 449): секция сворачивается через `setVisible(False)` — мгновенно, без анимации. Высота содержимого прыгает.
- Все секции Inputs открыты по умолчанию (`heading.setChecked(True)`).

**Цель:**
1. Раскрытие панели на вкладке «Расчёты» плавное, без рывков.
2. Секции Inputs открываются и закрываются анимацией высоты (≈180 мс, `OutCubic`), как аккордеон в `measures_menu.py` (`MeasuresAccordionSection`).
3. Начальное состояние по Q4: при старте приложения все секции Inputs свёрнуты. Секции, которые пользователь открыл в сессии, остаются открытыми до перезапуска.

**Изменения:**

*Ширина панели.* Перекладку содержимого убрать из цикла анимации. Варианты (выбор при реализации, по замеру):
- **Клип-контейнер:** внутренний виджет вкладки «Расчёты» получает фиксированную ширину = целевая, а внешний контейнер анимирует только собственную ширину с обрезкой (`clip`). Содержимое не перекладывается, меняется только геометрия контейнера.
- Альтернатива: на время анимации `setUpdatesEnabled(False)` на содержимом вкладки и показ финального размера в конце.

*Секции Inputs.* В `_on_section_toggled` вместо `setVisible` — `QPropertyAnimation` по `maximumHeight` тела секции, целевая высота = `sizeHint().height()`. Стрелка меняется в начале анимации. При `reduce_motion` — мгновенно.

*Начальное состояние.* В `_build()` все секции создаются свёрнутыми (`setChecked(False)`, тело `setVisible(False)`). Заголовок показывает счётчик заполненных полей `(filled/total)` — он уже есть в `_update_section_headings`, сворачивание не мешает видеть состояние.

**Тесты:**
- `test_calculators_panel.py`: после создания панели все секции свёрнуты; переключение секции ставит анимацию (проверка `QPropertyAnimation` по `maximumHeight`), а в конце значение совпадает с целевым.
- `test_tool_panel_calculators.py`: ширина после перехода на вкладку «Расчёты» равна `_CALC_WIDTH_FACTOR * base`; после анимации вызов `setFixedWidth` происходит один раз в конце (или на внешнем контейнере).

**Приёмка:** раскрытие панели без подёргиваний на машине пользователя; секции Inputs открываются и закрываются плавно; при первом входе на вкладку все секции свёрнуты.

### Ф4. Переключение вкладок: не перерисовывать всё окно

**Текущее поведение (код) — гипотезы, не подтверждены:**
- `_switch_to_tab` → `_tab_flush_or_block` → `_park_active_tab` → `_load_tab_content`.
- `_load_tab_content` вызывает `_leave_special_layouts()`, `_refresh_tab_strip()` (два раза за переключение), `_update_main_stack()`.
- `_refresh_tab_strip()` → `TabStrip.set_tabs()` удаляет и заново добавляет все вкладки в `QTabBar` (с заблокированными сигналами). Из-за этого полоса перестраивается, а её высота и геометрия могут меняться.
- `_update_main_stack()` на время загрузки переключает `_main_stack` на заглушку «Загрузка…» (`tabs.loading`). Область просмотра на короткое время исчезает.
- Возможная причина мигания всего окна: перестройка полосы и смена страницы стека вызывают relayout и перерисовку верхней части окна, системной панели и панели инструментов.

**Цель:** при переключении перерисовываются только панель миниатюр и окно просмотра. Системная панель, полоса вкладок, панель инструментов и строка статуса не перерисовываются.

**Шаг 4a. Замер (обязательно первым):**
- Записать видео переключения на 3 вкладках с PACS и с локальными папками.
- Проверить гипотезы: (а) меняется ли высота `TabStrip` при `set_tabs`; (б) вызывается ли `_update_main_stack` с заглушкой; (в) сколько раз за переключение вызывается `repaint`/`update` верхнего уровня (через `QWidget.update` hook или `QT_LOGGING_RULES` при отладке).
- Результат — короткая таблица в `docs/` с цифрами, до правок.

**Шаг 4b. Правки (по итогам замера):**
- `TabStrip`: обновлять вкладки на месте. Если набор `tab_id` не изменился — только `setCurrentIndex` при заблокированных сигналах. Полная перестройка — только при добавлении или удалении вкладки. Высота полосы фиксирована (см. Ф1).
- Во время загрузки вкладки не менять страницу `_main_stack` на заглушку, если в вкладке уже есть предыдущее исследование. Вместо этого поверх области просмотра показывается лёгкий индикатор (`QLabel` с полупрозрачным фоном), который скрывается по приходу студий.
- Переключение обернуть в `setUpdatesEnabled(False)` на контейнере области просмотра и миниатюр, а не на всём окне, и снимать его после установки состояния.
- Не вызывать `_leave_special_layouts()`, если multiview и M-mode уже выключены (проверка условием).

**Тесты:**
- Тест «полоса не пересоздаётся при переключении»: идентичность объектов `QTabBar` и количество `addTab` вызовов не меняется.
- Тест «заглушка не показывается при переключении между вкладками с исследованиями».
- Ручной: видео переключения до и после (см. §5).

**Приёмка:** при переключении системная панель, полоса вкладок, панель инструментов и статус-бар не мигают; миниатюры и просмотр обновляются.

### Ф5. Ручной контур (Trace freehand): без помощников и улучшений

**Текущее поведение (код):**
- `viewer_widget.py`, `_finish_active_freehand_contour` (~стр. 4860–4905) строит открытую дугу из трассы и вызывает `_auto_snap_new_contour` (~стр. 8606). Этот метод применяет магнитную привязку, если `_magnetic_snap_enabled` (глобальная настройка из Controls).
- Оптический поток (`_apply_optical_flow_refinement`, ~стр. 4664) вызывается из пути автосегментации LA (~стр. 4650–4660). Нужно проверить, попадает ли в него трасса; это делается при реализации.
- Магнитная привязка также применяется в пути дуги по точкам (`len(_active_arc_points) >= 5`, ~стр. 4472). Нужно проверить, относится ли он к трассе.

**Цель:** если контур строится в режиме freehand (трасса ЛЖ, трасса ЛП/ПП, свободная площадь), помощники и улучшения **не применяются**: магнит, оптическая коррекция, auto-snap. Точки контура — ровно те, что нарисовал пользователь (с прореживанием как сейчас).

**Изменения:**
- Ввести явный признак «трасса»: `self._freehand_recording and (self._freehand_open_arc or self._area_tool_mode == "freehand")` на момент завершения. В `_auto_snap_new_contour` и во всех путях оптического потока для такого контура — ранний выход.
- Глобальная настройка магнита (Controls) не меняется и продолжает действовать для landmark-режима и кликового контура.
- Проверить и при необходимости закрыть путь 4472 для трассы.

**Тесты:**
- Новый `tests/unit/test_freehand_trace_no_assist.py`: при завершении трассы моки `_apply_magnetic_snap_to_contour`, `_apply_optical_flow_refinement` и `_auto_snap_new_contour` не вызываются; точки контура совпадают с прореженной трассой.
- Регрессия: клик-контур и landmark-контур по-прежнему вызывают магнит при включённой настройке.

**Приёмка:** трасса ЛЖ и трасса ЛП на реальном клипе — контур повторяет движение мыши без «притягивания» к краям.

### Ф6. Настройки Tools: добавление секций и их перестановка

**Текущее поведение (код):**
- `tool_panel_settings.py`: секции — `QGroupBox` в двух колонках по балансу строк. Перетаскивать можно только инструменты, между секциями. Перестановка самих секций не предусмотрена.
- `measures_menu.py`: `apply_tool_layout()` сохраняет порядок секций из каталога (`_MENU`), игнорируя порядок в JSON. Секции идентифицируются ключом i18n (`menu.aorta` и т. п.).
- `tool_panel_layout_json` — список `{key, items:[{id, enabled}]}`.
- `MeasuresAccordionSection` принимает только `title_key` и вызывает `tr()`, поэтому произвольное название секции не поддерживается.

**Цель:**
1. В Настройки → Tools кнопка **«Добавить»** создаёт новую пустую секцию (название задаёт пользователь) и затем её можно заполнять инструментами из других секций.
2. Секции можно перемещать и менять местами. Порядок сохраняется и применяется в панели инструментов.
3. Встроенные секции (Общие, Аорта, ЛЖ и др.) сохраняют своё содержимое по умолчанию.

**Изменения:**

*Схема.* Новая версия `tool_panel_layout_json`:
```json
{"version": 2, "sections": [
  {"key": "menu.general", "title": null, "items": [{"id": "...", "enabled": true}]},
  {"key": "custom:3f2a", "title": "Мои", "items": []}
]}
```
Порядок в массиве `sections` — порядок показа. Чтение v1 (голый список) остаётся: порядок = порядок каталога, `title` = null.

*Декодирование.* `decode_tool_layout` понимает обе версии; неизвестные `key` без `custom:` отбрасываются; `custom:` требует непустой `title` (иначе секция пропускается).

*`apply_tool_layout`.* Порядок секций берётся из layout, а не из каталога. Новые встроенные секции, появившиеся в каталоге после сохранения, добавляются в конец по умолчанию. Инструменты, не назначенные ни в одну секцию, попадают в дефолтную секцию, как сейчас.

*`MeasuresAccordionSection`.* Принимает либо `title_key` (встроенная), либо `title` (пользовательская). `reload_text` обновляет только встроенные.

*Редактор.* В `ToolPanelSettingsWidget`:
- кнопка «Добавить секцию» (`tools.add_section`) → `QInputDialog` с названием (лимит 40 символов) → новая секция в конце;
- у каждой секции кнопки «↑» и «↓» в заголовке группы (надёжнее перетаскивания; перетаскивание секций — возможное улучшение, не в этом шаге);
- у пользовательских секций кнопка «Переименовать» и «Удалить» (удаление возвращает инструменты в дефолтную секцию, Q5);
- лимит 12 секций (кнопка «Добавить» отключается с подсказкой).

*Пересборка колонок.* После перестановки колонки пересчитываются тем же алгоритмом баланса по строкам.

*Миграция.* При первом сохранении из старого формата записывается версия 2. Пустой layout = дефолт.

**Тесты:**
- `test_tool_panel_layout.py` / `test_measures_menu.py`: декодирование v1 и v2; порядок секций из layout; пользовательская секция с заголовком; отбрасывание секции без `title`; перенос инструмента в пользовательскую секцию и обратно; лимит 12.
- `test_measures_menu_vessel.py`, `test_measures_menu_highlight.py`: регрессия — подсветка и сосудистый блок работают при переставленных секциях.
- `test_presentation_user_preferences_dialog.py`: кнопка «Добавить» создаёт секцию, значение уходит в `tool_panel_layout_json`.

**Приёмка:** в Tools можно добавить секцию «Мои», перенести туда измерения из MV/AV Doppler и TV/PV Doppler, переставить секции. В панели инструментов порядок и содержимое совпадают с настройками после перезапуска.

### Ф7. Допплер: подсказка о ручной калибровке

**Текущее поведение (код):**
- `DopplerWidget` (`doppler_widget.py`) — график спектрального допплера.
- Состояние калибровки во `viewer_widget.py`: `_doppler_axis_calibrated`, `is_doppler_axis_calibrated()`; полная калибровка — `DopplerCalibrationState.is_complete()` (есть и скорость, и время).
- Есть баннер `CALIBRATION_PROMPT_OVERLAY_KEY` в строке кадра, но не в центре ROI.

**Цель:** на полосе спектрального допплера, где вертикальная калибровка не задана (нет тегов и автокалибровка не сработала), в центре ROI показывается оверлей **«Проведите ручную калибровку допплера»** (ключ `viewer.doppler_manual_calibration_hint`).

**Q3 (решено):** секции Inputs сворачиваются по умолчанию; карточки калькуляторов не сворачиваются и не меняются.

**Условие показа (уточнено):** показывать, когда допплер-клип открыт и `not has_velocity_scale()`. Если задана только скорость, но не время — оверлей не показывается (время вне scope). Q8: во время активного режима калибровки оверлей скрывается.

**Изменения:**
- В `DopplerWidget` — `QLabel`-оверлей (стиль как у `results overlay`, полупрозрачный фон) как дочерний виджет viewport `_plot`. Позиционируется по центру ROI в `resizeEvent` и при `set_axis_mapping`.
- Оверлей `WA_TransparentForMouseEvents`, чтобы не перехватывать клики калибровки.
- Метод `set_manual_calibration_hint_visible(bool)`; вызывается из `viewer_widget` при смене состояния калибровки.
- Локали: `viewer.doppler_manual_calibration_hint` (ru: «Проведите ручную калибровку допплера», en: «Draw the manual Doppler calibration»).

**Тесты:**
- `test_doppler_widget.py`: оверлей виден при отсутствии вертикальной шкалы; скрыт при полной калибровке; скрыт при `set_calibration_active(True)`; клик проходит сквозь него.
- `test_presentation_doppler_overlay.py`: ничего не меняется в результатах.

**Приёмка:** открыть файл без тегов с неудачной автокалибровкой — оверлей в центре ROI; после ручной калибровки — пропадает.

### Ф8. Лупа: активация по Z и постоянный режим для линейных измерений

**Текущее поведение (код):**
- `viewer_widget.py`, `keyPressEvent` (~стр. 8117): нажатие Z ставит `_magnifier_held = True` и больше ничего не делает.
- Лупа показывается только в `_update_magnifier_loupe`, а он вызывается из `_on_scene_mouse_moved` (~стр. 1089). Без движения мыши лупа не появляется. Именно это описывает пользователь.
- `_hide_magnifier_on_point` (~стр. 1245) вызывается при каждой постановке точки (калипер ~7248, контур ~6772): гасит лупу и сбрасывает удержание Z.
- Лупы в M-режиме нет: `mmode_widget.py` не использует `MagnifierLens`. Линейные калиперы M-режима работают через `viewer_widget` — подтвердить при реализации.
- Фокус: клавиши Z принимаются только если фокус у `ViewerWidget`. Если фокус на миниатюрах или панели, Z не срабатывает. Нужно проверить.

**Цель:**
1. **Z (удержание):** при нажатии Z с курсором над окном просмотра лупа появляется сразу, без движения мыши, и следует за курсором.
2. **Постоянный режим (новая настройка):** в Настройки → Интерфейс → Отображение (рядом с блоком лупы) — чекбокс «Лупа при линейных измерениях». Когда включён, при активации линейного измерения в B-режиме или M-режиме (LA-AP, AV, любой линейный калипер) лупа активна с курсором над окном просмотра до завершения всех точек. Для допплера и сосудов — не применяется.

**Изменения:**
- `user_preferences.py`: `magnifier_linear_persistent: bool = False` (Q7), чтение и запись в QSettings.
- `viewer_widget.py`:
  - в `keyPressEvent` при Z: если курсор внутри области просмотра (`_last_view_cursor_xy` или `QCursor.pos()` в геометрии), вызвать `_update_magnifier_loupe` для текущей позиции сразу;
  - в `_handle_linear_caliper_mouse_press` и аналогичных путях не вызывать `_hide_magnifier_on_point`, если активен постоянный режим;
  - при активации линейного калипера в B/M-режиме (`activate_generic_dist_caliper`, `toggle_linear_caliper`, пути LA-AP / AV) в постоянном режиме — `_magnifier_persistent_active = True`, лупа показывается при наведении;
  - при завершении последовательности (`linear_caliper_sequence_completed`), отмене (Esc) или смене инструмента — `_magnifier_persistent_active = False` и скрытие.
- Удержание Z и постоянный режим не конфликтуют: Z при постоянном режиме лупу не прячет.
- Фокус: по результатам проверки при реализации либо вешаем Z на окно (`QShortcut`/eventFilter на `MainWindow`), либо явно передаём фокус `ViewerWidget` при активации калипера.
- `preferences_dialog`: чекбокс `_magnifier_linear_persistent` в блоке лупы (`display_form`), подсказка `preferences.magnifier_linear_persistent_hint`.
- Локали: ru/en ключи.

**Тесты:**
- Новый `tests/unit/test_magnifier_trigger.py`: при Z и курсоре в области просмотра `lens.isVisible()` сразу True без `mouseMove`; без курсора — False.
- Постоянный режим: активация линейного калипера в B-режиме → лупа активна; клик, первая точка → лупа остаётся; вторая точка → скрыта; Doppler/vessel — не активируется.
- Проверка, что с выключенным чекбоксом поведение точно как до изменений (клик гасит лупу).

**Приёмка:** Z над просмотром сразу показывает лупу. При включённом «Лупа при линейных измерениях» — LA-AP или AV активирует лупу до последней точки; на допплере лупы нет.

## 6. Риски

- **Ф1 + #127:** код вкладок ещё не в основной ветке. Любые правки до merge создают конфликты.
- **Ф4:** без замера причина может оказаться не в полосе вкладок, а, например, в перерисовке при смене студии. Поэтому замер обязателен.
- **Ф6:** смена схемы `tool_panel_layout_json`. Нужна миграция и тест на старые сохранённые данные; ошибка здесь сбрасывает у пользователя всю раскладку.
- **Ф8:** фокус клавиатуры. Если Z не доходит до окна просмотра, Ф8 не работает независимо от логики лупы.
- **Ф5:** возможная связь трассы с путём оптического потока через автосегментацию. Нужен отдельный прогон на реальном клипе.
- **Ф2/Ф7:** визуальные решения (толщина выделения, положение оверлея) проверяются только глазами; тесты их не ловят.
