# Спека: реализация плана аудита 2026-10-22 (3 спринта)

- Дата: 2026-10-23
- Источник: `docs/reviews/2026-10-22-comprehensive-audit-ru.md`, §12–13
- Статус: proposed
- Область: исправление дефектов и техдолга из аудита, без новых продуктовых фич
- Формат работы: один issue = один проверяемый шаг; один PR = один issue (допускается
  объединение только для S1-02 и S3-03, если изменения чисто документационные)

---

## 1. Цель

Закрыть 14 шагов плана аудита за три спринта так, чтобы:

1. Клинические числа не зависели от непринятых AI-контуров.
2. Обещания README/HELP совпадали с кодом.
3. Дистрибутив был воспроизводимым и проверял целостность моделей.
4. Кодовая база перестала расти в ширину: мёртвый код, дубли, гигантские функции и
   широкие `except` не маскируют реальные дефекты.
5. CI ловил регрессии на Windows/macOS, Python 3.12/3.13 и новых зависимостях.

## 2. Вне области

В эту спеку не входят продуктовые фичи, которые аудит перечисляет как пробелы:

- автоматическая классификация проекций;
- автоматический допплер (E/e′, AS-градация) как «из коробки»;
- DICOM SR и отправка отчёта в PACS;
- worklist/MWL, мультипользовательность, 3D/4D, стресс-эхо.

Это отдельные продуктовые инициативы. Их техническая реализуемость и стоимость описаны
в ответе к аудиту; они не должны блокировать закрытие P1-дефектов и техдолга.

## 3. Общие правила приёмки

Для каждого issue:

- [ ] Все пункты issue закрыты, поведение покрыто тестом (юнит или интеграционным).
- [ ] `uv run ruff check <изменённые файлы>` — без новых ошибок.
- [ ] `uv run pytest <целевые тесты> -q --maxfail=1` — зелёный.
- [ ] Если менялся набор тестов — `uv run python .github/scripts/update_pytest_baseline.py --fix`.
- [ ] Если менялось поведение/документация — обновлены README/HELP/CHANGELOG в том же PR.
- [ ] Нет новых зависимостей и изменений `pyproject.toml`, кроме S3-02.
- [ ] Нет новых импортов `presentation → infrastructure`; для S2-03 — только уменьшение

- [ ] PR содержит ссылку на issue и краткий отчёт о проверке.

**Изменения.**

3. Исправить удалённые алиасы (`np.float_`, `np.product`, `np.trapz`, `np.in1d` и т.п.)

   тесты под новое поведение без объяснения.

### S3-04 — PDF export worker, лимит пикселей, accessibility

**Проблема.** Три независимых риска:

1. PDF экспортируется синхронно на UI-потоке (`report_dialog._export_pdf`,

3. Нет `setAccessibleName` для ключевых кнопок/полей, tab-order и проверки screen

**Изменения.**

  прогресс/ошибку через сигналы.

- Добавить `setAccessibleName` ключевым controls, проверить tab-order, прогнать
  базовый сценарий с screen reader.
- Не менять внешний вид отчёта без необходимости.

**Приёмка.**

- [ ] PDF-экспорт не блокирует UI; отмена и ошибка обрабатываются.
- [ ] Огромное исследование отклоняется до выделения памяти.
- [ ] Ключевые controls имеют accessible name; tab-order логичен.
- [ ] Есть тест/чек-лист accessibility.

**Размер:** M. **Зависимости:** S2-01 (worker-паттерн), S3-01.

## 7. Порядок и зависимости

```text
S1-01 ─┬─> S1-05
S1-04 ─┘

S1-04 ─> S2-01 ─┬─> S2-03
                ├─> S2-04
                └─> S2-05

S1-03 ─> S3-02
S1-04 ─> S3-01 ─> S3-02
S1-02 ─> S3-03
S2-01 ─> S3-04
```

Правила:

- S1-01 и S1-04 идут первыми: они фиксируют инварианты и не дают рефакторингу
  замаскировать дефект.
- S1-05 не начинать до S1-01: иначе можно удалить модуль, который участвует в
  инварианте.
- S3-02 не начинать до S1-03: иначе новая матрица Python сломает установщик.
- S3-04 не начинать до S2-01: worker-паттерн должен быть уже выделен.

## 8. Риски и меры

| Риск | Мера |
|---|---|
| Удаление «мёртвого» модуля, который планировали подключить | Решение фиксируется в issue; при сомнении — issue-заглушка вместо удаления |
| Рефакторинг меняет клинические числа | Характеризационные тесты до/после; запрет менять формулы в S2 |
| numpy 2 меняет численные результаты | Отдельный этап, документированный допуск, пере-базлайн только с объяснением |
| Перенос I/O ломает UI-сценарии | По 5–6 модулей за PR; smoke-тесты после каждого переноса |
| Windows/macOS runners нестабильны | Smoke-набор из 20 сценариев, без GPU/PACS; маркеры и таймауты |
| Coverage ratchet блокирует работу | Baseline фиксируется по факту, повышается только после роста покрытия |
