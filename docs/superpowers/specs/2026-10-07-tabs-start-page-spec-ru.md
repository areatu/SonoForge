## 2. Границы и принципы

1. **Новый код — новые модули (N-08).** `main_window.py` (≈3,7 тыс. строк) и `app_controller.py` (≈4,1 тыс.) не раздуваются: слой сессии вкладок живёт в `application/tab_session.py`, полоса вкладок — в `presentation/tab_bar.py`, приветственная страница — в `presentation/start_page.py`. `main_window` только соединяет их сигналами.
2. **Без QtWebEngine.** Пользователь спросил «html?» — ответ спеки: нет. Приветственная страница собирается из нативных виджетов: QtWebEngine добавил бы ~100 МБ к сборке, отдельную тест-матрицу в Э4 (`docs/superpowers/specs/2026-10-05…` §8) и отдельный путь для Presenter. Быстрые ссылки — это кнопки и списки, а не документ.
3. **PHI в заголовках — не здесь.** Пользователь не ответил на пункт «ФИО в заголовках», а единая политика PHI вынесена им в отдельную задачу (N-01). Поэтому заголовок вкладки по умолчанию: `дата · модальность · короткое описание серии` (+ номер вкладки); ФИО появляется только вместе с будущей настройкой отображения PHI и вместе с маской (пункт N-01). До её появления ФИО в заголовках нет.
4. **Измерения уже привязаны к UID.** Хранилище WP4.1 сопоставляет запись по Study/SOP UID, поэтому переключение вкладок не требует «переноса» измерений: каждая вкладка восстанавливает свою запись при загрузке своего исследования. Спецификация вкладок обязана лишь не ломать это: один `MeasurementPersistence` на приложение, смена активной записи при смене вкладки через существующий serial-воркер.
5. **Presenter.** Вкладки и приветствие существуют и в профиле Presenter, но недавние исследования и история загрузок там выключены по умолчанию (портативный носитель, D-21/rollout-заметки): страница показывает только «Открыть папку», «С сервера» и справку.
6. **Локализация и документы.** Каждый PR: строки `ru.json`/`en.json` (паритет `test_locale_key_parity`), `CHANGELOG.md`, `docs/HELP_RU.md`/`HELP_EN.md`, при изменении поведения данных — `SECURITY.md`/`docs/security/data-inventory.md`.

## 3. Модель вкладки (Э9, слой без UI)

`application/tab_session.py`:

```python
@dataclass
class TabSession:
    tab_id: str                 # uuid4 hex, стабилен между переключениями
    origin: str                 # "folder" | "server" | "empty"
    root: str                   # папка на диске или "" для кэш-сессии PACS
    cache_session_id: str       # сессия Z3 для серверной вкладки, "" для локальной
    studies: list[StudyMetadata]
    active_instance_uid: str
    frame_index: int
    viewer_state_json: str      # W/L, калибровки, оверлеи — то, что сегодня в StateManager
    created_at: float
```

Инварианты:

- одна вкладка = один набор `studies` (то, что сегодня возвращает сканер папки или диалог загрузки);
- галерея, транспорт и панель инструментов читают состояние активной вкладки; неактивные вкладки не владеют виджетами просмотра (см. §4);
- закрытие вкладки: измерения остаются в Z2-M (политика D-27), кэш Z3 её `cache_session_id` удаляется, если это не открытая сессия другой вкладки;
- «закрепление клипа» из прежнего плана Э9 отложено до PR-E: сначала сравнение между исследованиями, закрепление добавляет состояние, которого ещё нет в модели.

Тесты слоя: создание/переключение/закрытие без Qt-виджетов, восстановление `viewer_state_json`, защита от двух вкладок с одним `cache_session_id`, выгрузка по §5.

## 4. Полоса вкладок и жизненный цикл виджетов (Э9, UI)

- Полоса над системной панелью: вкладки + кнопка «+» (новая пустая вкладка = приветственная страница). Перетаскивание вкладок и контекстное меню («Закрыть», «Закрыть другие») — со второго шага, в первом только клики и `Ctrl+Tab`/`Ctrl+W`.
- **Предложение по лимиту:** 8 открытых вкладок; при превышении — вопрос закрыть старую неактивную (не молчаливый LRU: измерения не теряются, но пользователь должен видеть, что произошло). Число вынесено в константу до решения пользователя.
- Виджеты: у приложения один комплект виджетов просмотра/галереи/панелей (как сегодня). Переключение вкладки = снять состояние старой (§5) и применить состояние новой. Второй комплект GL-вьюпортов не создаётся: память и Presenter-зеркало этого не переживут.
- Multiview внутри вкладки остаётся как есть (два клипа одного исследования); межвкладочный multiview — §6.
- PACS: каждое отмеченное в диалоге исследование открывает свою вкладку (сегодня `load_pre_scanned_studies` складывает всё в один список — это поведение заменяется). Диалог загрузки остаётся модальным и вне вкладок.

## 5. «Кэш неактивной вкладки сохранять на диск» (D-29 + WP4.3)

Трактовка решения, зафиксированная спецификацией (пользователь писал «кэш», не разделяя его слои):

| Слой | Где живёт | Что делаем при деактивации вкладки |
|---|---|---|
| Измерения, калибровки, рост/вес | Z2-M (`measurements/`) | уже на диске; flush отложенных изменений перед переключением |
| Состояние просмотра (кадр, W/L, позиция оверлеев) | RAM | сериализуем в `viewer_state_json` вкладки |
| Декодированные кадры (`FrameCache`) | RAM | освобождаем целиком: локальные файлы уже на диске пользователя, а PACS-изображения — в Z3 на диске; повторная активация вкладки читает их заново |
| Изображения PACS | Z3 (`cache/orthanc`) | **не трогаем**: сессия нужна для возврата во вкладку; удаляется при закрытии вкладки и при выходе (D-27) |
| Миниатюры | RAM-кэш планировщика | освобождаем вместе с кадрами; повторный рендер миниатюр дешёв (середина петли уже кэшируется в Z3) |

То есть «на диск» уходит то, что пользователь теряет иначе (измерения и состояние), а тяжёлые пиксели не дублируются: они либо исходники пользователя, либо Z3. Это же закрывает WP4.3 в части «выгрузить неактивное» без нового формата кэша кадров. Ограничение фиксируем честно: первая секунда после возврата во вкладку тратится на повторное чтение кадров; метрика — время активации вкладки в `playback_diagnostics`.

## 6. Сравнение исследований в multiview (Э10)

Сегодня `MultiViewSession.clips_are_comparable()` требует один `study_uid`. По D-29 заменяется на сравнимость по геометрии съёмки:

1. **Условие сравнимости:** одинаковый размер кадра и одинаковая частота кадров (±5 %); совпадение `study_uid` больше не требуется. Несовпадение частот не запрещает загрузку, но выключает синхронное воспроизведение и показывает причину в полосе multiview.
2. **Подписи панелей обязательны:** у каждой панели — свой бейдж `вкладка N · дата исследования · модальность/вид` (без ФИО, §2.3), иначе «реальное сравнение» превращается в угадайку. Бейджи рисуются и в Presenter-зеркале.
3. **Синхронизация:** по времени от начала цикла (МК/фаза), если оба клипа имеют R-R или число кадров и частоту; иначе — по индексу кадра с явной пометкой «без синхронизации по фазе».
4. Измерения в панелях по-прежнему отложены (этап 4 прежнего плана multiview): сравнение смотрят глазами, а не калиперами двух панелей сразу.

Тесты: матрица пар (та же частота/разная; тот же размер/разный; один и тот же клип), подписи панелей в состоянии зеркала, запрет синхро-воспроизведения при несовместимой частоте.

## 7. Приветственная страница (Э5)

Занимает область просмотрщика, пока во вкладке нет загруженного исследования (D-30). Это не режим запуска и не отдельное окно: это содержимое пустой вкладки, поэтому `startup_mode="empty"` просто открывает одну пустую вкладку со страницей, а «Последнее»/«последняя папка» открывают вкладку сразу с содержимым.

Состав (сверху вниз):

1. **Главные действия:** `Открыть папку…`, `Загрузить с сервера…`, `Продолжить: <папка или сервер · дата · число клипов>` (последняя сессия, D-28: для сервера кнопка открывает диалог загрузки).
2. **Недавние места** — `RecentStore` (закреплённые сверху, отсутствующие серым), до 8 строк.
3. **Недавние исследования** — записи Z2-M (если хранилище включено) и истории загрузок Z3 текущего запуска: `дата · описание серии · число клипов`; клик по локальному открывает папку, по серверному — диалог загрузки с предвыбранным исследованием. В Presenter блок скрыт (§2.5).
4. **Ссылки-разделы:** справочник нормативов, пользовательские `.md/.pdf`, «Сообщить о проблеме…», `Настройки`, `Справка` (HELP).
5. Строка состояния страницы: версия, профиль, включено ли сохранение измерений — то, что сегодня приходится искать по настройкам.

Поведение: страницы не видно, когда во вкладке есть исследование; закрытие всех вкладок возвращает страницу; клавиши `Ctrl+O`/`Ctrl+P` работают и на странице; реестр горячих клавиш (N-05) page не регистрирует, но и не конфликтует с ним (все обработчики — на главном окне).

Вёрстка: `QStackedWidget` в области просмотрщика + список-делегат с миниатюрами-заглушками; никаких веб-движков (§2.2). Высоты строк — от метрик шрифта (Э4).

## 9. Приёмка пользователем (Windows)

1. Открыть папку A, затем папку B — две вкладки; измерения из A на месте после возврата.
2. Загрузить два исследования с сервера — две вкладки; выход очищает Z3, повторный вход с «Последнее» открывает диалог, измерения возвращаются после загрузки.
3. Переключение вкладок на медленной папке (сетевой диск): возврат не дольше ~2 с на исследование из 50 клипов (метрика в журнале).
4. Multiview: клип из вкладки 1 и клип из вкладки 2 рядом, бейджи различимы с рабочего расстояния; при разной частоте кадров синхро-воспроизведение выключено с пояснением.
5. Приветственная страница: свежие ссылки работают после перезапуска; отсутствующая папка серая; в Presenter блоков недавних исследований нет.
6. Масштаб 150 % (Э4): страница и полоса вкладок не обрезаются, подписи читаемы.

## 10. Открытые вопросы и решения

Ответы пользователя (сессия Arena, после PR-A):

1. **Лимит вкладок — 8, подтверждено.** Константа `MAX_OPEN_TABS = 8`; при превышении — вопрос пользователю, не LRU (PR-B).
2. **ФИО в заголовках — нет.** Заголовок вкладки: `дата · модальность · описание серии` + номер вкладки. ФИО появится только вместе с политикой PHI и маской (N-01).
3. **Закрепление и переименование вкладки — не нужны.** Вкладки не закрепляются и не переименовываются; закрепление клипа отложено до PR-E, если понадобится.
4. **Исследования без изображений на машине — не показывать** в блоке «Недавние исследования» страницы приветствия. Блок показывает только исследования, чьи изображения доступны (папка на диске или кэш Z3 текущего запуска). Предложение «с пометкой „нужна загрузка“» снято.

Пункт 4 меняет §7 (блок «Недавние исследования»): записи только из Z2-M без изображений в нём не выводятся.
