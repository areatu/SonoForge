## 0. Подготовка

### 0.1. Получить сборку с функцией

v0.3.1 из Releases не подходит. Варианты:

- **Вариант А (рекомендуемый):** попросить ассистента запустить workflow **«Build (test artifacts)»** на `main` (кнопка *Run workflow* / `gh workflow run build.yml --ref main`). В Actions появится артефакт **`sonoforge-windows`** — `SonoForge.exe` (standalone, полный профиль). Артефакт живёт **24 часа** — скачать и распаковать сразу.
- **Вариант Б:** запуск из исходников (`uv run python -m echo_personal_tool`).

Первый запуск неподписанного exe: SmartScreen → «Подробнее → Выполнить в любом случае».

### 0.2. Включить функцию

1. Меню → Настройки → вкладка **«Прочее»** → блок **«Сохранённые измерения»**.
2. Поставить галочку **«Сохранять измерения и рост/вес (экспериментально)»**.
3. ОК — настройка применяется **сразу, без перезапуска** (исправлено 2026-10-09; раньше требовался перезапуск). Если при включении открыто исследование с уже сохранённой записью, появится диалог «Загрузить сохранённые / Оставить текущие».
4. После включения в строке статуса: **«Измерения: готовы»**. (Галочка снята → «Измерения: только текущая сессия»; при выключении с несохранёнными изменениями приложение спросит, сохранять ли их.)

### 0.3. Знать, где лежат данные

```
%LOCALAPPDATA%\SonoForge\measurements\
  .writer.lock            — lock-файл на время работы процесса
  <64-символьный hex>.json — по одному файлу на исследование
  .pending-*.tmp           — временные файлы только во время записи
```

Путь показывается в шапке менеджера («Управление сохранёнными измерениями…»).

### 0.4. Материалы и инструменты

- Локальная папка DICOM-исследования с **несколькими клипами** (B-mode + допплер + M-mode, если есть).
- Доступ к вашему Orthanc (PACS) для блока B.
- Диспетчер задач (закладка «Подробности») — для принудительного завершения процесса.
- Проводник и Блокнот — для просмотра папки measurements и JSON.
- (Для D4) Командная строка с правами обычного пользователя — команды `icacls` приведены в тесте.
- (Блок P, опционально) USB-флешка и Presenter-сборка с `main` (workflow «Presenter (lite portable build)» без тега — только артефакты).

### 0.5. Что считать «требуемым ответом»

Точные строки статусов и диалогов, на которые ссылаться (русская локаль):

| Состояние | Строка в статус-баре |
|---|---|
| включено, изменений нет | «Измерения: готовы» |
| выключено | «Измерения: только текущая сессия» |
| есть несохранённые изменения | «Измерения: ещё не сохранены» |
| идёт запись | «Сохранение измерений…» |
| запись подтверждена | «Измерения сохранены» |
| восстановление при открытии | «Измерения и рост/вес восстановлены» |
| восстановлены не все клипы | «Частичное восстановление: доступны не все исходные клипы» |
| проверка при открытии | «Проверка сохранённых измерений…» |
| ошибка | «Измерения не сохранены/не восстановлены ({код}). Изменения остаются в памяти. Настройки → Сохранённые измерения: повторить или экспортировать.» |

Коды ошибок в скобках: `занято` (второй экземпляр), `ввод-вывод` (диск), `загрузка не удалась` (битый JSON), `источник не совпадает`, `неизвестное исследование`, `конфликт версий`, `нет места`, `заблокировано`.

Блокировка навигации: «Часть измерений не сохранена. Открытие другого исследования или закрытие отменено. Повторите сохранение или экспортируйте через Настройки → Сохранённые измерения.»

### 0.6. Известные ограничения среза — НЕ дефекты (§16 WP4.1)

При нахождении нижеперечисленного **не фиксировать как ошибку** (известные ограничения текущего среза):

1. Менеджер показывает только ключ записи и размер — без времени сохранения и числа измерений.
2. Импорт без предпросмотра категорий: сразу подтверждение «Заменить ВСЕ…», замена целиком.
3. Битая/несовместимая запись **остаётся на диске и блокирует перезапись** до явного удаления через менеджер — автомиграции/автоудаления нет.
4. Закрытие при неуспешном flush отменяется (диалога «ждать дальше» нет); Retry/Экспорт — в менеджере.
5. AI-черновики контуров не сохраняются — только принятые измерения (статус «Принятые измерения сохранены; AI-черновики остаются только в сессии»).
6. Strain сохраняется консервативно (summary по набору источников), история tracking не восстанавливается.
7. Ручные значения калькуляторов (вкладка «Расчёты») между сеансами не сохраняются — вне scope WP4.1–4.2.

## A. Базовый цикл: включить → измерить → перезапустить → восстановить

### A1 [ОБЯЗ] Включение и статус
**Действия:** выполнить §0.2, открыть локальную папку DICOM без измерений.
**Требуемый ответ:** статус «Измерения: готовы»; в `%LOCALAPPDATA%\SonoForge\measurements` файлов записей **нет** (пустое исследование не создаёт файл).

### A2 [ОБЯЗ] Сохранение измерений разных типов
**Действия:** в открытом исследовании сделать на **разных клипах**: линейный калипер, контур ЛЖ (Simpson manual), допплер (пик + VTI-трейс), M-mode калипер, ручную калибровку B-mode (ввод см). После каждого — пауза 2–3 с, следить за статусом.
**Требуемый ответ:** после завершения каждого объекта статус: «Измерения: ещё не сохранены» → «Сохранение измерений…» → **«Измерения сохранены»** (не позже ~6 с от правки; статус меняется только после подтверждённой записи). Прокрутка/воспроизведение не подвисают во время записи. В папке measurements появился один `<hex>.json` (плюс `.writer.lock`), `.pending-*.tmp` после записи не остаются.

### A3 [ОБЯЗ] Перезапуск и восстановление
**Действия:** закрыть приложение обычным способом. Запустить снова, открыть ту же папку.
**Требуемый ответ:** статус **«Измерения и рост/вес восстановлены»**; все объекты на своих клипах и кадрах; значения калибровок **на каждом клипе свои** (не перемешаны); допплер-маркеры/трейсы на месте; панель результатов и оверлей совпадают с тем, что было до перезапуска.

### A4 [ЖЕЛ] Неполный набор клипов
**Действия:** закрыть приложение; из папки исследования временно убрать (переместить) один DICOM-файл. Открыть папку заново.
**Требуемый ответ:** статус «Частичное восстановление: доступны не все исходные клипы»; измерения доступного клипа восстановлены; недостающий клип без оверлеев и без чужих данных. Вернуть файл, открыть снова → полное восстановление, включая вернувшийся клип.

### A5 [ЖЕЛ] Защита от подмены источника
**Действия:** закрыть приложение; заменить один DICOM-файл в папке файлом **другого** исследования (то же имя).
**Требуемый ответ:** при открытии записи заменённого источника **не** восстанавливаются (ошибка «источник не совпадает» или пропуск без чужих оверлеев); оригинальная запись на диске не испорчена. (Файл вернуть обратно.)

### A6 [ЖЕЛ] Запись не мешает работе
**Действия:** во время воспроизведения cine непрерывно править узлы контура 15–20 с.
**Требуемый ответ:** воспроизведение не замирает на секунды при каждой записи (I/O в фоне); статусы сменяются корректно, в конце — «Измерения сохранены».

## B. PACS (Orthanc)

### B1 [ОБЯЗ] Скачивание → сохранение → повторное скачивание
**Действия:** открыть диалог «Загрузить с сервера…», скачать исследование. Сделать несколько измерений, дождаться «Измерения сохранены». Закрыть приложение (кэш DICOM при выходе очищается — по умолчанию). Запустить снова, скачать **то же** исследование с сервера.
**Требуемый ответ:** «Измерения и рост/вес восстановлены»; измерения на своих клипах. Кэш очищался, но запись измерений пережила это (она хранится отдельно от кэша).

### B2 [ОБЯЗ] Без повторного скачивания восстановления нет
**Действия:** после B1 закрыть приложение, запустить, открыть только локальную папку (не скачивая с PACS).
**Требуемый ответ:** записи измерений PACS-исследования никуда не подгружаются и не показываются — это ожидаемо (D-27: восстановление только при повторной загрузке тех же источников). Ошибок/подвисаний нет.

### B3 [ЖЕЛ] Очистка кэша не трогает измерения
**Действия:** Настройки → Прочее → блок «Кэш загруженных DICOM-исследований» → «Очистить кэш…». Затем открыть «Управление сохранёнными измерениями…».
**Требуемый ответ:** список записей и их размеры не изменились (кэш Z3 и измерения Z2-M — разные хранилища).

## C. Удаление и сброс

### C1 [ОБЯЗ] Удалённое не воскрешает
**Действия:** удалить последний калипер (или допплер-маркер) → дождаться «Измерения сохранены». Перезапустить, открыть папку.
**Требуемый ответ:** удалённое измерение **отсутствует** после перезапуска. (Допускается «пустая» запись-файл, если это было последнее измерение — это различие «удалил» vs «никогда не сохранял», не дефект.)

### C2 [ОБЯЗ] «Сбросить измерения и калибровку»
**Действия:** внести ручной рост/вес (блок F). Затем SystemBar → «Сбросить измерения и калибровку» → подтвердить. Перезапустить, открыть папку.
**Требуемый ответ:** после сброса — чистое исследование; после перезапуска измерения не вернулись; **рост/вес сохранились** (сброс измерений демографию не трогает — контракт WP4.2). До следующего реального изменения файл записи не появляется.

### C3 [ОБЯЗ] Удаление открытой записи из менеджера
**Действия:** с открытым исследованием и парой измерений: Настройки → Прочее → «Управление сохранёнными измерениями…» → выделить запись → «Удалить выбранную запись…».
**Требуемый ответ:** диалог подтверждения: «Удалить выбранную запись, включая рост/вес? Если она открыта, измерения останутся в памяти, но не будут сохраняться до повторного открытия исследования.» После подтверждения: измерения **видны в окне** (RAM), но автосохранение для этого исследования приостановлено (новые правки не пишутся на диск); перезапуск → чисто.

### C4 [ЖЕЛ] «Удалить все сохранённые данные…»
**Действия:** в менеджере нажать «Удалить все сохранённые данные…».
**Требуемый ответ:** подтверждение с PHI-предупреждением («…Это не гарантированное стирание с носителя»); после — папка records пуста (остаётся `.writer.lock`), автосохранение выключено (статус «только текущая сессия»), открытые измерения остаются в памяти. Повторное включение — через настройки + перезапуск.

## D. Аварии и конкуренция (native Windows)

### D1 [ОБЯЗ] Force-kill после подтверждённого сохранения
**Действия:** сделать измерения, дождаться **«Измерения сохранены»**. Не закрывая приложение, снять процесс: Диспетчер задач → найти `SonoForge.exe` → «Снять задачу» (или `taskkill /F /IM SonoForge.exe`). Запустить заново, открыть папку.
**Требуемый ответ:** восстановлена **последняя подтверждённая** ревизия. Новый процесс получил lock без ошибки «занято» (OS-lock освободился с процессом).

### D2 [ОБЯЗ] Kill во время записи
**Действия:** непрерывно править контур/добавлять калиперы и **во время этого** (статус «Сохранение измерений…») снять процесс. Запустить заново, открыть папку.
**Требуемый ответ:** приложение открывается без ошибок схемы; на диске **целый** JSON — старая или новая полная версия, никогда не «обрезанный» файл; восстановилось одно из двух состояний. Потеря последних несохранённых правок допускается (не обещается «ни одного потерянного действия»).

### D3 [ОБЯЗ] Два экземпляра одновременно
**Действия:** запустить **второй** экземпляр того же exe (двойной запуск). Во втором открыть ту же/другую папку и сделать измерение.
**Требуемый ответ:** во втором экземпляре статус-ошибка **«…(занято)»** — «Хранилище занято другим экземпляром; изменения не сохраняются» (по смыслу; точный текст — код `занято` в строке ошибки). Измерения во втором экземпляре работают в памяти, экспорт доступен. Первый экземпляр продолжает сохранять без ошибок. Закрыть первый → во втором: «Управление…» → «Повторить сохранение» → lock захвачен, сохранение прошло успешно, статус «Измерения сохранены».

### D4 [ОБЯЗ] Ошибка диска (каталог только для чтения)
**Действия (командная строка, обычные права):**
```
icacls "%LOCALAPPDATA%\SonoForge\measurements" /deny "%USERNAME%:(WD,AD)"
```
Запустить приложение (или продолжить в открытом), открыть папку, сделать измерение.
**Требуемый ответ:** статус-ошибка «…(ввод-вывод)…», изменения живут в памяти, **ложного «Сохранено» нет**; попытка открыть другое исследование или закрыть приложение → предупреждение «Часть измерений не сохранена. Открытие другого исследования или закрытие отменено…»; в менеджере доступны «Повторить сохранение», «Экспорт текущего исследования…», «Продолжить без сохранения…» (с подтверждением «Выключить автосохранение этой сессии и отменить ожидающие запросы записи?…»).
**Откат прав:** `icacls "%LOCALAPPDATA%\SonoForge\measurements" /remove:d "%USERNAME%"` → «Повторить сохранение» → «Измерения сохранены». Прежние записи не пострадали.

### D5 [ЖЕЛ] Закрытие сразу после правки (flush при выходе)
**Действия:** сделать измерение и **сразу** Alt+F4 (раньше, чем истёк debounce ~1 с).
**Требуемый ответ:** приложение закрывается не мгновенно — до ~5 с ждёт завершения записи; после повторного запуска правка на месте. Если запись не удалась — закрытие отменяется с предупреждением (см. D4), а не тихая потеря.

### D6 [ЖЕЛ] Битый JSON не перезаписывается молча
**Действия:** закрыть приложение. Через менеджер предварительно убедиться, что запись одна. В `%LOCALAPPDATA%\SonoForge\measurements` открыть `<hex>.json` в Блокноте, удалить несколько символов в середине (сломать JSON), сохранить. Запустить приложение, открыть исследование, сделать измерение.
**Требуемый ответ:** ошибка загрузки (код `загрузка не удалась`) или блокировка записи (`заблокировано`); испорченный файл **остался на месте** (не удалён, не перезаписан пустым); перезапись этого исследования заблокирована до явного действия. Менеджер → «Удалить выбранную запись…» → файл удаляется; после этого новое измерение сохраняется нормально.

## E. Экспорт / импорт

### E1 [ОБЯЗ] Экспорт
**Действия:** менеджер → «Экспорт текущего исследования…» → сохранить `study.sonoforge-measurements.json` в выбранную папку. Открыть файл Блокнотом.
**Требуемый ответ:** файл создан; предупреждение о PHI/отсутствии шифрования показано (текст privacy в менеджере); в файле **нет** ФИО пациента, PatientID, путей к файлам; есть измерения, UID исследования и рост/вес (UID в файле — по дизайну, не течь).

### E2 [ОБЯЗ] Импорт (замена целиком)
**Действия:** сначала изменить/удалить пару измерений в открытом исследовании (чтобы было чем заменить). Затем менеджер → «Импорт в текущее исследование…» → выбрать файл из E1 → подтвердить («Заменить ВСЕ измерения и рост/вес текущего исследования?…»).
**Требуемый ответ:** после подтверждения состояние = состоянию из файла (включая удалённые в файле объекты); «Отмена» на подтверждении ничего не меняет. **Предпросмотра категорий нет — известное ограничение, не дефект.**

### E3 [ЖЕЛ] Импорт чужого файла
**Действия:** попробовать импортировать файл **другого** исследования в текущее.
**Требуемый ответ:** импорт не выполняется (источники не совпали / неизвестное исследование), текущие измерения не изменились.

## F. Рост/вес (контракт WP4.2)

Поля ввода: панель инструментов (Controls) — «Рост» / «Вес». Действие «Взять рост/вес из DICOM…» — в менеджере.

### F1 [ОБЯЗ] Ручные значения переживают перезапуск и не перекрываются DICOM
**Действия:** открыть исследование, ввести рост и вес вручную → статус «Измерения сохранены». Переключиться на другой клип (в т.ч. клип с другими значениями в DICOM, если есть). Перезапустить, открыть папку.
**Требуемый ответ:** ручные значения на месте; DICOM другого клипа их **не** перезаписал; BSA/индексы в оверлее/отчёте посчитаны из этой пары.

### F2 [ОБЯЗ] Неполная пара
**Действия:** ввести только рост, вес оставить пустым.
**Требуемый ответ:** BSA и индексированные показатели **не** вычисляются (нет нулей/мусора); после перезапуска рост на месте, вес пуст.

### F3 [ОБЯЗ] «Взять рост/вес из DICOM…»
**Действия:** при ручных значениях нажать в менеджере «Взять рост/вес из DICOM…».
**Требуемый ответ:** подтверждение «Удалить ручные рост/вес и использовать значения текущего DICOM? Отсутствующие в DICOM значения останутся пустыми.» После — значения из DICOM (или пустые, если в DICOM нет); ручные переопределения сняты; исходный DICOM-файл не изменён; при переключении клипов первый валидный DICOM-ввод не перезаписывается следующим молча.

### F4 [ОБЯЗ] Очищенное поле не возвращается
**Действия:** значение роста взять из DICOM, затем поле **очистить** вручную (не путать с пустым «unset»). Переключать клипы, построить отчёт.
**Требуемый ответ:** поле остаётся пустым — DICOM не подставляет значение обратно ни в UI, ни в отчёт; BSA не считается.

### F5 [ЖЕЛ] Точность и происхождение в JSON
**Действия:** экспортировать запись (E1), открыть JSON в Блокноте.
**Требуемый ответ:** значения роста/веса записаны без экранного округления (те, что введены/прочитаны из DICOM; если поле UI допускает только целые — отметить это наблюдением, это ограничение поля ввода, не хранилища); рядом с полями есть признак происхождения (dicom/manual/…); `null` там, где значения нет.

### F6 [ЖЕЛ] Изоляция исследований
**Действия:** открыть второе исследование (другой Study UID / другая папка), посмотреть рост/вес.
**Требуемый ответ:** значения первого исследования **не** подставились во второе (пусто или свои значения).

## G. Менеджер, настройки, локализация

### G1 [ОБЯЗ] Список записей и плюрализация
**Действия:** при 1, затем 2, затем 3–5 сохранённых исследованиях открыть менеджер.
**Требуемый ответ:** список — строки «<ключ>… — N,N КиБ»; строка статистики склоняется корректно: «**1 запись** · …», «**2 записи** · …», «**5 записей** · …» (исправлено 2026-10-08; до этого было «1 записей»). Отсутствие времени сохранения и числа измерений в списке — известное ограничение.

### G2 [ОБЯЗ] Выключение/включение
**Действия:** снять галочку «Сохранять измерения и рост/вес» → перезапуск → поработать с измерениями → проверить папку measurements → вернуть галочку → перезапуск → открыть папку.
**Требуемый ответ:** в выключенном режиме статус «Измерения: только текущая сессия», новых файлов не появляется, **старые записи не удаляются**; после включения — восстановление работает как до выключения.

### G3 [ОБЯЗ] Локализация RU/EN
**Действия:** переключить язык интерфейса на английский, открыть блок настроек и менеджер, затем вернуть русский.
**Требуемый ответ:** все строки блока «Сохранённые измерения», менеджера, подтверждений и статусов — на выбранном языке; стандартные кнопки диалогов тоже локализованы (не «OK/Cancel» в русском интерфейсе).

### G4 [ЖЕЛ] Подсказка статуса
**Действия:** навести курсор на статус измерений в строке состояния.
**Требуемый ответ:** tooltip с privacy-текстом («Медицинские данные остаются на этом устройстве до явного удаления…»).

## H. Установщик (только на релизной сборке — можно отложить до v0.3.2) [ОПЦ]

### H1 Обычное удаление сохраняет данные
**Действия:** установить setup-сборку, включить сохранение, создать запись. Удалить приложение через «Установка и удаление программ» **без** галочки «удалить данные». Переустановить, включить, открыть исследование.
**Требуемый ответ:** `%LOCALAPPDATA%\SonoForge\measurements` пережил удаление; записи восстановились.

### H2 Удаление с данными
**Действия:** удалить с отмеченной опцией удаления пользовательских данных.
**Требуемый ответ:** каталог measurements удалён вместе с остальными данными профиля.

## P. Presenter (портативная сборка с main, флешка) [ОПЦ]

### P1 По умолчанию — никакой записи на хосте
**Действия:** записать Presenter-сборку на флешку (workflow «Presenter (lite portable build)» без тега → артефакт Windows). Запустить с флешки **не включая** сохранение, поработать с измерениями. Проверить размер/содержимое `%LOCALAPPDATA%\SonoForge` на машине до и после.
**Требуемый ответ:** на хост-профиле ничего не появилось/не изменилось; на флешке файлов записей нет.

### P2 Opt-in пишет только на флешку
**Действия:** в Presenter включить сохранение, перезапустить с флешки, сделать измерения.
**Требуемый ответ:** запись появилась **только** в portable root на флешке (`<флешка>/…/measurements`), не в `%LOCALAPPDATA%`; после перезапуска с флешки — восстановление.

### P3 Read-only носитель
**Действия:** перевести флешку в read-only (переключатель на корпусе или атрибут «Только чтение») при включённом сохранении, сделать измерение.
**Требуемый ответ:** нет падения; статус-ошибка; измерения работают в памяти; **никакой скрытой записи на хост**.

## Форма отчёта

По каждому пункту верните: **ID → PASS / FAIL / N/A** + одна строка наблюдений (что видели фактически, точный текст статуса/диалога при FAIL).

При любом FAIL:
1. Не исправляйте состояние сами — сначала соберите диагностический архив: Настройки → **«Сообщить о проблеме…»** (нижний ряд) → галочка «Создать диагностический архив» → приложить полученный ZIP (логи без PHI).
2. По возможности — скриншот строки статуса и/или диалога.
3. Для D-блока — записать, что именно делали (kill из диспетчера/команда, момент относительно статуса).

| F | F1–F6 | | | |

## Критерии закрытия приёмки

- Обязательные пункты (A1–A3, B1–B2, C1–C3, D1–D4, E1–E2, F1–F4, G1–G3) — **все PASS**.
- Известные ограничения §0.6 не блокируют; новые находки — отдельным списком в отчёт.
- После закрытия: решение **W41-01** (хранение до явного удаления — подтвердить) и **W41-02** (default-on автосохранения в Full + первое уведомление) → перевод функции из experimental в production.
- H1–H2 допускается закрыть на релизной сборке v0.3.2; P1–P3 — при наличии флешки, не блокирует Full-приёмку.
