# Redesign Справочника (Reference) — Design Spec

**Date:** 2026-08-16
**Status:** Draft
**Scope:** UI таблиц, данные YAML, конструктор справочника

---

## 1. Problem Statement

Справочник нормативов в SonoForge имеет четыре ключевые проблемы:

1. **Таблица скроллится** — QTableWidget не растягивается на всю высоту панели, пользователь прокручивает чтобы увидеть все параметры
2. **Нет градаций** для большинства параметров (масса ЛЖ, КДО, ФВ, TAPSE и т.д.) — только 7 патологий (клапаны) имеют градации
3. **Ширина колонок неоптимальна** — первая колонка часто широковата, 2-3 не влезают; нет ручной настройки
4. **Конструктор** не позволяет вставлять/удалять строки/столбцы, объединять ячейки

---

## 2. Goals

| # | Goal | Success Metric |
|---|------|---------------|
| G1 | Таблица параметров без вертикального скролла | Все строки видны без прокрутки, таблица растянута на всю высоту панели |
| G2 | Градации для каждого параметра | Все параметры (LVM, LVMI, RWT, LVEDD, LVEF, TAPSE и т.д.) имеют градации: Норма / Лёгкое / Умеренное / Тяжёлое |
| G3 | Оптимальная ширина колонок | Пользователь может перетаскивать границы заголовков для настройки ширины |
| G4 | Excel-подобный конструктор | Вставка/удаление строк/столбцов, merge/split ячеек через контекстное меню и toolbar |
| G5 | Цветовая кодировка градаций | Зелёный (норма), жёлтый (лёгкое), оранжевум (умеренное), красный (тяжёлое) — фон ячеек |

---

## 3. Non-Goals

- Изменение общей layout-структуры (левая панель топиков + правая панель с патологиями/таблицей/изображением)
- Изменение поиска (текущий поиск по названиям параметров достаточен)
- Добавление калькулятора норм (ввод значения → определение градации)
- Изменение PDF/Markdown viewers

## 4. Design Decisions

### 4.1 Убираем радиокнопки М/Ж

**Решение:** Обе колонки (Норм М / Норм Ж) всегда видны в таблице. Радиокнопки убираем из лейвой панели.

**Причина:** Радиокнопки дублируют информацию (в таблице flat всегда показаны обе колонки) и занимают место в левой панели. Врач всегда знает пол пациента и видит обе нормы рядом — это удобнее для сравнения.

**Затронутые файлы:**
- `structured_reference_widget.py` — удалить radio buttons, `_on_sex_changed()`, `self._sex_male`
- `_format_norm()` — упростить, всегда показывать обе нормы

### 4.2 Растягивание таблицы на всю высоту

**Решение:** QTableWidget растягивается через layout на всю доступную высоту панели. Минимальная высота строки — 24px. Если параметров >15 — строки ужимаются автоматически.

**Реализация:**
- Убрать QScrollArea из `_cards_layout` — таблица вставляется напрямую в layout
- `table.verticalHeader().setDefaultSectionSize(max(24, available_height / len(params)))`
- `table.setVerticalScrollBarPolicy(Qt.ScrollBarPolicy.ScrollBarAlwaysOff)`

### 4.3 Цветовая кодировка градаций

**Решение:** Фон ячейки — полупрозрачный цвет severity. Текст — насыщенный.

| Градация | Фон (rgba) | Текст | CSS class |
|---|---|---|---|
| Норма | `rgba(34, 197, 94, 0.12)` | `#22c55e` | `grad_normal` |
| Лёгкое | `rgba(234, 179, 8, 0.12)` | `#eab308` | `grad_mild` |
| Умеренное | `rgba(249, 115, 22, 0.12)` | `#f97316` | `grad_moderate` |
| Тяжёлое | `rgba(239, 68, 68, 0.12)` | `#ef4444` | `grad_severe` |

Полупрозрачность фона обеспечивает читаемость на тёмной теме. Текст — насыщенный для WCAG AA контраста.

### 4.4 Моноширинные цифры

**Решение:** Все числовые значения (нормы, диапазоны градаций) используют моноширинный вариант шрифта (`font-variant-numeric: tabular-nums` в Qt через `QFont.setStyleHint(QFont.StyleHint.Monospace)` или CSS).

**Причина:** Колонки с числами должны быть выровнены для сканирования глазом.

### 4.5 Чередующийся фон строк

**Решение:** Чётные строки — `bg_panel`, нечётные — `bg_panel_alt` (чуть светлее/темнее). Разница — ~5% яркости.

### 4.6 Ширина колонок — ручная настройка

**Решение:** `QHeaderView.setSectionResizeMode(QHeaderView.ResizeMode.Interactive)` для всех колонок кроме первой. Первая колонка — `Stretch` (занимает остаток). Пользователь перетаскивает границы заголовков.

### 4.7 Новая структура YAML — градации на уровне параметра

**Решение:** Каждый параметр может иметь собственные градации (помимо norm_male/norm_female).

```yaml
- id: lvm
  name: Масса миокарда ЛЖ (LVM)
  unit: г
  norm_male: {low: 88, high: 224}
  norm_female: {low: 66, high: 150}
  gradations:
  - name: Норма
    range_male: {low: 88, high: 224}
    range_female: {low: 66, high: 150}
  - name: Лёгкое увеличение
    range_male: {low: 225, high: 258}
    range_female: {low: 151, high: 171}
  - name: Умеренное увеличение
    range_male: {low: 259, high: 292}
    range_female: {low: 172, high: 193}
  - name: Тяжёлое увеличение
    range_male: {low: 293}
    range_female: {low: 194}
  source: 2015, ASE
```

**Обратная совместимость:** Старый формат (pathology-level gradations для клапанов — MR, AR, TR, PR) остаётся поддерживаемым. Парсер `_parse_parameters()` расширяется для обработки вложенных `gradations`.

### 4.8 Отображение таблицы с градациями

**Решение:** Единый режим отображения — матрица. Все патологии используют одну и ту же таблицу:

```
+--[Показатель]--+--[Норм М]--+--[Норм Ж]--+--[Лёгкое]--+--[Умеренное]--+--[Тяжёлое]--+
|  LVM (г)       | 88–224     | 66–150     | 225–258 /  | 259–292 /     | ≥293 /       |
|                |            |            | 151–171    | 172–193       | ≥194         |
|  LVEF (%)      | 52–72      | 52–72      | 41–51      | 30–40         | <30          |
```

- **Если у параметра есть градации** — колонки градаций показывают диапазоны `range_male / range_female` (через " / "). Если диапазон только для одного пола — показывается только он
- **Если у параметра нет градаций** — колонки градаций показывают "—" (em dash)
- **Цвет фона ячейки** определяется градацией (зелёный/жёлтый/оранжевый/красный, см. 4.3)
- **Колонки градаций скрываются** если НИ ОДИН параметр в текущей патологии не имеет градаций — тогда таблица показывает только 3 колонки (Показатель / Норм М / Норм Ж)
- **Тип градаций** (увеличение/снижение/нарушение) определяется автоматически по названию градации в YAML и влияет на цвет: "Норма" = зелёный, "Лёгкое/снижение/нарушение" = жёлтый, и т.д.

**Маппинг названия градации → цвет:**
- Содержит "Норма" → зелёный
- Содержит "Лёгк" → жёлтый
- Содержит "Умерен" → оранжевый
- Содержит "Тяжёл" → красный
- Не匹配 → серый (без цвета)

### 4.9 Конструктор — Excel-подобный редактор

**Контекстное меню** (правый клик на ячейку или заголовок столбца/строки):
- Вставить строку выше
- Вставить строку ниже
- Вставить столбец слева
- Вставить столбец справа
- Удалить строку
- Удалить столбец
- Объединить выделенные ячейки (merge)
- Разделить ячейку (split)

**Toolbar** (добавить к существующему):
- `+ строка` / `- строка`
- `+ столбец` / `- столбец`
- `merge` / `split`

**Drag & drop** — перемещение строк и столбцов (уже частично реализовано в `parameter_table_editor.py`).

## 6. Risks

| Risk | Mitigation |
|---|---|
| Нет данных градаций для большинства параметров | Phase 1 — наполнить YAML. Источники: ASE 2015, ESC/EACTS 2021, Lang et al. |
| Обратная совместимость YAML | Старый формат (pathology-level gradations) остаётся поддерживаемым |
| Merge/split в QTableWidget нет из коробки | Реализовать через `setSpan()` / `clearSpans()` + кастомная логика |
| Производительность при большом числе параметров | Lazy loading, virtual table если >50 параметров |
