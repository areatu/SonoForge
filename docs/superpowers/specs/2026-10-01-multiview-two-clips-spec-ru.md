# Multiview: просмотр и синхронизированное воспроизведение двух клипов

**Дата:** 2026-10-01
**Статус:** План / Draft для согласования
**Тип:** UX + архитектура
**Область:** два разных эхокардиографических клипа в одном исследовании
**Связанные документы:** `2026-06-30-customize-layout-spec.md`, `docs/HELP_RU.md` (Simpson, LV Auto)

---

## 1. Краткое описание и решения

Multiview — это **два разных клипа рядом**, например A4C + A2C, A4C + A3C, A4C + PLAX или клипы разных проекций для стресс-эхо. Это не просмотрщик ED/ES одного клипа и не сравнение предыдущих исследований.

Режим должен иметь три состояния воспроизведения:

1. **Независимо:** каждый клип листается и воспроизводится отдельно.
2. **Общий фрагмент:** пользователь задаёт стартовый кадр в каждом клипе; оба запускаются вместе, общая длительность фрагмента равна оставшейся длительности более короткого клипа, после чего оба автоматически возвращаются к старту и повторяют фрагмент. Это быстрый, приблизительный вариант без требования найти фазовую метку.
3. **По маркерам (синхронизация по циклу):** пользователь отмечает одинаковое видимое событие на каждом клипе. Можно задать один интервал `МК₁→МК₂` или два соседних интервала `МК₀→МК₁→МК₂`. Кадры каждого интервала сопоставляются по нормированной позиции внутри интервала; циклы воспроизводятся совместно и зацикленно.

**Для режима по маркерам принято:**

- `МК₁→МК₂` задаёт один цикл от закрытия МК до следующего закрытия МК;
- `МК₀→МК₁→МК₂` задаёт два последовательных цикла; средний маркер позволяет отдельно выровнять длительность каждого RR, а не применять один коэффициент ко всему ролику;
- синхронизация не требует ЭКГ. В MVP маркеры ставит пользователь по видимому событию; ЭКГ может стать источником автоматических подсказок позднее, если машинно-читаемые данные действительно присутствуют в файле;
- изображения не интерполируются и не синтезируются. При растяжении исходные кадры дольше остаются на экране/повторяются, при сжатии часть кадров пропускается;
- скорость каждого клипа показывается явно. Фазово синхронизированный просмотр не считается воспроизведением в реальном времени.

**Граница первой версии:** воспроизведение, навигация, выбор клипов и маркеры. Инструменты измерений, контуры и LV-auto добавляются следующим этапом после появления корректной изоляции состояния каждого клипа. В первой версии эти инструменты в Multiview не должны молча работать только на основном viewer.

## 2. Цели и не-цели

### 2.1. Цели

- Одновременно просматривать два разных клипа из одного исследования.
- Уметь независимо листать клипы и явно видеть, какой клип сейчас выбран для взаимодействия.
- Запускать совместный playback двух клипов.
- Поддерживать быстрый повтор общей временной длительности и более точный повтор одного/двух событийно-ограниченных циклов.
- Не требовать ЭКГ, LV-контуров или расчёта ФВ для синхронизации.
- Сохранять исходные кадры и исходные измерения; не создавать синтетических кадров.

### 2.2. Не-цели

- Просмотр ED и ES одного и того же клипа как двух панелей.
- Автоматическое определение митрального клапана или автоматическая разметка его закрытия в MVP.
- Сравнение разных пациентов или продольное сравнение исследований.
- Автоматический диагноз гипокинезии, расчёт ФВ по движению или изменение алгоритма объёмов/контуров.
- Синтез, морфинг, optical flow-интерполяция или искусственное увеличение частоты кадров.
- Одновременное выполнение одного инструмента на обоих клипах.

## 3. Термины

- **Панель / pane:** область одного `ViewerWidget`, показывающая один SOP Instance.
- **Активная панель:** единственная панель, на которую направляются клавиатурные команды и (в будущей версии) инструменты.
- **Общий фрагмент:** одинаковый интервал реального времени, отсчитанный от выбранных стартовых кадров; конец определяется более коротким доступным фрагментом.
- **Маркер события:** ручная метка кадра, например закрытие митрального клапана (МК).
- **Фазовая позиция:** относительная позиция внутри интервала между двумя соседними маркерами, от 0 до 100%.
- **Коэффициент скорости `k`:** скорость воспроизведения отдельного клипа относительно исходной скорости: `k=1.0` — исходный темп, `k<1.0` — замедление, `k>1.0` — ускорение.

## 4. Вход в режим и поведение при выходе

### 4.1. Кнопка входа

- Добавить отдельную кнопку с пиктограммой двух панелей в системную/верхнюю панель рядом с кнопкой настройки раскладки.
- Tooltip: **«Два клипа рядом»**; в меню раскладки оставить чекбокс Multiview, синхронизированный с этой кнопкой. Оба entry point вызывают один обработчик переключения.
- В активном состоянии кнопка подсвечена.
- Второе нажатие выключает Multiview и возвращает основному viewer полную ширину.

### 4.2. Первое открытие

- Текущий клип остаётся в левой/основной панели.
- Правая панель открывается пустым placeholder: **«Выберите второй клип»** с подсказкой про Ctrl+клик в галерее.
- Не загружать автоматически тот же файл во второй viewer. Одинаковый файл не считается вторым клипом.
- Если клип ещё не выбран, обе панели показывают пустые состояния; инструменты воспроизведения и маркеров выключены.

### 4.3. Выход и повторный вход

- При выключении режима правая панель скрывается, но в рамках текущей сессии сохраняются выбранный файл, кадр и маркеры. Повторное включение восстанавливает состояние.
- При явной загрузке другого исследования/пациента обе панели, маркеры и временные состояния очищаются, чтобы не смешать данные разных исследований.
- Маркеры Multiview в первой версии не сохраняются между перезапусками, не экспортируются как DICOM-аннотации и не меняют доменные данные контура/ФВ.

## 5. Раскладка и органы управления

Внутри центральной области приложения:

```text
┌───────────────────────────────┬───────────────────────────────┐
│ Панель A: файл / вид / статус │ Панель B: файл / вид / статус │
├───────────────────────────────┼───────────────────────────────┤
│                               │                               │
│       изображение A           │       изображение B           │
│                               │                               │
├───────────────────────────────┼───────────────────────────────┤
│ slider A + маркеры            │ slider B + маркеры            │
└───────────────────────────────┴───────────────────────────────┘
┌───────────────────────────────────────────────────────────────┐
│ Независимо | Общий фрагмент | По маркерам | ▶▶ Пауза | Темп  │
└───────────────────────────────────────────────────────────────┘
```

### 5.1. Заголовок каждой панели

Показывает:

- имя файла/серии;
- метку вида (A4C/A2C/A3C/PLAX/SAX), если она доступна или задана пользователем; не угадывать её без подтверждения;
- кадр `n/N` и время, если время известно;
- состояние **Активна**;
- кнопку **Заменить клип** и меню панели.

Щелчок по заголовку или изображению активирует панель и рисует вокруг неё заметную рамку. Левая панель активна по умолчанию, если в ней есть файл. Если левая пустая, а правая загружена, активна правая. Если обе пусты, активной панели нет.

### 5.2. Панель общего транспорта

Постоянно расположена под двумя cine-панелями. Содержит:

- селектор режима: `Независимо`, `Общий фрагмент`, `По маркерам`;
- общие `Воспроизвести/Пауза` и `Стоп/Сброс к началу`;
- общий темп `0.5×–2.0×`, по умолчанию `1.0×`;
- состояние синхронизации, например `По времени` / `По фазе`, количество выбранных циклов и предупреждения о неизвестной частоте кадров;
- в режиме маркеров — `1 цикл: МК₁→МК₂` или `2 цикла: МК₀→МК₁→МК₂`.

В синхронных режимах повтор обязателен и включён всегда. Кнопка Play запускает оба клипа вместе; Pause ставит на паузу оба. Stop возвращает оба к начальным позициям выбранного режима.

### 5.3. Панельный транспорт и активность

- В режиме `Независимо` у каждой панели есть собственные Play/Pause и собственный slider.
- В синхронном режиме обе локальные кнопки отражают глобальное состояние: нажатие любой из них запускает/останавливает оба клипа.
- Клавиша Space: в `Независимо` переключает playback активной панели; в синхронных режимах — общий playback.
- Не переназначать Tab: сейчас он используется для цикла меток калипера.

## 6. Выбор второго клипа

### 6.1. Галерея

- Обычный клик по превью загружает клип в активную панель. При выключенном Multiview это остаётся загрузкой в основной viewer.
- `Ctrl+клик` по превью при выключенном Multiview режим не запускает сразу: клип открывается как обычно, а поверх галереи появляется оверлей-подсказка **«Выберите второй файл для запуска режима Multiview»**. Следующий клик по другому файлу включает Multiview и загружает его в правую панель; повторный клик по тому же файлу скрывает подсказку. При включённом Multiview `Ctrl+клик` по превью загружает клип в правую панель и активирует её.
- Контекстное меню превью в Multiview: **«Открыть слева»**, **«Открыть справа»**. При выборе клип загружается именно в указанную панель.
- Клип из другого исследования/пациента в первой версии не загружать в эту пару: показать понятное сообщение, что Multiview сравнивает клипы одного исследования. Это исключает случайное смешение исследований.
- Если выбранный SOP Instance уже открыт в другой панели, не дублировать его: активировать панель, где он уже открыт, и показать уведомление.

### 6.2. Замена и загрузка

- Замена клипа в панели останавливает синхронное воспроизведение, очищает её локальные маркеры/кадр/временные коэффициенты и загружает новый SOP Instance.
- Замена одного клипа не меняет другой.
- При ошибке чтения сохранять заголовок с ошибкой и возможность повторить загрузку; не показывать кадр предыдущего клипа под новым именем.
- Асинхронный ответ loader принимается только если совпадают SOP Instance UID и поколение запроса панели; устаревший результат не должен перерисовать уже заменённый клип.

## 7. Маркеры синхронизации

### 7.1. Общие правила

- Маркер ставится на текущем кадре **конкретной панели** кнопкой в её нижней панели управления. Он не зависит от того, какая панель активна.
- Тип события по умолчанию — `МК`; при необходимости пользователь может выбрать подпись `Другое событие`. В первой версии программная синхронизация использует позицию кадра, а не семантическое распознавание события.
- После установки на timeline отображается вертикальная цветная метка с номером, подписью события и номером кадра.
- Маркеры должны идти строго по времени вперёд; нельзя принять дубликат кадра или переставить последовательность местами.
- Маркер локален для SOP Instance. При замене клипа маркеры этого pane удаляются.
- Нужна команда `Очистить маркеры` отдельно для панели и `Очистить все`.
- Если клип содержит визуально неразличимое/отсутствующее МК, пользователь может отказаться от режима по маркерам и использовать `Общий фрагмент`; не подставлять автоматический маркер.

### 7.2. Быстрый однократный цикл: МК₁→МК₂

На каждой панели пользователь:

1. Колёсиком мыши или slider находит закрытие МК и нажимает `Задать МК₁`.
2. Находит следующее закрытие МК и нажимает `Задать МК₂`.
3. Повторяет то же для второго клипа.

Валидация разрешает запуск, когда у обоих клипов есть две корректно упорядоченные метки. При старте оба клипа показывают свои МК₁ одновременно. Общий playhead проходит от МК₁ до МК₂; достижение МК₂ в обеих панелях завершает интервал, после короткого общего endpoint hold (150 мс) оба возвращаются к МК₁.

### 7.3. Два последовательных цикла: МК₀→МК₁→МК₂

На каждой панели пользователь ставит три последовательных закрытия МК. Они задают два интервала:

- цикл 1: `МК₀→МК₁`;
- цикл 2: `МК₁→МК₂`.

Playhead сначала синхронно проходит цикл 1, на МК₁ переключается на цикл 2, затем на МК₂ возвращается к МК₀. Коэффициент скорости пересчитывается независимо для каждого цикла. Это позволяет отдельно компенсировать различия длительности первого и второго RR, а не применять одну среднюю скорость ко всему двухцикловому клипу.

Для будущего расширения на `N` циклов требуется `N+1` последовательных меток одного события; первая версия UI предлагает только один или два цикла.

### 7.4. МК на разных проекциях

Пользователь задаёт один и тот же механический ориентир там, где он виден. Если закрытие МК неразличимо, клип не включается в синхронизацию по МК до ручного выбора альтернативной соответствующей метки. Например, не следует заставлять пользователя ставить МК на SAX LV Pm, где сам клапан не виден.

## 8. Режимы воспроизведения и коэффициенты скорости

### 8.1. Независимо

- Колесо мыши, slider и Play/Pause действуют только на панель под курсором/активную панель.
- Воспроизведение одного клипа не меняет кадр второго.
- Конец клипа обрабатывается существующим циклическим проигрыванием; общий repeat не задействован.

### 8.2. Общий фрагмент — грубый режим без фазовых маркеров

1. Пользователь независимо выставляет стартовый кадр в A и B.
2. Нажимает `Воспроизвести вместе`.
3. Оба клипа стартуют по одному монотонному clock с исходной скоростью.
4. Общая длительность фрагмента равна минимуму из доступных времён после стартовых кадров:
   `T_common = min(T_left_remaining, T_right_remaining)`.
5. По истечении `T_common` оба сбрасываются к своим стартовым кадрам и автоматически повторяют этот общий временной фрагмент.

В более длинном клипе не проигрывается часть после общего конца. На timeline каждого pane показываются свой старт и общий endpoint. Режим помечается **«по времени, не по фазе»**: общий запуск сам по себе не доказывает совпадение сердечных фаз и не является циклической разметкой.

### 8.3. По маркерам — нормализация по фазе

Для каждого парного цикла `j` рассчитывается исходная длительность клипов по временным меткам кадров:

- `T_left,j` — длительность интервала между маркерами в левом клипе;
- `T_right,j` — длительность соответствующего интервала в правом клипе;
- при глобальном темпе `r` (по умолчанию `1.0×`) общая длительность отображаемого цикла:
  `T_display,j = mean(T_left,j, T_right,j) / r`;
- коэффициент для каждого клипа:
  `k_i,j = T_i,j / T_display,j`.

Интерпретация `k`: `k=1` — исходная скорость, `k<1` — растянуть/замедлить этот интервал, `k>1` — сжать/ускорить. Для `МК₀→МК₁→МК₂` формула отдельно применяется к `МК₀→МК₁` и `МК₁→МК₂`.

Пример при темпе `1.0×`:

| Клип | Исходный интервал | `T_display` | Коэффициент |
|---|---:|---:|---:|
| A | 0,80 с | 0,90 с | 0,89× (замедлить) |
| B | 1,00 с | 0,90 с | 1,11× (ускорить) |

Оба интервала будут занимать 0,90 секунды на экране. В UI показываются `0.89×` и `1.11×` рядом с соответствующими панелями; в двухцикловом режиме значение может измениться после МК₁.

### 8.4. Как растягивается/сжимается видео

- Время общего playhead преобразуется в нормированную позицию `p` внутри текущего цикла (`0…1`).
- Для каждой панели эта позиция отображается на её собственный интервал между маркерами с учётом временных меток исходных кадров.
- Показывается ближайший доступный **оригинальный** кадр. При замедлении некоторые кадры удерживаются дольше; при ускорении часть кадров пропускается. Никакие промежуточные изображения не создаются.
- В цикле используются исходные кадры от первого маркера до кадра второго маркера включительно. На втором маркере — общая пауза 150 мс, затем возврат к первой метке.
- Если известна только частота кадров, длительность рассчитывается по ней. Если кадровые timestamps и fps недоступны, разрешена только фазовая навигация по frame index; UI показывает `время неизвестно`, не выдаёт коэффициент в секундах и не заявляет синхронизацию реального времени.
- При коэффициенте вне `0.5×–2.0×` показать предупреждение с точными коэффициентами и предложить отменить либо явно продолжить. Коэффициент не ограничивается молча: ограничение нарушило бы совпадение маркеров.
- Разная длительность клипов или RR не скрывается: исходная длительность каждого интервала доступна в подписи/tooltip.

### 8.5. Ограничение интерпретации

Фазовая синхронизация сопоставляет выбранные маркеры и относительный прогресс между ними; она **не означает реальное одновременное получение двух проекций** и не доказывает совпадение всех механических событий внутри цикла. UI должен различать режим `По времени` и режим `По фазе`.

## 9. Перемотка колесом мыши и ручное позиционирование

- Колесо над областью изображения листает кадры только того клипа, над которым находится указатель, если playback независимый или синхронизация ещё не запущена.
- Сохраняются текущая инверсия направления, шаг и debounce `ViewerWidget`.
- Колесо над галереей, заголовком, панелью маркеров или control bar не должно менять кадр.
- В синхронном режиме колесо над любой областью изображения двигает **общий playhead**: по времени в режиме `Общий фрагмент`, по фазе текущего цикла в режиме `По маркерам`. Оба клипа обновляются согласованно.
- Для индивидуальной доводки после синхронизации пользователь нажимает `Независимо`/`Развязать`; дальнейший wheel действует только на панель под указателем. Маркеры при этом сохраняются.
- Ручное изменение любого маркера во время playback автоматически ставит оба клипа на паузу и переводит управление в режим разметки маркеров.
- Клик по маркеру timeline перемещает соответствующий pane в независимом режиме; в режиме по маркерам выбор позиции/перетаскивание маркера до фиксации перемещает общий playhead и временно приостанавливает playback.

## 10. Активная панель и инструменты

### 10.1. Выбор активной панели

- В Multiview всегда ноль или одна активная панель, никогда две одновременно.
- При входе выбирается загруженная левая панель; если левая пустая — загруженная правая.
- Щелчок по изображению или заголовку меняет активную панель; загрузка через Ctrl+клик делает активной правую.
- Наведение мыши не меняет активность — только явный click, чтобы не перенаправлять клавиши неожиданно.
- Активность видна рамкой и подписью; она сохраняется при потере фокуса приложения.
- Если активной панели нет/она не содержит файл, команда инструмента не должна молча переключаться на основной viewer. Показать **«Выберите загруженный клип»**; для команды с явным target можно показать компактный выбор панели.

### 10.2. Решение по измерительным инструментам

**Этап 1:** Multiview — просмотр, wheel, zoom/pan, выбор маркеров и транспорт. Измерения, контуры, Doppler-инструменты и LV-auto отключены с объяснением, пока не готова pane-scoped модель состояния. Не направлять их скрытно в основной viewer.

**Целевое поведение следующего этапа:**

- Все инструменты выполняются только в активной панели.
- Контуры, калибровки и измерения принадлежат конкретным `StudyInstanceUID + SeriesInstanceUID + SOPInstanceUID + frame index`, отображаются только на соответствующем клипе и не смешиваются с результатами второго.
- Запуск инструмента при отсутствии активного загруженного pane заблокирован с подсказкой выбора.
- Переход на другой клип останавливает инструмент или запрашивает подтверждение; незавершённая геометрия не переносится на другой SOP Instance.
- Одновременное рисование на двух панелях не поддерживается.

### 10.3. LV-auto

LV-auto не должен запускаться сразу на обеих панелях и не должен угадывать target по последнему изменённому клипу.

Когда LV-auto будет поддержан:

1. Пользователь явно активирует панель с подходящим LV-view.
2. `LV Auto` показывает, на каком клипе/виде будет расчёт.
3. Если активной панели нет, команда заблокирована и предлагает выбрать панель.
4. Если активная панель пустая или несовместимая, расчёт не запускается; сообщается причина.
5. Результат хранится и показывается только для target instance/frame; после переключения панели сегментация не должна визуально «переехать» на второй клип.
6. Во время playback синхронных панелей запуск блокируется; сначала нужна пауза.

В существующей архитектуре второй viewer сейчас получает пиксели отдельно от основного состояния/controller, поэтому этот этап требует отдельного рефакторинга; подключить существующую кнопку без pane-scoped состояния небезопасно.

## 11. Состояние, загрузка и устойчивость

Рекомендуемый объект сессии Multiview:

```text
MultiViewSession
  panes[A, B]:
    instance_uid, study_uid, series_uid
    current_frame, timestamps/frame_rate
    markers[]
    active_tool_state (только после этапа 1)
  active_pane: A | B | None
  playback_mode: independent | common_window | event_cycle
  selected_cycle_count: 1 | 2
  common_playhead, global_rate, is_playing
```

- Состояния двух pane независимы; одна общая модель playback связывает их только в выбранном синхронном режиме.
- Общий clock основан на монотонном времени; не на двух несвязанных `QTimer`, увеличивающих frame index на единицу.
- Загрузка кадра асинхронна. Для синхронного playback устаревшие промежуточные запросы можно объединять/отбрасывать, но итоговый отображённый кадр должен соответствовать текущему playhead.
- Ошибка декодирования в одном pane не останавливает приложение; общий playback сообщает о проблеме, ставит оба клипа на паузу и сохраняет позиции.
- При удалении/замене файла или смене исследования остановить общий playback и очистить маркеры соответствующего pane.
- Сохранённые результаты одного клипа не отображаются на другом только потому, что он активен.

## 12. План реализации

### Этап 0 — подготовка

- Зафиксировать текущие события выбора, загрузки, playback и wheel.
- Разделить состояние viewer1 и viewer2; удалить автоматическую подстановку основного клипа во второй pane при переключении главного instance.
- Решить жизненный цикл cache/loader и защиту от устаревших ответов.

### Этап 1 — надёжный двухклиповый просмотр

- Кнопка входа, пустое состояние второй панели, загрузка клипа в конкретную панель.
- Заголовки, frame slider, активная рамка, независимые Play/Pause и wheel.
- Вход из галереи: обычный клик в активную панель, Ctrl+клик во вторую, защита от дубля instance и другого исследования.
- Пока без контуров и измерений.

### Этап 2 — общий фрагмент

- Выбор старта каждой панели.
- Один монотонный playback clock, запуск одновременно, конец по минимальной оставшейся длительности, обязательный повтор от стартов.
- Показывать режим как временной, не фазовый; тестировать разную кадровую частоту.

### Этап 3 — маркерная синхронизация

- Ручные МК-маркеры на каждом pane.
- `МК₁→МК₂` (один цикл) и `МК₀→МК₁→МК₂` (два цикла).
- Нормированная фазовая шкала, отдельный коэффициент для каждого pane/цикла, предупреждение о сильном ретайминге.
- Только исходные кадры, никакой интерполяции.

### Этап 4 — инструменты

- Pane-scoped ручные измерения и оверлеи.
- Затем LV-auto после переноса состояния сегментации на явный pane/session target.
- Doppler/STE и другие крупные инструменты — отдельными задачами, не считать автоматически поддержанными.

## 13. Критерии приёмки

### Layout и выбор файлов

- Вход в Multiview сохраняет текущий клип слева и показывает пустой правый pane, не клонируя файл.
- Ctrl+клик при выключенном режиме готовит запуск (подсказка + первый клип), клик по второму файлу включает режим и грузит его справа; при включённом режиме Ctrl+клик сразу грузит клип справа.
- Повторный SOP Instance не создаёт дубль; другой study/patient блокируется с объяснением.
- Замена одного клипа не меняет файл, кадр или маркеры другого.
- Выход и повторный вход в текущей сессии сохраняют второй клип; смена исследования очищает обе панели.

### Маркеры и playback

- Wheel до маркеров двигает кадр только панели под курсором.
- Маркеры нельзя поставить вне временного порядка; маркеры привязаны к правильному SOP Instance.
- В `Общий фрагмент` оба запускаются вместе, останавливаются на минимальной оставшейся длительности и зацикливают один и тот же общий временной фрагмент.
- В `МК₁→МК₂` маркеры обоих клипов одновременно совпадают на старте и на каждой границе повтора.
- В `МК₀→МК₁→МК₂` цикл 1 и цикл 2 имеют отдельные коэффициенты; на МК₁ синхронность не теряется.
- Pause, resume, stop, ручной перевод в независимый режим и wheel не создают незаметного рассогласования.
- При fps/timestamps разного качества UI явно помечает приблизительную/только фазовую синхронизацию.
- Отображаемые коэффициенты соответствуют расчёту; кадры не создаются синтетически.

### Активная панель и инструменты

- Click переключает активную панель; Space действует согласно выбранному playback mode.
- На этапе 1 инструменты измерений и LV-auto не выполняются на скрытом/неактивном viewer.
- На будущих этапах запуск при `active_pane=None` безопасно блокируется; LV-auto никогда не запускается одновременно на обоих клипах.

### Устойчивость

- Поздний ответ загрузчика для старого клипа не перерисовывает новую панель.
- Длительный cine и повторные циклы не накапливают независимые таймеры/потоки.
- Переключение режима, замена клипа и закрытие окна останавливают совместный playback.

## 14. Текущие расхождения с реализацией

На момент составления плана `main_window.py`:

- Multiview включается через layout menu или Ctrl+клик по галерее.
- Второй viewer создаётся лениво и получает кадры через отдельную загрузку.
- `_sync_viewer2_state()` и `_on_state_changed_for_viewer2()` могут подтягивать во второй pane тот же instance, что и в основной; для независимых клипов это поведение необходимо заменить.
- Playback второго viewer использует отдельный `QTimer` и frame index, оборачивает весь клип; общего транспорта и событийных циклов нет.
- Вторая панель получает изображение, но не полный набор оверлеев/контуров текущего main viewer.
- Event filter уже назначает `_active_viewer` по клику, но глобальные действия в основном опираются на основной controller.

Эти ограничения объясняют порядок реализации: сначала независимое состояние и общий transport, затем маркеры и только потом инструменты.
