## 3. Ключевые находки, влияющие на порядок работ

1. **Multiview не влит в `main`, PR нет.** Ветка `arena/01a0f5c0-sonoforge` (коммиты `744be3f` спецификация, `0a9a2bc` доменная модель и математика таймингов, `c6734ba` презентационный слой): 24 файла, +5559/−149. Затрагивает `main_window.py` (около 540 строк правок), `system_bar.py`, `thumbnail_gallery.py`, `viewer_widget.py` — те же файлы, что нужны вкладкам, приветствию и галерее. В её спецификации измерения в панелях отложены до «изоляции состояния по панелям» (Этап 4) — это та же задача, что и состояние вкладки. `clips_are_comparable()` пока блокирует клипы из разных исследований. Вывод: сначала влить multiview, потом вкладки (Э0 → Э9 → Э10).
2. **Кэш PACS стирается при выходе** (`OrthancSessionCache.clear_all()` в `MainWindow.closeEvent`). Основной сценарий пользователя (около 95%) — PACS, поэтому «Последнее» и сохранённые измерения после перезапуска требуют решения по кэшу (П.12).
3. **Логи Windows-сборки почти слепые** (П.10): у оконного exe (`console=False`) нет stderr, файловые логи покрывают два модуля и 8 модулей загрузки, файлы перезаписываются при каждом запуске.
4. **Допплер не различает клапаны** (П.8): пункты меню AV и MV ставят одну метку `Vmax`; итог по исследованию склеивается по метке (побеждает последняя); VTI усредняются по всем трассам всех клапанов; `pgpeak` считается только от `Vmax` или трассы и в отчёте лежит в группе «Аортальный клапан».
5. **GUI-тесты на Windows и macOS в CI не запускаются** (`pytest -m "not gui"`), поэтому Windows-специфичные правки (диалоги, масштаб) не имеют автоматического покрытия. В `CHANGELOG.md` (Unreleased → «Проверка») зафиксированы 6 падающих тестов, воспроизводимых на базовом коммите.
6. **`docs/superpowers/plans/` в `.gitignore`** («Internal dev plans and specs (not shipped)»), поэтому этот план лежит в `docs/superpowers/specs/`, как и спецификация multiview.

## 4. Темы

### П.1 Вкладки для нескольких исследований

**Запрос.** Закладки (вкладки) для нескольких исследований.

**Принято** (D-02…D-05, D-14)

- Вкладки как в браузере под верхней панелью кнопок и строкой статуса. Допущение: «строка статуса» — строка с названием исследования в `SystemBar`; она переезжает в заголовок вкладки.
- Единица вкладки — папка.
- Вариант B (лёгкий снимок сессии на общем «движке»).
- Multiview между исследованиями — П.13. Одновременный показ двух исследований рядом не планируется, кроме одного заранее выбранного файла из каждой папки.
- PACS: второе и следующие исследования раскладываются по вкладкам автоматически (П.9).

**Факты (код)**

- `AppController` — одна сессия: один `ViewerState` (`StateManager`), один кэш кадров (бюджет до 8% свободной ОЗУ), один таймер воспроизведения, одна очередь миниатюр (счётчик поколений), один список `_studies`.
- `open_folder()` и `load_pre_scanned_studies()` вызывают `_measurement_session.clear()`: открытие второй папки стирает измерения первой.
- `StudyMeasurementSessionStore` хранит неизменяемые `StudyMeasurementData` по `study_uid` (контуры, калиперы, допплер по инстансам и кадрам, калибровки, M-mode, сосуды, ручной pixel spacing, рост и вес, strain) — это почти готовое содержимое вкладки.
- Часть состояния живёт во вьюере и в `MainWindow`: допплер-маркеры и калибровка (локально во вьюере), `_instance_overlay_cache`, `_instance_overlay_positions`, `_study_overlay_positions`, ED/ES-кадры, окно STE, M-mode. При смене клипа оно уже сохраняется в `MainWindow._on_instance_selected` — этот код можно переиспользовать при смене вкладки.
- Измерения хранятся только в памяти (автосохранения нет), см. П.12.
- Галерея одна (`ThumbnailGalleryWidget`); `populate()` сбрасывает кэш миниатюр (до 200 pixmap).
- Окно безрамочное; `SystemBar` содержит `_study_label` и кнопки; меню «Файл» нет.
- `MainWindow` около 3,2 тыс. строк, `AppController` около 3,9 тыс. строк.
- Multiview в `main`: Ctrl+клик по миниатюре открывает клип во втором вьюере (`_viewer2`); кадры грузятся отдельным `FrameLoaderWorker` по пути файла.

**Рассмотренные варианты**

- A — на вкладку отдельные контроллер и вьюер: просто, но тяжело (у каждого свой кэш кадров, декодеры, таймер; возможно одновременное воспроизведение).
- B — вкладка = снимок сессии на общем «движке», неактивные «засыпают» (выбран, D-04).
- C — без вкладок: не стирать измерения и переключать исследования секциями галереи (П.7).

**Предложено** (ПРЕДЛОЖЕНО)

- Состав вкладки: источник (папка или исследование с PACS), результат сканирования, выбранный клип и кадр, прокрутка и масштаб галереи, кэши оверлеев, ссылка на измерения, **закреплённый клип «для сравнения»**. Общие для всех вкладок: кэш кадров, декодер, таймер воспроизведения. При смене вкладки воспроизведение ставится на паузу, неактивные вкладки «засыпают» (кэш кадров сбрасывается, метаданные и измерения остаются).
- «Новая вкладка» = приветственная страница (П.2): одна механика на два пункта.
- Управление: Ctrl+T, Ctrl+W, Ctrl+Tab (Tab занят циклом меток калипера); закрытие средней кнопкой; перетаскивание; контекстное меню («Закрепить для сравнения», «Закрыть другие», «Показать в проводнике»); лимит 8–10 вкладок.
- Заголовок: имя папки + дата; для PACS «ФИО · дата» с настройкой «скрывать ФИО» (по умолчанию скрыто в Presenter).
- Порядок реализации (Э9): слой сессии без UI → полоса вкладок → PACS во вкладки → закрепление клипа.

**Не решено** (НЕ РЕШЕНО): Q-08 (поведение «Открыть папку», лимит вкладок, ФИО в заголовках).

### П.2 Приветственная страница

**Запрос.** Приветственное окно «Открыть / Последнее / Недавние».

**Принято** (D-06, D-07, D-08, D-10)

- Вариант B: страница внутри главного окна, не модальное окно.
- На ней краткий help по инструментам и горячим клавишам и полезные кнопки (язык интерфейса, настройки, справочник, help и т.д.).
- «Последнее» восстанавливает только папку; «недавние» — папки.

**Факты (код)**

- `startup_mode` принимает `empty` (по умолчанию — пустое окно) и `last_folder`; хранится в `UserPreferences` (`user_preferences.py`), `last_opened_folder` — одна строка.
- `main.py` открывает последнюю папку через `QTimer.singleShot(200)`, проверяя `is_dir()` в GUI-потоке (недоступный сетевой путь может подвесить запуск).
- `last_opened_folder` пишется только в `MainWindow._open_folder` (диалог), но не при загрузке с PACS и не при автооткрытии.
- Списка «недавних» нет, меню «Файл» нет, режима `welcome` нет.
- Переключение языка «на лету» есть (`_reload_ui_language`, `register_ui_reload`); тест `test_locale_key_parity` проверяет паритет ключей `en.json` и `ru.json`.
- Справочник скрыт в Presenter (`has_reference_ui()`); в exe модели ИИ скачиваются при первом запуске (`runtime_setup`).
- Единого реестра горячих клавиш нет: список в `_install_shortcuts` (`main_window.py`) плюс клавиши во вьюере.
- Presenter хранит настройки в INI рядом с exe (портативно).
- Сайт заявляет «локально — без облака и телеметрии».

**Рассмотренные варианты:** (a) модальное окно перед главным; (b) страница внутри окна (выбран): нет второго top-level окна (на безрамочном окне с ручным maximize — лишние проблемы с фокусом), совпадает с «пустым состоянием» без вкладок, принимает drag-and-drop папки.

**Предложено** (ПРЕДЛОЖЕНО)

- Основное: «Открыть папку», «С сервера», «Продолжить: <папка, дата, число клипов>», «Недавние» (закрепить / убрать / очистить; недоступные пути серым; существование путей проверять лениво).
- Справка: карточки по инструментам и горячим клавишам, строятся из единого реестра клавиш (его нужно создать, N-05); ссылки на Help и справочник.
- Кнопки: язык интерфейса, настройки, справочник (в Presenter скрыт), Help, версия.
- Статус: установлены ли модели ИИ, настроен ли профиль PACS.
- Обновления — только по желанию (opt-in): сайт обещает «без телеметрии», любой сетевой запрос должен быть явным.
- Режимы запуска `startup_mode`: `welcome`, `last`, `empty`.
- Недавние в Presenter по умолчанию выключены; везде есть «Очистить».
- Страница подписывается на перезагрузку языка.
- Подсказка про масштаб (П.5): «Экран 4K при 100% — установить 150%?».

### П.5 Масштабирование и 4K

**Запрос.** Проблемы масштабирования на мониторах 4K.

**Принято** (D-12): интерфейс мелкий — кнопки, надписи, инструменты измерений, шрифт оверлея; причина — хардкоды размеров; скриншота нет.

**Факты (код)**

- В `main.py` нет настроек масштаба. Qt 6 по умолчанию Per-Monitor DPI Aware V2 с политикой округления PassThrough; документация Qt советует целые коэффициенты и допускает артефакты на дробных.
- 144 вызова `setFixed*`, `setMin*`, `setMax*`, `resize`; порядка 570 вхождений «NNpx» в стилях; 96 объявлений `font-size: …px` против 4 `pt`.
- `ui_font_size` (по умолчанию 12, диапазон 9–18) попадает в глобальный стиль в **px** (`dark_theme.py`), а шрифт приложения задаётся тем же числом в **pt** (`main.py`): смесь единиц.
- Миниатюры всегда генерируются в рамку 96 px (`ThumbnailLoaderWorker`, `preview_size` не меняется), а галерея рисует их в ячейки до 176×132 логических px: на масштабе 150–200% «мыло».
- Иконки диалогов рисуются в `QPixmap(16, 16)`; `setDevicePixelRatio` на весь код встречается один раз.
- Шрифт оверлея результатов: диапазон 10–28 px, по умолчанию 20. Маркеры инструментов в pyqtgraph зашиты (10–14 px). Толщина линий калипера и контуров настраивается (1–6).
- `apply_maximized_to_work_area()` берёт экран до показа окна; на мониторах с разным масштабом размер может быть неверным (ГИПОТЕЗА).
- Фиксированные размеры: PACS-диалог 800×520, панель инструментов 280 px, миниатюры 72–176 px.
- Presenter уже имеет пресет «крупнее для проектора» (`PRESENTATION_PRESET_OVERRIDES`: шрифт UI 14, оверлей 24, линии 3.5) — готовая идея.
- В Presenter уже исправляли HiDPI-ошибку (letterbox через `devicePixelRatio`, CHANGELOG v0.3.1): DPI-проблемы в проекте встречались.

**Классы проблем** (раунд 1): (a) Windows 100% на 4K — всё мелко; (b) дробные 125/150% — округление, размытость pixmap; (c) смешанный DPI на нескольких мониторах (в т.ч. второй дисплей Presenter); (d) pyqtgraph-вьюер и оверлеи.

**Предложено** (ПРЕДЛОЖЕНО)

- **Основное решение:** настройка «Масштаб интерфейса» (Авто, 100…250%), применяется через `QT_SCALE_FACTOR` до создания `QApplication`, нужен перезапуск. Qt использует этот коэффициент как есть (политика округления на него не влияет) и масштабирует все логические пиксели разом: стили, фиксированные размеры, маркеры pyqtgraph, радиусы захвата точек, — без правки сотен мест. Ручной `px()`-хелпер — только для исключений.
- Отдельно: (1) миниатюры и иконки рендерить с учётом DPR; (2) шрифт оверлея — расширить диапазон или привязать к высоте изображения; (3) множитель размера маркеров инструментов; (4) maximize и мониторы с разным масштабом; (5) привести `ui_font_size` к одной единице.
- Проверка: офскрин-скриншоты окна при `QT_SCALE_FACTOR` 1.0, 1.5, 2.0 для поиска обрезаний (не заменяет реальный 4K); справочник (QtWebEngine) проверить отдельно.
- Подсказка на приветственной странице про масштаб при 4K на 100%.

**Не решено** (НЕ РЕШЕНО): Q-06.

### П.8 Допплер: TRmax → PGmax, каталог измерений, единицы

**Запрос.** Для TRmax нет расчёта PGmax. Расширено пользователем (D-16, D-17): PGmax для всех измерений Vmax на всех клапанах и в калипере; единицы по режиму.

**Принято** (D-16, D-17): PGmax для каждого результата Vmax на любом клапане и в допплеровском калипере; CW — м/с, PW и TDI — см/с, давление — мм рт. ст.

**Факты (код)**

- Маркер `TR Vmax` (пункт меню «TRpeak»; в локали `result.tr_vmax` = «TRpeak»): `compute()` берёт `tr_vmax_cm_s` и на этом останавливается. PG для TR нет нигде: ни в оверлее, ни в панели, ни в рабочем листе, ни в отчёте.
- `pgpeak_mmhg` считается только от маркера `Vmax` или от VTI-трассы (`pressure_gradient_mmhg` = 4·v², `bernoulli.py`); в отчёте он лежит в группе «Аортальный клапан».
- Пункты меню AV и MV ставят одну и ту же метку `Vmax` (`doppler_peak="Vmax"`).
- Итог по исследованию (`StudyMeasurementData.all_doppler_dto`) склеивает маркеры по метке (побеждает последняя, `merge_doppler_peaks`) и усредняет VTI по всем трассам всех клапанов (`_find_vti_cm` берёт любые метки, начинающиеся на «vti»).
- Скорость маркера хранится со знаком (`velocity_cm_s_from_y`: ниже базовой линии — минус); струя ТР в апикальных проекциях обычно ниже базовой. По коду `TRpeak` может показываться как `-312.0 cm/s`, а критерий `TR Vmax > 280` в `grade_diastolic_function` и проверка нормы в отчёте для отрицательного значения не срабатывают. Для трасс модуль скорости уже берётся (есть тесты), для маркеров — нет. В тестах `compute()` TR не покрыт. Выводы по коду; на реальном спектре не проверено.
- Тип допплера из DICOM уже разбирается для панели свойств (`properties_extractor.py`: `RegionDataType` 3 = PW, 4 = CW, 0x10 и 0x11 = TDI).
- TR Vmax показывается в см/с; нормы справочника (`references_structured.yaml`) заданы в м/с (порог 2,8 м/с ≈ 31 мм рт. ст.; ESC/ERS 2022: 2,9–3,4 м/с — промежуточная вероятность, больше 3,4 м/с ≈ 46 мм рт. ст. — высокая).
- Допплеровский калипер (PR #89) измеряет Δt (мс) и амплитуду скорости (см/с) внутри откалиброванной зоны.
- Подписи в UI: «TRpeak», «PG peak / РГпик», «PG mean / РГср»; пользователь говорит «TRmax», «PGmax».

**Предложено** (ПРЕДЛОЖЕНО)

- **Каталог измерений** в домене: участок (AV, LVOT, MV, TV, PV, RVOT, AR, MR, TR, PR), режим (CW, PW, TDI), вид (пик, VTI, интервал, калипер), единицы, производные (PGmax, PGmean…), группа отчёта, справочный параметр, знак. Заменяет разрозненные списки: `_PEAK_LABELS` в `doppler_overlay.py` и `doppler_widget.py`, меню, алиасы в `compute()`, `report_builder`, форматтеры, рабочий лист.
- **Метки по участкам:** `AV Vmax`, `LVOT Vmax`, `MV Vmax`, `TR Vmax`, `PR Vmax`, `AR Vmax`, `PV Vmax`, `RVOT Vmax`; трассы `VTI LVOT`, `VTI AV`, `VTI RVOT` и т.д. Старую метку `Vmax` относить к AV с пометкой.
- **Режим** по умолчанию из DICOM (`RegionDataType`); для MP4 и JPEG — переключатель режима в допплер-панели; явный выбор приоритетнее.
- **Единицы** — функция (режим, величина): CW — м/с; PW и TDI — см/с; градиент — мм рт. ст. Хранение остаётся в см/с, миграции данных нет.
- **PGmax = 4·V²** (упрощённый Бернулли) для всех Vmax. E, A, e′, a′, s′ — без PG по умолчанию (Q-07). Полная формула 4·(V₂² − V₁²) с учётом скорости до клапана — позже, в калькуляторах.
- **Знак:** нормализовать по модулю (затрагивает диастолический критерий и проверку нормы в отчёте).
- **Показ:** подпись у маркера на спектре («TR Vmax 3,12 м/с · PGmax 39 мм рт. ст.»), оверлей, панель, рабочий лист (строка на участок), отчёт (по группам клапанов).
- **Итог по исследованию** — по участкам, а не «по метке с усреднением всех VTI».
- **Подписи:** «PG peak / РГпик» → PGmax, «TRpeak» → TR Vmax; RU-вариант — Q-07.
- **Допплеровский калипер:** если результат — скорость, показывать скорость и PG по режиму; время — без PG.
- **Миграция** поэтапно: каталог рядом со старой моделью (адаптер) → перенос потребителей → удаление старого.
- **Тесты:** параметризованные по участку и режиму, с эталоном (2,8 м/с → 31 мм рт. ст.; 4,0 м/с → 64 мм рт. ст.); тесты на знак.
- **PASP/RVSP** = PG + давление в правом предсердии (3, 8 или 15 мм рт. ст. по НПВ) — отдельным шагом (П.11); сейчас НПВ и давления в ПП в приложении нет.

**Не решено** (НЕ РЕШЕНО): Q-07; N-02 (несколько измерений одного параметра и усреднение).

| dP/dt, мм рт. ст./с | 32 / Δt (с) между 1 и 3 м/с на CW-спектре MR |

### П.12 Хранение измерений и «Последнее»

**Уточнение 2026-10-03:** подготовлен отдельный [draft WP4.1 — постоянное хранение измерений](2026-10-03-wp4-1-measurement-persistence-spec-ru.md).

В частности, хранение до явного удаления вместо LRU последних N исследований и возможность начать WP4.1 до Э2 — **новые предложения**, а не принятые решения.
Q-03/Q-04 остаются открытыми до согласования; Q-05 («Последнее»/автодокачка PACS) вынесен за scope WP4.1.
Сохранение роста/веса остаётся WP4.2. Исторические предложения ниже сохранены для сравнения.

**Запрос и решения:** D-08, D-09, D-18.

**Факты (код)**

- `StudyMeasurementSessionStore` — только память («до конца сессии приложения»); ключ — `study_uid`, элементы по SOP UID.
- Для не-DICOM папок UID синтетический (`local:<sha256 пути>`).
- Кэш PACS (`OrthancSessionCache`, корень `orthanc_cache_root()`) стирается при выходе.
- `last_opened_folder` — единственная запись о последней папке.
- Presenter хранит настройки и кэш рядом с exe.
- Автосохранения измерений нет (есть экспорт отчёта и gold-режим).

**Рассмотренные места хранения**

| Вариант | Плюсы | Минусы |
|---|---|---|
| 1. `%LOCALAPPDATA%\SonoForge\…`, ключ `StudyInstanceUID` (предложение пользователя + уточнения) | работает для PACS (путь временный); не Roaming; переживает переустановку; ничего не пишем в папки пациентов | невидимо для пользователя; не переносится вместе с данными |
| 2. Sidecar-файл рядом с исследованием | переносится с данными, виден | пачкает папки пациентов; не работает на носителях только для чтения; для кэша PACS бесполезен |
| 3. Гибрид: (1) + явный экспорт и импорт файлом | переносимость без мусора | немного больше работы |

**Предложено** (ПРЕДЛОЖЕНО; рекомендация — вариант 3)

- Local, не Roaming: данные пациентов не должны уезжать с доменным профилем.
- Ключ — `StudyInstanceUID` (для не-DICOM — синтетический UID), а не путь: после повторной загрузки с PACS (другая временная папка) измерения вернутся на место.
- Автосохранение через 1–3 с после изменения и при закрытии вкладки или приложения; атомарная запись (temp + rename); версия схемы; JSON-кодек для `StudyMeasurementData`.
- Автовосстановление при открытии со строкой «Восстановлено от … [Сбросить]»; «Сбросить измерения» стирает и файл.
- Срок хранения: LRU, последние N исследований (N=1 — вариант «пока не сменится другим»; при вкладках N не меньше числа открытых); настройка и «Очистить всё».
- Presenter: по умолчанию не сохранять; при включении — в портативную папку.
- Экспорт и импорт измерений файлом (перенос между ПК).
- Приватность: файлы не содержат ФИО; рост и вес — демография, режим тот же.
- Порядок: сначала каталог измерений (П.8), затем хранилище, чтобы не мигрировать схему.
- **«Последнее» и PACS:** (а) хранить сервер, UID и серии и докачивать по «Продолжить» (по умолчанию); (б) не стирать кэш последнего исследования до следующей загрузки (галочкой; данные пациента остаются на диске после выхода — решение политики безопасности пользователя).
- Вкладки: тот же ключ; каждая вкладка сохраняет свои исследования.

**Не решено** (НЕ РЕШЕНО): Q-03, Q-04, Q-05.
