## 1. Проблема

| Что есть сейчас | Почему этого недостаточно |
|---|---|
| `ecg_rpeak_detector.py` — Pan–Tompkins, `ecg_ed_es_mapper.py` — ED по первому R-пику, ES = `ED + 0,35·RR` | Один цикл на весь ролик; ES — фиксированная доля RR, а не механическое событие; времена R-пиков отсчитываются от начала записи ЭКГ и делятся на `frame_time_ms` без учёта `TriggerTime` / `TriggerSamplePosition` (см. STE_IMPROVEMENT_PLAN §2.5); при нерегулярном ритме усреднение RR недопустимо |
| `cardiac_cycle_detector.py` — FFT ЧСС и ED/ES по кривой площади; `heart_rate.py` — optical flow + area-time | Дают **период** или один ED/ES, но не разметку **каждого кадра** на систолу/диастолу и не confidence |
| `cardiac_cycle_service.py` — циклы из ЭКГ или огибающей допплера | Работает только для спектрального допплера, не для B-mode кино |
| `ui/cine_panel.py::_PhaseMarkerBar` | Явная заглушка: два приглушённых чипа «S»/«D» на третях шкалы; в комментарии прямо сказано, что «phase-evaluation mechanism is not designed yet» |
| `viewer_widget.py::_timeline_slider` (основной просмотрщик) | Полоса воспроизведения вообще не показывает фазы; ЭКГ-полоска (`EcgStripWidget`) показывается только в допплеровском режиме |
| `multiview_marker_strip.py` | Готовый паттерн «полоса над слайдером, выровненная по его дорожке», но маркеры — ручные события, не фазы |

**Цель:** единый доменный сервис, который для любого ролика возвращает покадровую разметку
`систола / диастола / неизвестно`, границы каждого цикла (ED, ES), источник решения и честную оценку
уверенности. Одинаковые маркеры при этом рисуются на полосе воспроизведения и в окне STE, и в основном
просмотрщике.

**Не цель (P0):** клинически валидированный детектор AVC, измерение QT, замена ручного выбора ED/ES в
Simpson/STE-протоколах, анализ M-mode и цветового допплера, автоматическое исправление сохранённых измерений.
Маркеры — **визуальная подсказка и навигация**, а не измерение: при низкой уверенности фазы не
раскрашиваются, а решение всегда можно поправить вручную.

## 2. Клинические определения и инварианты

1. **ED (конец диастолы)** — кадр, ближайший к началу QRS / R-пику (по consensus Task Force для STE) либо
   локальный максимум площади полости ЛЖ / максимум «тёмной» фракции при отсутствии ЭКГ.
2. **ES (конец систолы)** — кадр закрытия аортального клапана (AVC); практически — минимум площади ЛЖ /
   минимум глобальной продольной деформации (наиболее отрицательное значение) в окне систолы.
3. **Систола** = `[ED, ES)`, **диастола** = `[ES, ED_следующего)`. Диастола включает и диастазис;
   поэтому «систола ≈ 1/3 цикла» — только априорная оценка, а не правило.
4. Электрическая систола (QRS→T) ≠ механическая. ЭКГ даёт **только ED (и RR)**; ES без изображения —
   всегда оценка, что обязано быть видно в UI (`source`, штриховка, подсказка).
5. Длительность систолы слабо зависит от ЧСС (≈ 400 мс при 60 уд/мин, ≈ 270–300 мс при 150 уд/мин),
   диастола укорачивается сильнее. Поэтому априорный ES ищется в окне
   `[ED + 0,20·RR, ED + 0,50·RR]`, дополнительно ограниченном 180–400 мс.
6. При ФП / эктопии RR индивидуален для каждой пары R-пиков; усреднять RR и «причёсывать» циклы нельзя.
7. Усечённый первый/последний цикл помечается `partial=True` и не получает уверенной заливки.
8. Если уверенность ниже порога — возвращается `unknown` на всех кадрах, а UI показывает нейтральную
   полосу и явное сообщение, а не «красивую, но выдуманную» разметку.
9. Точность по времени ограничена одним кадром: при 30 fps это ±33 мс. UI должен показывать номер кадра,
   а миллисекунды — только когда `frame_time_ms` известен из DICOM.

## 3. Архитектура

```
DICOM/MP4 + WaveformSequence + frame_time_ms + (Simpson area / STE strain)
                         │
        CinePhaseWorker (QThreadPool, чтение файла вне UI-потока)
                         │  frames(N,64,64) + R-peaks + area/strain
                         ▼
   domain/services/cine_phase_timeline.py  ── чистые функции, без Qt
     ├─ сигналы: area / strain / dark_pool / intensity / motion / burned_ecg
     ├─ ECG-путь: R-пики → ED, ES из изображения, выравнивание сдвига
     ├─ безЭКГ-путь: период → экстремумы → полярность → циклы
     └─ PhaseTimeline(labels[], cycles[], segments[], markers[], source, confidence, warnings)
                         │
        ┌────────────────┴─────────────────┐
        ▼                                  ▼
MainWindow → ViewerWidget            StrainWindow → CinePanel
        └────── presentation/cine_phase_strip.py ────┘
             полосы фаз + чипы ED/ES + playhead + tooltip + drag
```

**Разделение ответственности:**

| Слой | Ответственность |
|---|---|
| `CinePhaseTimeline` (domain) | Разметка, источники, уверенность, ручная правка, сериализация. Ни Qt, ни файлового ввода |
| `CinePhaseWorker` (application) | Прочитать кадры (DICOM/MP4) и ЭКГ в фоне, пространственно уменьшить кадры до 64×64, вызвать домен, отдать результат с `(instance_uid, generation)` |
| `CinePhaseStrip` (presentation) | Отрисовка, hit-test, подсказки, клик-переход, перетаскивание маркеров. Домен не изменяет |
| `ViewerWidget` / `CinePanel` | Владеют полосой, связывают её со слайдером, хранят таймлайн для текущего файла |

Полоса — **один и тот же виджет** в обоих окнах. В `CinePanel` он стоит над слайдером (как сейчас), в
основном просмотрщике — в контейнере `QVBoxLayout(strip, slider)`, что гарантирует одинаковую ширину
дорожки без ручного пересчёта координат. Для выравнивания с бегунком `QSlider` сохраняется поправка
`_SLIDER_INSET = 9` (половина ручки): кадр 0 и кадр N−1 рисуются не у самых краёв, а под центрами ручки.

## 4. Алгоритм

### 4.1 Лестница источников (приоритет сверху вниз)

| № | Источник | Что даёт | Вес | Комментарий |
|---|---|---|---|---|
| 0 | Ручная правка пользователя | ED/ES конкретного цикла | 1.00 | Всегда побеждает, инвалидирует производные расчёты |
| 1 | DICOM `WaveformSequence` (Lead II), R-пики | ED каждого цикла, RR | 1.00 | ES всё равно уточняется по изображению |
| 2 | Сохранённая кривая Simpson / контуры ЛЖ | площадь → ED/ES | 0.95 | Лучший безЭКГ-сигнал, если есть |
| 3 | Кривая глобального продольного strain (STE) | ES = минимум | 0.90 | Уже есть в `StrainResult.longitudinal` |
| 4 | «Тёмная» фракция полости в центральном ROI (`dark_pool`) | площадь-подобный сигнал | 0.70 | Порог Оцу на усреднённой картинке; ED = max |
| 5 | Средняя яркость центрального ROI (`intensity`) | обратный площади сигнал | 0.60 | ED = min; чувствителен к gain/TGC |
| 6 | Вшитая в видео ЭКГ (зелёная кривая в нижней зоне) | R-пики | 0.80 | Для экспортированных AVI/MP4; эвристика, низкая уверенность |
| 7 | Энергия межкадрового движения / optical flow | только период RR | 0.40 | Подстраховка периода, не полярность |
| 8 | Спектральная огибающая (допплер) | пики = систолы | 0.85 | Уже реализовано отдельно в `cardiac_cycle_service.detect_cycles_from_envelope`; в `PhaseTimeline` P0 не подключено (у допплера другая ось времени) — **P2** |

Источник решения записывается в `PhaseTimeline.source` и в каждый `PhaseCycle`/`PhaseSegment`:
`ecg+area`, `ecg+prior`, `area`, `strain`, `dark_pool`, `intensity`, `burned_ecg`, `envelope`, `manual`.

Для внешних периодических индексов с неизвестной полярностью (вендорный индекс, траектория
движения) в API есть явный вход `unlabelled_curve` (вес 0,70): какие экстремумы считать ED/ES,
решается по приорам длительности систолы и кривизны в вершинах либо одним ручным якорем
`manual_anchor=(frame, "ed"|"es")`. Без якоря такое решение помечается пониженной уверенностью.

### 4.2 Путь с ЭКГ

1. **Парсинг.** `read_ecg_waveform()` → `EcgWaveform`; Lead II (или первый канал), `sampling_frequency`,
   перевод в мВ. `detect_r_peaks_from_waveform()` → `RPeakResult(times_ms, rr, confidence)`.
2. **Привязка к кадрам (критично).** Время R-пика в системе координат ЭКГ переводится в кадры как
   `f = (t_R − Δ) / frame_time_ms`. `Δ` — сдвиг между началом записи ЭКГ и кадром 0:
   - если доступен DICOM `TriggerTime (0018,1060)` / `TriggerSamplePosition (0018,1062)` /
     `FrameTimeVector (0018,1065)` — берём из тегов (**P1**, парсер сегодня их не читает);
   - иначе — **автоматическое выравнивание**: перебор `Δ` в пределах ±RR/2 с шагом `frame_time_ms/2`,
     максимизирующий среднее z-значение площади (или `−strain`, или `dark_pool`) в кадрах R-пиков.
     ED физиологически совпадает с максимумом площади, поэтому корреляция «R-пики ↔ максимумы площади»
     надёжно находит сдвиг. Это закрывает гипотезу C5 из STE_IMPROVEMENT_PLAN §2.5.
   - если опорного сигнала нет — `Δ` из аргумента (по умолчанию 0) и предупреждение
     `ecg_not_aligned`: маркеры рисуются штриховкой.
3. **ED** = `round(f_R)`; границы `0 ≤ ED < N`. R-пики вне ролика отбрасываются.
4. **RR** = разность соседних R-пиков (мс), индивидуально для цикла. При `CV(RR) > 0,20` — предупреждение
   `irregular_rhythm`, понижение уверенности, запрет фазового усреднения.
5. **ES** = `argmin(area_like)` в окне `[ED + 0,20·RR, ED + 0,50·RR]`, суженном до 180–400 мс.
   Если опорного сигнала нет — `ED + systole_ms(RR)/frame_time_ms` и источник `ecg+prior`
   (честно: это оценка, а не AVC).
6. **Цикл** = `[ED_i, ED_{i+1})`; последний — до конца ролика с `partial=True`.

### 4.3 Путь без ЭКГ (основной)

1. **Сбор сигналов** (`N` = число кадров, все сигналы длиной `N`):
   - переданные `area_curve` / `strain_curve` (могут содержать `NaN` вне окна анализа);
   - иначе из кадров: `dark_pool_signal()`, `intensity_signal()`, `motion_signal()`,
     `burned_ecg_signal()` (см. 4.4).
2. **Предобработка каждого кандидата:** линейная интерполяция `NaN` → вычитание линейного тренда →
   сглаживание Савицки–Голея (окно 5–9 кадров, порядок 2) → z-нормализация.
   Фильтрация с нулевой фазой (zero-phase) — проход вперёд и назад, без «колец» на краях (краевые циклы всё равно помечаются `partial`).
3. **Период.** Автокорреляция (FFT) с поиском лагов в диапазоне 35–200 уд/мин; возвращаются
   `period_frames` и `periodicity` (высота пика ACF 0…1). Кандидаты с `periodicity < 0,35`
   отбрасываются: белый шум на 60 кадрах регулярно даёт 0,25–0,33. Для коротких клипов
   (1–1,5 цикла) есть консервативный фолбэк по расстоянию «максимум → минимум → максимум».
   Двигательный сигнал и `dark_pool` голосуют за период вместе; у `motion` период часто вдвое
   меньше (два всплеска за удар) — он удваивается по консенсусу остальных сигналов.
4. **Экстремумы.** `scipy.signal.find_peaks` с `distance ≥ 0,6·period` и
   `prominence ≥ max(0,15·(p95−p05), 0,15·σ)` для максимумов (ED-кандидаты) и минимумов
   (ES-кандидаты). Отдельная функция `_with_edge_extrema` возвращает экстремумы у краёв ролика:
   `find_peaks` не видит максимум в кадре 0, а кино очень часто начинается ровно с ED.
   Для оценки «остроты» используется вторая разность в окне ±2 кадра.
5. **Полярность (главная ловушка безЭКГ-пути).** Для сигнала с известной физикой (площадь, strain,
   `dark_pool`, `intensity`) полярность фиксирована. Для «сырого» кандидата без семантики перебираются
   две гипотезы — «максимумы = ED» и «минимумы = ED» — и выбирается по сумме:
   - **длительностный приор:** `|systole_fraction − expected(HR)|` (систола 0,25–0,50 цикла);
   - **приор кривизны:** ES — острый минимум (короткая площадка), ED — пологий максимум (диастазис);
     сравнивается средняя вторая разность в окне ±2 кадра;
   - **приор движения:** сразу после ED начинается сокращение — знак производной опорного сигнала;
   - **ручной якорь:** один клик пользователя («здесь ES») снимает неоднозначность на весь ролик.
6. **Сборка циклов.** Для каждой пары соседних ED ищется первый ES внутри интервала. Если ES не найден —
   оценка по приору с пониженной уверенностью. Проверки: `ED < ES < ED_next`,
   `ES−ED ≥ 3 кадра`, `ED_next−ED ≥ 0,6·period`; нарушители удаляются, а не «подтягиваются».
7. **Покадровая разметка.** `labels[f] = systole` для `ED ≤ f < ES`, `diastole` для `ES ≤ f < ED_next`.
   Кадры до первого ED и после последнего ES остаются `unknown` (усечённые циклы).
8. **Уверенность** (0…1, честно и монотонно):
   ```
   q_signal      = 0,5·periodicity + 0,3·prominence_ratio + 0,2·regularity
   q_source      = вес источника из §4.1
   q_agreement   = доля совпавших ED/ES (±2 кадра) в остальных сигналах;
                   при одном-единственном сигнале = 0,75 (нет противоречий, но нет и подтверждения)
   confidence    = clamp(q_source · (0,75·q_signal + 0,25·q_agreement))
   ```
   При `confidence < min_confidence (0,35)` все метки заменяются на `unknown`, циклы сохраняются в
   результате для отладки, но UI рисует их штриховкой без заливки.
9. **Отказ.** Нет кадров / нет периода / нет экстремумов / плоский сигнал →
   `PhaseTimeline(source="unavailable", labels=("unknown",)*N, confidence=0, warnings=(...))`.
   Никаких «третей цикла» по умолчанию.

### 4.4 Извлечение сигналов из кадров

Функции в `cine_phase_timeline.py`, работают с `(N,H,W[,C])` `uint8`/`float`, пространственно
прореженными воркером до 64×64:

- `dark_pool_signal(frames)` — центральный ROI (по 18 % срезано с каждой стороны, чтобы убрать
  подписи, шкалу глубины и логотип вендора); глобальный порог Оцу по медианному кадру; доля тёмных
  пикселей в ROI на каждом кадре. ED = максимум. Отказ, если доля тёмного < 3 % или > 80 %.
- `intensity_signal(frames)` — средняя яркость того же ROI; инвертируется в площаде-подобный сигнал;
  используется только как второй голос (усиление/глубина меняют амплитуду, но не фазу).
- `motion_signal(frames)` — среднее `|I_t − I_{t−1}|` в ROI; пики в начале систолы и ранней диастоле;
  используется для периода и как проверка, что клип действительно динамический.
- `burned_ecg_signal(frames)` — в нижней четверти кадра ищутся пиксели с доминирующим зелёным
  каналом (`G > 1,2·R`, `G > 1,2·B`, `G > 60`); для каждого столбца берётся медианная `y` →
  трасса; острые пики (`find_peaks(−y, prominence)`) дают R-пики; `x → t` линейно по длительности
  ролика. Если пиков < 2 или ЧСС вне 35–200 — сигнал игнорируется. Известные ограничения: жёлтая/
  белая ЭКГ, ЭКГ внутри сектора, нелинейная развёртка, обрезанный трек — **P1**, см. §9.

### 4.5 Слияние и ручная правка

- Несколько сигналов дают несколько наборов циклов. Сначала выбирается набор с максимальным
  `q_source·q_signal`; затем ED/ES уточняются медианой по согласованным кандидатам в окне ±2 кадра.
  Расхождение > 2 кадров понижает уверенность и добавляет предупреждение `signals_disagree`.
- `PhaseTimeline.with_manual_ed_es(cycle_index, ed, es)` пересобирает разметку, помечает цикл
  `source="manual"` и `confidence=1.0`. Полоса эмитит `marker_moved(cycle_index, kind, frame)` при
  перетаскивании; владелец (CinePanel / ViewerWidget) вызывает этот метод. Ручная правка не перетирает
  автоматический результат: хранится рядом, чтобы его можно было сбросить.
- `to_dict()/from_dict()` (с `schema_version`) готовы к сохранению в `MeasurementPersistence` (**P1**);
  ключ кэша — `(sop_instance_uid, N, frame_time_ms, schema_version, конфиг-хэш)`.

## 5. Маркеры на полосе воспроизведения

**Два слоя:**

1. **Заливка фаз** — непрерывные полупрозрачные сегменты: систола `state.err` (тёплый), диастола
   `state.info` (холодный), `unknown` — нейтральный `line.1`. Сегменты рисуются по `PhaseSegment`
   (начало/конец в кадрах), а не по пикселям: O(число циклов) на перерисовку.
2. **События** — чипы `ED`/`ES` со стрелкой-указателем на дорожку и линия текущего кадра.
   Отдельные тики R-пиков в P0 не рисуются: при выбранном определении ED они совпадают с чипом ED;
   при необходимости их можно добавить, храня `r_peak_frame` в `PhaseCycle` (P2).

**Честность источника:**

| Состояние | Визуал |
|---|---|
| ЭКГ + ES по изображению, confidence ≥ 0,7 | сплошная заливка, сплошные чипы |
| ЭКГ без выравнивания / ES по приору | штриховка, подсказка «ES — оценка 0,35·RR» |
| Только изображение, confidence 0,35–0,7 | штриховка + «изображение, требуется проверка» |
| confidence < 0,35 / отказались | нейтральная полоса, серые чипы-плейсхолдеры, подсказка «фаза не определена» |
| Ручная правка | рамка чипа + метка «вручную» |

**Подсказка (hover)** для каждого чипа: `ED · кадр 12 · 396 мс ± 33 мс · источник: ЭКГ + площадь ЛЖ ·
уверенность 0,86 · цикл 2/3`. Общая подсказка полосы — источник, ЧСС, число циклов, список
предупреждений. Цвет **не единственный** признак: есть буквы, штриховка и текст (требование
`ui_tokens.md`/a11y).

**Взаимодействие:** клик по чипу или полосе → переход на кадр; перетаскивание чипа `ED`/`ES` →
ручная правка цикла; двойной клик по чипу → сброс правки; клавиатура не перехватывается (горячие
клавиши просмотрщика остаются прежними).

**Производительность:** домен считается один раз на файл в фоновом потоке; полоса хранит готовые
`segments/markers` и пересчитывает только пиксельные координаты при ресайзе. Перерисовка не читает
кадры и не вызывает numpy.

## 7. Модель данных (публичный API домена)

```python
PHASE_SYSTOLE, PHASE_DIASTOLE, PHASE_UNKNOWN = "systole", "diastole", "unknown"

@dataclass(frozen=True)
class PhaseCycle:
    ed_frame: int; es_frame: int; end_frame: int      # end_frame — exclusive
    confidence: float; source: str; partial: bool = False

@dataclass(frozen=True)
class PhaseTimeline:
    n_frames: int
    frame_time_ms: float | None
    labels: tuple[str, ...]               # по кадру
    cycles: tuple[PhaseCycle, ...]
    source: str
    confidence: float
    warnings: tuple[str, ...] = ()
    schema_version: str = "1.0"

    def segments(self) -> tuple[PhaseSegment, ...]: ...   # для заливки
    def markers(self) -> tuple[PhaseMarker, ...]: ...     # ED/ES/R тики
    def phase_at(self, frame: int) -> str: ...
    def with_manual_ed_es(self, cycle_index: int, ed: int, es: int) -> PhaseTimeline: ...
    def to_dict(self) -> dict: ...
    @classmethod
    def from_dict(cls, data: dict) -> PhaseTimeline: ...

def build_phase_timeline(
    *, n_frames: int, frame_time_ms: float | None = None,
    frames: np.ndarray | None = None,
    area_curve: np.ndarray | None = None,       # ED = max
    strain_curve: np.ndarray | None = None,     # ES = min
    ecg_r_peaks_ms: np.ndarray | None = None,
    ecg_confidence: float = 1.0,
    ecg_offset_ms: float = 0.0,                 # TriggerTime, если известен
    manual_anchor: tuple[int, str] | None = None,
    min_confidence: float = 0.35,
) -> PhaseTimeline: ...
```

**P0 (сделано):** доменный сервис, воркер, полоса в двух окнах, тесты на синтетике, честный `unknown`.

**Что именно лежит в репозитории (P0):**

| `presentation/cine_phase_geometry.py` | чистое преобразование кадр ↔ пиксель (тестируется без Qt) |

| `tests/unit/test_cine_phase_{timeline,geometry,worker,strip}.py` | 37 тестов: 28 чистых (алгоритм/геометрия/воркер) + 9 GUI (`QT_QPA_PLATFORM=offscreen`) |

Ограничение P0, которое важно помнить: `manual_anchor` и `to_dict()` есть в API, но в UI ещё не
подключены к постоянному хранению (`MeasurementPersistence`) — правка живёт до смены файла.

**P1 (валидация и точность):**
1. Чтение `TriggerTime`, `TriggerSamplePosition`, `FrameTimeVector`, приватных вендорных тегов;
   сверка авто-выравнивания с эталонными кадрами ED (STE_IMPROVEMENT_PLAN §2.5, фаза 0).
2. Детектор AVC по длинной оси/допплеру — замена «ES = минимум площади» для клинически значимых
   измерений; сейчас ES — суррогат.
3. Сегментация ЛЖ (ONNX, уже есть в проекте) как основной `area_curve` вместо эвристики `dark_pool`.
4. Сохранение `PhaseTimeline` в `MeasurementPersistence`, инвалидация по конфиг-хэшу, undo/redo правок.
5. Вшитая ЭКГ: детектор цвета/формы трассы, калибровка развёртки по тикам, устойчивость к обрезке.
6. Валидация на размеченной выборке; публикация метрик в `docs/reviews/`.

**P2 (распространение):** маркеры в Multiview-панелях через общий `PhaseTimeline` (сейчас там ручные
`EventMarker`), фазовая синхронизация двух клипов, экспорт разметки в отчёт/JSON, подсветка фазы в
Presented-окне.

**Открытые вопросы для владельца продукта:**
- Считать ли ED кадром R-пика или кадром перед QRS (для STE consensus — R-пик, для Simpson часто
  «последний кадр перед закрытием митрального клапана»)? Сейчас выбран R-пик, но нужен явный флаг
  протокола.
- Показывать ли фазу на spectral Doppler и M-mode (там «систола» имеет другую временную ось)?
- Нужна ли цветовая кодировка фаз в отчёте/PDF или только в просмотрщике?

**Риски:** ошибка выравнивания ЭКГ на 1–2 кадра меняет GLS/EDV; полярность безЭКГ-сигнала может
инвертироваться при нестандартном усилении; «зелёная ЭКГ» легко принять за артефакт; при ЧСС > 150
длительностный приор слабеет. Все они смягчаются явным `source`, штриховкой, порогом уверенности и
обязательной ручной проверкой перед использованием разметки в измерениях.
