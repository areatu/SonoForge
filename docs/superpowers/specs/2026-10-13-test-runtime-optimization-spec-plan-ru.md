# Спека-план: оптимизация времени тестового прогона (TV)

- **Дата:** 2026-10-13
- **Статус:** draft, не реализовано
- **Область:** `.github/workflows/ci.yml`, `tests/unit/conftest.py`, `pyproject.toml` (pytest-конфигурация), вспомогательные CI-скрипты.
- **Связанные документы:** `docs/superpowers/specs/2026-10-13-quality-safety-hardening-spec-plan-ru.md` (QH), `docs/bench/2026-09-06-cine-720p-playback-audit.md` (§4.3).
- **Целевой результат:** сократить полный CI-прогон без уменьшения числа выполняемых тестов, без ослабления ассертов, без снятия обязательных gate и без потери диагностики падений.

---

## 1. Цели и не-цели

### 1.1. Цели

1. Убрать Linux `test` job как единственный критический путь (сейчас ~85 из ~86 минут прогона).
2. Параллелизовать набор так, чтобы быстрая логика не ждала GUI, а GUI не ждал логику.
3. Устранить суперлинейный рост времени из-за накопления виджетов в сессии.
4. Снизить фиксированную стоимость *на каждый* тест (autouse-фикстуры), не ослабляя изоляцию.
5. Сохранить 100% текущих тестов, маркеров, gate'ов, покрытия и диагностики.

### 1.2. Не входит

- Уменьшение числа тестов, добавление `skip`/`xfail`, разделение ассертов или «облегчение» проверок ради времени.
- Замена pytest на другой раннер; переписывание тестов на другой фреймворк.
- Изменение клинической логики, формул, моделей или production-кода вне правок, требуемых для изоляции тестов.
- Снятие GUI-тестов с PR, отключение coverage или Coveralls.
- Переписывание `tests/unit/conftest.py` «с нуля»; изменения только адресные.

### 1.3. Контракты, которые нельзя нарушать

| ID | Инвариант |
|---|---|
| **TV-S-01 Same set** | Число собранных тестов и распределение по маркерам до/после идентичны (`--collect-only -q`). Ускорение только за счёт исполнения, не за счёт выбрасывания тестов |
| **TV-S-02 No weakened checks** | Ни один ассерт/фикстура-инвариант не ослаблен; новые `skip`/`xfail`/`pytest.mark` не добавляются для скорости |
| **TV-S-03 Gate parity** | Обязательные checks остаются обязательными; ни один job/gate не удаляется; обязательность у параллельных job'ов такая же, как была у одного `test` |
| **TV-S-04 Coverage non-regression** | Покрытие не ниже текущего; покрытие по-прежнему измеряется на Linux и публикуется |
| **TV-S-05 Diagnostics parity** | Падение/зависание/`SIGSEGV` по-прежнему называет упавший node id через checks API, в том числе под parallel-исполнением |
| **TV-S-06 Isolation** | Изоляция QSettings, кэша, store и i18n на тест сохраняется; `QT_QPA_PLATFORM=offscreen` и xvfb не ослабляются |
| **TV-S-07 Determinism** | Порядок исполнения не влияет на результат; от parallel/label-раскладки нет новых падений |
| **TV-S-08 Reproducible locally** | Любой новый режим прогона воспроизводится одной документированной командой локально |

Состав набора:

- `tests/unit/` — **400 файлов, 6704 теста**; всего в `tests/` — 459 файлов / ~7164 теста.
- **158 файлов** помечены `pytestmark = pytest.mark.gui`.

- `timeout = 60`, `timeout_method = "thread"`.

Тренд последних прогонов CI: 53 → 72 → 77 → **86 мин**. Время растёт вместе с числом тестов.

## 3. Диагноз

1. **Один критический путь на одном ядре.** Linux последовательно прогоняет 6704 теста; нет `-n`, нет шардирования.
2. **GUI-тесты идут вместе с логикой.** mac/win в ~10 раз быстрее именно потому, что пропускают GUI; Linux — единственный, кто их выполняет.
3. **Суперлинейный рост из-за утечки виджетов.** Задокументировано в `tests/unit/conftest.py:136-147`: к концу сессии живут ~90k QWidget, Python GC их не видит (C++/signal-цикл). Смена stylesheet даёт реполиш ~62 c на CI. Поздние тесты платят за ранние — стоимость не линейна.
4. **Фиксированная стоимость на тест ×6704.** Autouse-фикстуры: `_drain_global_thread_pool` (`waitForDone(5000)` каждый тест), `_gc_per_test` (`gc.collect()` каждый тест), `_isolate_user_settings` (`QSettings.clear()/sync()` каждый тест), `_restore_canonical_app_sheet`, плюс session-scoped `_ru_locale` (`set_language("ru")` ×2 на тест) и три monkeypatch-изолятора.
5. **Coverage на всём наборе** (`--cov=src/echo_personal_tool`) добавляет инструментальную нагрузку ко всем 400 файлам.
6. **Логика, coverage и bench слиты в один Linux job.** Они могли бы идти параллельно.
7. **Мелочи:** `checkout` с `lfs: true` на тестовом job; отсутствует кэш pip; `-vv` полезен, но не бесплатен.

Каждый пункт по отдельности не даёт 10×; вместе они объясняют, почему Linux = 85 мин, а mac/win = 10 мин.

## 4. Целевая архитектура прогона

Разнести текущий монолитный `test` на независимые job'ы с сохранением обязательности всех checks:

| Job (предлагаемое имя) | ОС | Что запускает | Параллелизм |
|---|---|---|---|
| `lint` | ubuntu | без изменений | — |
| `test-logic` | ubuntu + macOS + Windows (матрица) | `tests/unit/ -m "not gui"` | `-n auto --dist loadfile` |
| `test-gui` | ubuntu (xvfb) | `tests/unit/ -m "gui"` | `-n N --dist loadfile`, отдельный процесс-воркер на QApplication |
| `test-bench` | ubuntu (xvfb) | `tests/bench/test_cine_playback_e2e_ci.py` | отдельный job |
| `coverage` | ubuntu | сбор/публикация coverage поверх Linux-прогона логики+GUI | `coverage combine` |
| `build` / `release` | ubuntu | без изменений (`needs` обновить) | — |

Почему так безопасно: **каждый xdist-воркер — отдельный процесс**, поэтому session-scoped `QApplication` создаётся в своём процессе и не шарится между тестами. `--dist loadfile` гарантирует, что все тесты одного файла идут в одном воркере, сохраняя модульный/session-скоуп и порядок внутри файла.

**Coverage под xdist:** либо запускать покрытие на выделенном job'е последовательно по «медленной» половине, либо `coverage run -p` по воркерам + `coverage combine`. Целевой вариант — второй, но он вводится только после TV-1 (детерминизм).

## 5. Работы по этапам

### TV-0 — Baseline, метрики, инвентарь

- Зафиксировать baseline: полный прогон, per-job, `pytest --durations=25`, `--collect-only -q` (сохранить число тестов и число по маркерам gui/not-gui).
- Добавить в job шаг `--durations` и публикацию таймингов как артефакта (retention короткий).
- Зафиксировать размер покрытия (Coveralls baseline).
- **Приёмка:** есть воспроизводимый снимок «до»: длительности, counts, coverage.

### TV-1 — Аудит детерминизма (предусловие параллелизма)

- Прогнать `tests/unit/` дважды в одном порядке (`-p no:cacheprovider --tb=line`), затем с `--dist loadfile -n 4` и сравнить результаты.
- Найти и обезвредить order-dependent тесты (общий глобальный state, незакрытые виджеты/таймеры/потоки).
- **Запрещено** «лечить» падения ослаблением ассертов; только правильная изоляция/teardown.
- **Приёмка:** результат не зависит от раскладки; список order-dependent тестов пуст или каждый задокументирован и изолирован.

### TV-2 — Разделение logic / gui и параллелизм логики

- Ввести job `test-logic` (`-m "not gui"`) на матрице ubuntu/mac/win с `-n auto --dist loadfile`.
- Добавить `pytest-xdist` в dev-зависимости (отдельный PR, с обоснованием).
- Включить кэш pip у `actions/setup-python` (`cache: pip`).
- **Приёмка:** `test-logic` завершается быстрее текущего `-m "not gui"`; counts сохранены.

### TV-3 — Параллелизм GUI и сохранение диагностики

- Ввести job `test-gui` (ubuntu, xvfb) с `-n N --dist loadfile`.
- **Диагностика:** `pytest_current_node` писать уникальный файл на воркер (`PYTEST_CURRENT_NODE_FILE` с id воркера); `annotate_pytest_failures.py` должен собирать последние node по всем воркерам и сохранять текущие аннотации (`::error title=pytest abort::`).
- Ограничить `pytest-timeout` корректно под xdist (thread-метод остаётся).
- **Приёмка:** искусственно вызванный `SIGSEGV`/hang в GUI-тесте по-прежнему называет виновника через checks API.

### TV-4 — Стоимость на тест и утечка виджетов

- **Утечка:** добавить session-teardown проверку `QApplication.allWidgets()`/top-level widgets; обязать тяжёлые виджеты (`MainWindow`, viewer, overlays) вызывать `close()+deleteLater()+processEvents()` в teardown либо регистрироваться в `qtbot.addWidget`. После стабилизации оценить, нужен ли `_restore_canonical_app_sheet` (он — workaround, а не необходимость).
- **Autouse-фикстуры:** удешевить без потери изоляции, например:
  - `_gc_per_test`: пакетный `gc.collect()` каждые N тестов/по границе модуля вместо каждого теста — только после подтверждения отсутствия segfault;
  - `_drain_global_thread_pool`: выполнять только для тестов, реально трогавших `QThreadPool` (маркер/флаг), иначе сохранять no-op-путь;
  - `QSettings`-изоляция: оставить, но избегать лишнего `sync()` там, где это безопасно.
- Каждое изменение фикстуры проверяется на GUI-наборе отдельным прогоном.
- **Приёмка:** `gc.collect()`/`waitForDone` перестают доминировать в `--durations`; утечка виджетов ограничена; улучшение времени измеримо.

### TV-5 — Coverage, шардирование, финальный SLO

- Перенести сбор coverage в отдельный job (`coverage combine` по воркерам) или на выделенную последовательную половину; Coveralls сохранить.
- При необходимости — шардирование `test-gui` на несколько параллельных job'ов (одинаковая обязательность).
- Убрать `lfs: true` с job'ов, которым LFS не нужен (LFS оставить только bench).
- Зафиксировать SLO и алерт на регресс.
- **Приёмка:** полный прогон укладывается в целевой бюджет (см. §6), coverage и diagnostics без регресса.

## 7. Риски и меры

| Риск | Последствие | Мера |
|---|---|---|
| xdist + Qt: сегфолты из-за общего C++ state | Ложные падения | Изоляция процессов на воркер, `--dist loadfile`, TV-1 сначала |
| xdist маскирует order-dependent баг | Зелёный CI при реальном дефекте | TV-1 обязателен до параллелизма; сравнение с `-n0` |
| Потеря диагностики под `-n` | Слепые падения | Уникальный node-файл на воркер + обновлённый аннотатор (TV-3) |
| Coverage под xdist даёт неполный результат | Ложное снижение покрытия | `coverage combine` / отдельный job (TV-5) |
| Память: N воркеров × PySide6 | OOM на runner | Ограничить `-n`, мониторить; логика — на матрице, GUI — на ubuntu |
| «Ускорение» через skip/xfail | Потеря качества | TV-S-02, ревью diff'а CI и conftest |
| Изменение gate'ов | Ослабление обязательности | TV-S-03, обновить `needs` и rulesets осознанно |

## 9. Definition of Done

- Число собранных тестов и маркеров не изменилось; новых `skip`/`xfail` нет.
- Все обязательные checks сохранены и обязательны; gates не удалены.
- Покрытие не ниже baseline и публикуется как раньше.
- Диагностика падений/зависаний называет node id под параллелью.
- Полный прогон укладывается в целевой бюджет; метрики публикуются.
- Каждый режим прогона воспроизводится одной локальной командой.
- Отчёт по каждому этапу: commit, evidence (прогон + длительности + counts + coverage), PASS/BLOCKED.
