## 4. Чек-лист ручной приёмки «внутри приложения»

Платформы: **W** = Windows 10/11 (нужен не-админ аккаунт), **M** = macOS Apple Silicon, **L** = Linux, **P** = Presenter/флешка.

### A. Установщик и пути (W)
1. Чистая установка под учётной записью без прав администратора: нет запроса UAC; приложение стартует из меню «Пуск» и с ярлыка на рабочем столе; переживает перезагрузку.
2. В `%USERPROFILE%` не появляются `.local`, `.sonoforge`, `SonoForge`; модели лежат в `%LOCALAPPDATA%\SonoForge\models`.
3. Установка поверх старой версии: модели не скачиваются заново (миграция `migrate_legacy_paths`).
4. Режим «для всех пользователей»: установка в Program Files под админом; данные всё равно per-user.
5. Удаление через «Установку и удаление программ»: приложение и ярлыки удаляются, `%LOCALAPPDATA%\SonoForge` остаётся; повторное удаление с чекбоксом «удалить данные» стирает и его (включая `measurements`); тихий uninstall данные не трогает.
6. Если приложение запущено во время установки/удаления — Restart Manager просит закрыть, без принудительного kill.
7. SmartScreen-предупреждение присутствует (подпись не настроена) — сверить текст README с фактическим.

### B. Кэш DICOM (W/L/M)
1. Settings → Прочее → «Кэш загруженных DICOM-исследований»: путь, размер, лимит 20.0 GiB, «Очистить кэш…», «Очищать кэш при обычном выходе» (скриншот: `../../images/persistence-ui/settings_other_ru_dark.png`).
2. Очистка при открытом исследовании с PACS: сессия открытого исследования сохраняется, остальные удаляются.
3. Снятая галочка «очищать при выходе»: кэш переживает перезапуск; снятие галочки обратно возвращает очистку.
4. Force-kill во время загрузки: частичная сессия видна на диске и удаляется либо очисткой, либо по возрасту >7 дней (проверку возраста допустимо сделать переводом даты сессии).
5. Два запущенных процесса с одним кэш-корнем: координации нет (известное ограничение) — убедиться, что предупреждение нигде не обещает обратного.

### C. Сохранение измерений, opt-in (W/L/M/P) — главный ручной сценарий
1. Включить «Сохранять измерения и рост/вес», перезапустить; сделать калипер/контур/Doppler/калибровку на нескольких клипах; дождаться статуса «Измерения сохранены» (не «ещё не сохранены»).
2. Перезапустить приложение, открыть ту же папку: «Измерения и рост/вес восстановлены», оверлеи на своих кадрах, калибровки не перемешаны между клипами.
3. PACS: скачать исследование, сохранить, очистить кэш, скачать заново — измерения вернулись; без повторного скачивания изображений восстановления нет.
4. Удалить последнее измерение (калипер/planimeter/Doppler) и перезапустить — не «воскресает»; «Сбросить измерения и калибровку» стирает запись, рост/вес остаются.
5. Kill -9 сразу после подтверждённого сохранения: новый процесс читает последнюю подтверждённую ревизию; kill во время записи: целая прежняя или новая версия, без частичного JSON.
6. Второй экземпляр приложения: «Хранилище занято другим экземпляром; изменения не сохраняются», чтение и export RAM доступны.
7. Экспорт/импорт `.sonoforge-measurements.json` на второй машине: предпросмотра категорий пока нет (известное ограничение §16), замена целиком после подтверждения; отмена импорта ничего не меняет.
8. Ошибки диска: read-only каталог/ENOSPC — статус ошибки, RAM жива, ложного «Сохранено» нет; смена исследования/закрытие отменяются до решения («Повторить», «Экспорт», «Продолжить без сохранения…»).
9. Менеджер (`../../images/persistence-ui/measurement_storage_manager.png`): список записей, «Удалить выбранную запись…», «Удалить все…», «Взять рост/вес из DICOM…»; удалить открытую запись — измерения остаются в RAM, автосохранение для неё приостановлено.
10. Presenter: по умолчанию не пишет ничего; opt-in пишет только в портативный корень; read-only носитель не приводит к скрытой записи на хост.
11. Локализация статусов RU/EN; проверить плюрализацию (сейчас «1 записей» — дефект, см. §5).

### D. Рост/вес (контракт WP4.2)
Ручные значения переживают перезапуск; DICOM другого клипа не заменяет manual; «рост без веса» поддержан, BSA по неполной паре не считается; явно очищенное поле не возвращается из DICOM; «Взять из DICOM…» снимает переопределения; reset измерений демографию сохраняет; delete-record/delete-all удаляет её с диска; JSON round-trip хранит точность и provenance.

### E. Диалог загрузки с сервера (нужен живой Orthanc/PACS; офлайн — профиль сервера «Mock»)
1. Карточки: чекбокс с тремя состояниями, миниатюра, строка пациента `Фамилия Имя Отчество · пол · возраст · ID`, бейджи модальности/серий/инстансов/размера/`IsStable`/Accession.
2. Миниатюры: WADO-RS rendered; на серверах без рендеринга — Orthanc `/preview`; при пустом первом кадре — кадр из середины петли; тумблер «Миниатюры» выключает все превью-запросы и запоминается.
3. Панель серий: чекбоксы, «Все серии/Ни одной», счётчик; выбор исследования целиком одним кликом, в т.ч. пока серии ещё догружаются; двойной клик = скачать и открыть; `Space`, `Ctrl+A`, `Ctrl+F`, `F5`, `Esc`.
4. Полоса «История пациента»: чипы прошлых исследований, клик отмечает к загрузке, «+N вне списка»; пустой PatientID/ошибка запроса просто скрывают полосу.
5. Фильтры: период 1/7/30/90 (локальная фильтрация), сортировка дата/фамилия/размер, поиск с дебаунсом; устаревший ответ поиска не подменяет список.
6. Строгий сервер (400 на расширенный QIDO): автоматический откат на минимальный набор полей, список всё равно грузится.
7. TLS: самоподписанный сертификат + CA в настройках — проверка остаётся включённой; отключение проверки без CA показывает предупреждение и пишет его в журнал.
8. DIMSE-профиль: те же карточки/превью деградируют до заглушек без ошибок.
9. Большой список (сотни исследований): прокрутка без подвисаний, превью только видимых строк; сводка «N иссл. · M сер. · ≈ X МБ» сходится с фактом загрузки.
10. Windows: длинные реальные UID не упираются в MAX_PATH (исправлено в кэше — проверить на реальном сервере с глубокими UID).
11. Несколько отмеченных исследований: сейчас открываются одним списком в одной галерее (вкладок ещё нет) — ожидать именно это поведение.

## 5. Дефекты/расхождения, найденные обзором (мелкие, для backlog)

1. **Плюрализация RU — закрыто 2026-10-08:** `persistence.stats`, `viewer.vessel_average_done`, `constructor.param.delete_selected_confirm` и `constructor.pathology.delete_confirm` переведены на `tr_plural` с формами `.one/.few/.many/.other` в обеих локалях. Попутно исправлен дефект вне списка: подтверждение удаления параметров в конструкторе обращалось к несуществующему ключу `constructor.param.delete_params_confirm`, и диалог показывал пользователю сам ключ; теперь это `tr_plural("constructor.param.delete_selected_confirm", …)`.
2. **Нелокализованные стандартные кнопки — уже в коде на момент среза:** все девять модулей с `QDialogButtonBox` вызывают `localize_dialog_button_box()` (`styled_dialogs.py`), которая ставит тексты из ключей `button.*` и обновляет их при смене языка; строка устарела в снимке 2026-10-05.
3. **Первое включение persistence:** спека §10.1 предполагала отдельное первое уведомление; сейчас это постоянный текст-подсказка в настройках (`persistence.privacy` + `persistence.restart`). Решить: достаточно ли подсказки (тогда поправить спеку) или добавить однократный диалог.
4. **Менеджер записей минимален:** список показывает только усечённый хеш-ключ и размер (известное ограничение §16): нет времени сохранения, числа измерений, статуса quarantine/unsupported.
5. **Релизная гигиена — частично закрыто:** CI-гард «тег == `__version__`» существует в lint-джобе `.github/workflows/ci.yml` (появился после среза 2026-10-05). Черновик `v0.3.2` без ассетов при `__version__ = 0.3.1` остаётся организационным вопросом: черновик ведёт release-drafter, версию поднимаем при нарезке релиза вместе с ассетами, вручную черновик не публикуем.
6. **Импорт без предпросмотра категорий** и без переотображения перемещённого не-DICOM по hash (ограничения §16) — в HELP описаны, но UX-ожидание из спеки не закрыто.
