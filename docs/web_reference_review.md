# Отчёт: ошибки реализации web-справочника (References)

Дата: 2026-09-04 · Ветка: `arena/01a06e05-sonoforge` · База: `c213b56`

Область: `src/echo_personal_tool/presentation/web_reference/` (вид `WebReferenceWidget`
на QWebEngineView) + мост `web_reference_bridge.py` + данные `ReferenceDataStore`
и `references_structured(_ru).yaml`.

Строки указаны по состоянию файлов на момент ревью. Проблемы пронумерованы
сквозно; внутри каждой категории отсортированы по важности.

## 1. Критические (функциональность)

### 1.1. `reload()` не обновляет web-интерфейс
- Файлы: `web_reference_widget.py:150–162`, `script.js:705–708`.
- `reload()` вызывает JS `init()`, но первая строка `init()` — страж
  `if (_pageInitialized) return;`. После первого показа флаг уже `true`, поэтому
  после закрытия Конструктора (`ase_reference_dialog.py:659`) справочник
  **не перерисовывается** — данные устаревают до полного `reload_page()` (F5).
- Исправление: `init()` должен пере-запрашивать данные при каждом вызове
  (одноразовой делать только установку обработчиков).

### 1.2. Ложное определение готовности моста (сломанный fallback)
- Файлы: `web_reference_widget.py:122–134`, `bridge.js:66–82`.
- Проверка `typeof bridge !== 'undefined'` не означает подключения к backend.
  Если QWebChannel не подключился (`bridge._backend == null`), Python считает
  вид «ok»: скрывает статус-лейбл, **не эмитит `web_failed`**, fallback на
  Qt-вид (`StructuredReferenceWidget`) не срабатывает.
- `script.js:9` `renderTopics(topics)` получает `{error:…}` вместо массива →
  `topics.forEach` кидает исключение → пустой экран без сообщения.
- `bridge.js` `tryInit()` либо зацикливается каждые 50 мс, либо вообще не
  стартует (нет ограничения попыток и обработки «QWebChannel не появился»).
- Исправление: проверять `bridge._backend` (факт подключения), ограничить
  ретраи в `bridge.js`.

### 1.3. `update_param("name")` портит данные
- Файл: `web_reference_bridge.py:325`.
- `re.sub(r"\s*\([^)]+\)\s*$", "", value)` отрезает суффикс «(LVEDD)» из имён
  вида «КДР ЛЖ (LVEDD)». Сохранение любой правки имени необратимо портит YAML.
- Это поведение противоречит самому `ReferenceDataStore.update_param`, который
  сохраняет имя как есть и лишь бережёт `full_name` (есть тесты
  `test_update_param_captures_full_name` и др.).
- Исправление: убрать regex, сохранять имя без изменений (юнит отдельной ячейкой).

### 1.4. Сохранение градаций путает мужской/женский диапазон; очистка невозможна
- Файлы: `web_reference_bridge.py:196–202, 366–395`, `script.js:575–577`,
  `reference_data_store.py:update_gradation`.
- Ячейка форматируется `"м / ж"` без подписей. Если диапазон есть только у одного
  пола (напр. «Тяжёлое»: `range_female: {low: 62}` → «≥62»), при сохранении
  `text.split(" / ")` кладёт «≥62» в **male**, female — пусто → значение пишется
  не в тот пол.
- `update_gradation` игнорирует `None` → очистить градацию из UI невозможно.
- Исправление: выводить значения с маркерами пола (`♂`/`♀`), парсить по маркеру;
  пустое/«—» трактовать как очистку (пустой `{}` → `NormRange(None,None)`).

### 1.5. Тема `system` не применяется к web
- Файл: `web_reference_widget.py:91–104`.
- Пишется `data-theme='system'`, но CSS определяет только `light`, `vscode_dark`,
  `vscode_light` и дефолтный `:root` (тёмный). При `system` + светлая система
  web-вид остаётся тёмным.
- Исправление: резолвить `system` → `light/dark` через `_is_system_dark()`.

## 2. Меню (topics, табы, поиск, edit)

### 2.1. Иконки/короткие подписи тем не работают
- Файл: `web_reference_bridge.py:16–32`.
- `_TOPIC_LABELS` заполнены пустыми строками. JS рендерит
  `<span class="topic-icon">` только при непустой подписи (`script.js:20–27`),
  поэтому иконок нет. Поле `icon` («LV01»…) мост отправляет, но JS игнорирует.
- Исправление: заполнить подписи (язык-зависимые), рендерить их как иконки-чипы.

### 2.2. Поиск: ведущий « / » в строке-родителе
- Файл: `web_reference_bridge.py:230–268`.
- Из-за пустого `_TOPIC_LABELS` `topic_label=""` → `parent = "" + " / " + name`.
- Исправление: `parent` строить от полного имени темы `topic.name`.

### 2.3. Английские строки захардкожены
- Файлы: `index.html`, `script.js`.
- «Age:», «Search...», «Edit», «Save», «Cancel», «Anatomy»,
  «Select a topic on the left», «No images», «No parameters…», «Nothing found»,
  заголовки «Parameter / Norm M / Norm F», типы поиска, title-подсказки модалки —
  не проходят через `tr()`. В русской локали интерфейс смешанный EN/RU.
- Исправление: новый слот `get_ui_strings()` + ключи локализации, применение в JS.

### 2.4. Age-фильтр — мёртвый контрол
- Файл: `script.js:652–660`, `index.html:21–25`.
- `setupAgeFilter()` пустой; поле «Age» выглядит рабочим, но ничего не делает.
- Исправление: убрать контрол из интерфейса (данных по возрастам нет).

### 2.5. `.resize-handle` без логики
- Файлы: `styles.css` (`.resize-handle`), `script.js`.
- `cursor: col-resize` + подсветка есть, обработчиков нет — «ручка» не двигает
  панель (обманчивый аффорданс).
- Исправление: реализовать перетаскивание ширины левой панели.

## 3. Таблицы

### 3.1. Неверный `colSpan` подстроки описания
- Файл: `script.js:287`.
- `descTd.colSpan = 3 + grad_names.length`, а колонок `1 + grad_names.length`
  (на 2 больше). Латентно (в данных нет `pathology_desc`), но формула ошибочна.
- Исправление: colSpan по фактическому числу колонок.

### 3.2. Дублированный одинаковый обработчик клика
- Файл: `script.js:265–278` — обе ветви `if/else` идентичны (мёртвый код).
- Исправление: один обработчик.

### 3.3. Смешанные параметры (с/без градаций) рендерятся неправильно
- Файлы: `web_reference_bridge.py:get_pathology`, `script.js:renderParams`.
- `hasGrads` вычисляется на всю патологию, а не на параметр. В данных реально
  есть смешанные патологии: `la_dimensions`, `carotid_diameter`,
  `vertebral_stenosis` (проверено по обоим YAML). Параметр без градаций теряет
  колонки Norm M/F и получает «—» во всех градациях; сетка разъезжается.
- Исправление: считать признак градаций **на строку** (`has_gradations` в данных
  строки), колонки норм и градаций формировать по объединению.

### 3.4. Градации объединяют «м / ж» в один текст без подписей
- См. 1.4 — то же, но со стороны таблицы (нет валидации ≥/≤ и разграничения M/F).
- Исправление: маркеры пола в ячейке.

### 3.5. Поиск не доводит до параметра
- Файл: `script.js:637–642`.
- Для `type === "parameter"` клик открывает тему+патологию, но не прокручивает
  и не подсвечивает конкретный параметр (`param_id` есть, но не используется).
- Исправление: после рендера подсвечивать строку по `data-param` и скроллить.

## 4. Визуализация (галерея/модалка)

### 4.1. Осиротевший CSS-блок
- Файл: `styles.css` (сразу после `@keyframes modalImageIn`).
- Объявления `object-fit…; border-radius…; box-shadow…; cursor: zoom-out;`
  выпали из селектора `#modalImage` — недействительный CSS; у модального
  изображения теряются радиус/тень/курсор.
- Исправление: вернуть объявления в `#modalImage`, удалить «висящий» блок.

### 4.2. Десинхронизация модалки и галереи
- Файл: `script.js` (обработчики `#modalPrev/#modalNext`, `openModal`).
- Навигация в лайтбоксе меняет только модальную картинку; главная `#mainImage`,
  счётчик и активный тамб **не обновляются**. После закрытия модалки галерея
  показывает прежний кадр.
- Исправление: синхронизировать `showCurrentImage()` с модальной навигацией.

### 4.3. Стрелки клавиатуры перехватываются при вводе текста
- Файл: `script.js:setupKeyboard`.
- `ArrowLeft/Right` обрабатываются глобально без проверки фокуса в `input`/
  `contenteditable` → при наборе текста одновременно листаются изображения.
- Исправление: игнорировать, если фокус в поле ввода/редактирования.

### 4.4. Хрупкое экранирование атрибутов
- Файл: `script.js:227+`.
- `data-param`/`data-grad` строятся через `escapeHtml()` внутри
  `data-…="…"` без экранирования кавычек. Для текущих id безопасно, но паттерн
  сломается на id с кавычками/пробелами.
- Исправление: отдельный `escapeAttr()` для атрибутов.

## 5. Дизайн / темы

### 5.1. Рассинхрон палитр web и Qt
- Файлы: `styles.css:1–24`, `dark_theme.py`, `web_reference_widget.py`.
- CSS задаёт свои цвета (`--accent: #2dd4bf`, `--border: #2a4a6b`), а палитра Qt
  — `accent #40e2de` и др. Web-вид не получает палитру из Python и дублирует
  значения, которые уже разошлись с основной темой.
- Исправление: инжектировать CSS-переменные из `get_theme_palette()`.

### 5.2. Тени отключены в тёмной теме
- Файл: `styles.css:20–21`.
- `--shadow-md: none; --shadow-lg: none;` — тултип, выпадающий поиск и
  модал-панель без тени; `vscode_dark` тени задаёт. Несогласованность.
- Исправление: задать реальные тени для тёмной темы.

### 5.3. Несогласованные радиусы
- Файл: `styles.css:22–24`.
- `--radius-sm: 2px`, но `--radius-md: 0`, `--radius-lg: 0` — часть элементов
  (search, edit-toggle, модал-тулбар) прямоугольные при закруглённых остальных.
- Исправление: согласованные значения радиусов.

## 6. Микроанимации

### 6.1. Stagger-анимация строк срабатывает при каждой перерисовке
- Файл: `styles.css` (`.param-table tbody tr`).
- Анимация проигрывается при любом `renderParams`, включая `refreshPathology()`
  после сохранения правок — таблица «мигает» при каждом обновлении.
- Исправление: анимировать только при смене темы/патологии, не при refresh.

### 6.2. `transition: all` на кнопках
- Файл: `styles.css` (`.topic-btn`, `.patho-btn`, `.edit-toggle`, `.save-btn`).
- Анимируются и layout-свойства (ширина/высота) → лишние перерасчёты.
- Исправление: явные свойства `background, color, border-color, transform`.

### 6.3. `scale(1.02)` на полноширинных topic-кнопках
- Файл: `styles.css` (`.topic-btn:hover`).
- Масштабирование перекрывает соседей и «блюрит» текст.
- Исправление: убрать transform, оставить смену фона/цвета.

### 6.4. `slideDown` с фиксированным `max-height: 100px`
- Файл: `styles.css` (`.desc-panel`, `@keyframes slideDown`).
- Описание длиннее 100px «обрезается» на время анимации, затем прыжок.
- Исправление: простая fade-анимация без max-height.

### 6.5. Гонка при быстром переключении
- Файл: `script.js:54–62, 143–150`.
- `fading-out` + вложенные `requestAnimationFrame` без отмены предыдущего
  перехода → при быстрой навигации возможны наложение таймеров и «зависшее»
  полупрозрачное состояние.
- Исправление: токен-последовательность (счётчик переходов).

### 6.6. Индикатор активного таба не реагирует на resize/перенос
- Файлы: `script.js:moveTabIndicator`, `styles.css` (`.pathology-bar::after`).
- Позиция считается один раз; при изменении ширины окна или переносе табов на
  вторую строку (`flex-wrap`) подчёркивание остаётся на старом месте.
- Исправление: пересчёт на `resize`, позиционирование по строке активного таба.
