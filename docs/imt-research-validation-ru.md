# Полуавтоматический КИМ ОСА: исследовательский протокол (#558)

## Статус и назначение

**Это вычислительный исследовательский прототип, не клинически валидированная
функция и не автоматическая диагностика атеросклероза.** В текущем срезе есть
Qt-free API поиска, расчёта, коррекции координат и подтверждения. Кнопка в
основном viewer, редактируемый GUI-overlay, автосохранение и включение в
клинический PDF **пока не реализованы**. Обычные IMT-R/L-линейки не меняются.
Не считать issue #558 закрытым по этому прототипу.

## Входные условия

Оператор выбирает продольный B-mode кадр, сторону R/L, сегмент дальней стенки
ОСА без plaque и область интереса. `ImtSource` сохраняет study/SOP UID,
поколение media/document, индекс и число кадров, сторону, сегмент, фазу,
ROI и полный `CalibrationContext`. При отсутствии ECG использовать явное
`operator_selected`, а не присваивать диастолу по предположению.

- Поддерживается **только CCA_far_wall**, без автоматического поиска сосуда,
  plaque, near wall, луковицы и ICA.
- Оба интерфейса должны выглядеть как положительные яркостные переходы вниз
  по изображению. Перевёрнутые, вертикальные и сложные разветвлённые стенки
  не поддерживаются. API не распознаёт анатомию, B-mode или plaque по pixels:
  `clip_mode`/segment и выбор подходящего участка — ответственность оператора
  и будущего GUI-адаптера.
- ROI имеет half-open координаты `(x0,y0,x1,y1)`, от 8×8 до **512×256 px**.
  Верхняя граница — вычислительный предел, не клинический стандарт длины.
- Требуется measured/derived физическая калибровка всего ROI и нужного кадра.
  Отсутствующая, assumed/unknown, isotropic-assumption или чужая frame/region
  калибровка отвергается. Пиксельные единицы не выдаются за миллиметры.
- Два y-hint задают lumen–intima и media–adventitia. Скаляр означает
  горизонтальную направляющую; `(y_left,y_right)` — наклонную. Это
  подсказки врача, не предсказание идентичности границ алгоритмом.

## Алгоритм и ограничения QC

1. Копируется только bounded ROI, исходный ndarray не изменяется.
2. Нормирование по 1/99 процентилям ROI, Gaussian sigma=0.8 px, положительный
   осевой градиент. Flat/non-finite, цветные и обрезанные кадры отвергаются.
3. Два отдельных seed corridors, разделённых средней направляющей.
   Первый порядок dynamic programming: штраф за квадрат шага и ограничение
   шага между соседними колонками. **Совместной оптимизации пары и штрафа
   второй производной здесь ещё нет.** Различимость двух линий и их порядок
   проверяются после поиска; неоднозначная/неподходящая пара отвергается.
4. Параболическое subpixel-уточнение локального пика градиента.
5. Обе линии переводятся в физические координаты: `x * column_spacing`,
   `y * row_spacing`. Lumen–intima пересэмплируется равномерно по физической
   длине дуги. По локальной нормали ищется единственное пересечение с
   media–adventitia; не используется вертикальная разность строк.
6. Нет пересечения, несколько пересечений, слабый градиент на одной из
   границ, выход за заданные search limits и недостаточная дискретизация
   исключают sample. `min_axial_samples` — техническая оценка через spacing,
   **не измерение PSF/акустического разрешения аппарата**.
7. Mean/max/population SD считаются по принятым эквидистантным normal samples.
   Coverage = accepted / attempted. При coverage ниже явно заданного минимума
   результат **не возвращается вообще**. Длина `sampled_length_mm` относится
   ко всему участку LI, а не только к принятой части. Индексы принятых samples
   и их расстояния доступны вместе с обеими границами.

`ImtPolicy` **не имеет значений по умолчанию** для min/max толщины, coverage и
edge contrast. Это параметры исследовательского search/QC-протокола, не
диагностические пороги. Их нужно выбрать и заморозить до независимой оценки.
Числа в synthetic tests относятся только к phantom, не к пациентам.
Сильная артефактная двойная линия может пройти технические QC gates:
coverage/gradient не доказывают правильность анатомических интерфейсов.

## Workflow и API

```python
from echo_personal_tool.application.imt import propose_imt, correct_imt
from echo_personal_tool.domain.models.imt import ImtSource, ImtPolicy

# frame: неизменённый grayscale B-mode ndarray; source: выбранный контекст.
# policy: зафиксированные исследователем параметры, не клинический default.
draft = propose_imt(frame, source, policy, lumen_y=(20., 22.), adventitia_y=(28., 30.))
# UI/инструмент разметки корректирует координаты обеих полилиний.
corrected = correct_imt(
    draft, current_source, frame,
    lumen_intima=edited_li, media_adventitia=edited_ma,
)
accepted = corrected.confirm(current_source)  # только по явному действию оператора
record = accepted.report_record(current_source)  # research_only=True
```

Каждая коррекция проходит те же geometry/image gates, получает следующую
revision и теряет подтверждение. Отказ не изменяет прежний immutable draft.
Подтверждение/коррекция/export другого source/generation/frame/calibration
запрещены. Клиент обязан получать **актуальный** source от владельца media
session, а не повторно передавать сохранённый source черновика.

`caliper_label`/`measurement_key` совпадают с существующими IMT-R/L и
`cca.imt_right`/`cca.imt_left`; это адресация, **не конвертация** распределённого
измерения в одиночный caliper. `report_record` — JSON-совместимая
исследовательская запись, не запись в клинический протокол и не формат
постоянного storage приложения. Она хранит настройки, обе линии, sample
indices/distances, QC, provenance, revision и подтверждение. UID и контекст
относятся к медицинским данным; JSON не шифруется. Не складывать реальные
UID, кадры или разметку в Git/публичные CI artifacts.

## Независимое сравнение: до любых заявлений о клинической точности

### 1. До сбора результатов

С врачом зафиксировать intended use, фазу и методику, участок ОСА,
исключения (plaque, тень, dropout, near-wall, не-продольный срез), аппаратные
предпосылки, критерии качества reference и допустимую ошибку/отказ.
Заранее определить primary endpoints, объём/стратификацию выборки и
статистический план. Разработчик не назначает клинический допуск в коде.

Разделить tuning и held-out cohort **по пациентам**, при необходимости по
центрам/аппаратам. Все кадры одного пациента остаются в одной части.
Заморозить commit/method version, параметры policy и preprocess до оценки.
Сохранять отказы в знаменателе; не выбирать лучшие успешные кадры постфактум.

### 2. Данные и reference

Разные производители, пресеты, глубины, gain, spacing/анизотропия, разрешения,
стороны и фазы. Отдельно набрать случаи с artifact/низким качеством, plaque,
неподходящим mode/scale. Иметь лицензию, согласованный режим de-identification
и утверждённое место хранения; данные вне репозитория.

Не менее двух независимых квалифицированных операторов размечают оба
интерфейса и пригодность участка, не видя результата алгоритма. Reference и
разногласия adjudicate по заранее выбранной процедуре. Сравнивать одинаковые
ROI/фазы/масштаб; отдельно исследовать вариабельность выбора ROI/кадра.

### 3. Регистрируемые поля и endpoints

Pseudonymous patient/case ID, vendor/model/preset, deidentified source/frame,
side/segment/phase, calibration provenance/revision/spacing, ROI, policy,
method commit, draft boundaries/QC, исправленные границы, время коррекции,
reference boundaries и причины отказов. Не переносить PatientName/PatientID
в аналитический CSV и публичный отчёт.

- До и после коррекции: ошибка mean/max IMT, SD ошибки, bias и Bland–Altman
  limits of agreement с доверительными интервалами по заранее выбранной
  методике. Учесть кластеризацию повторных кадров одного пациента.
- Boundary distance в физической геометрии, coverage, доля отказов и
  ложного принятия плохих ROI. Отчёт по vendor/scale/side/quality strata.
- Intra-/inter-operator повторяемость с повторным выбором ROI и frame,
  intra-/inter-session acquisition, где это предусмотрено протоколом.
- Время до подтверждённого результата, объём правок, rate ошибочного
  подтверждения. Отдельно посчитать случаи, когда draft выглядит гладким,
  но выбран не тот интерфейс.
- Показать все исключения/missing/reference failures и причины, а не только
  статистику успешных cases. Дополнительные метрики/подгруппы помечать exploratory.

### 4. Критерий решения

Сравнить заранее зафиксированные endpoints с допусками врача и назначением.
Synthetic phantom показывает правильность геометрии/отказов, но не заменяет
этот этап. Не выдавать автоматический диагноз, не смешивать plaque и diffuse
IMT, не расширять scope на другие сосуды по одному хорошему среднему bias.

## Воспроизводимая синтетическая проверка

```bash
.venv/bin/python scripts/run_pure_core_tests.py -q
# Только КИМ, в процессе с запрещёнными Qt imports:
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest \
  --pure-core -p pytest_timeout tests/unit/test_imt.py -v -o addopts=
```

Локально: **261 passed** в pure-core lane, включая **60 IMT-тестов**.
Проверены горизонтальные и наклонные анизотропные phantom, rasterised seeded
поиск, subpixel, population SD, shadow coverage/refusal, отсутствие второго
edge, плоский и non-finite кадр, несколько фиксированных шумовых fixtures,
frame/region scopes, malformed geometry, stale и revision/reset confirmation,
JSON export. Это не доказательство чувствительности/специфичности QC на пациентах.

Информационный одиночный прогон максимального ROI 512×256 на синтетическом
кадре: ~130 ms, 1023 normal samples, coverage=1, mean=0.4 mm, draft=True.
Это результат конкретного phantom/CPU, не SLA и не точность на реальных УЗИ.
Объём поиска и normal sampling ограничен независимо от размера исходного cine.

Ruff, targeted mypy для четырёх новых runtime-модулей, size/private-access и
untested-module ratchets проверяются без повышения baselines. Нативный GUI
и реальные vendor/PACS исследования этим срезом не проверялись.

## Следующий интеграционный срез

- Два реально редактируемых overlay, ROI и hints в viewer, только на B-mode
  измерительной панели (не read-only previous-study pane).
- Надёжный источник current generation/frame/calibration и invalidation при
  переключении, закрытии, retiming, смене display/preprocessing и калибровки.
- Структурированное хранение/reload вместе с документом и явным Draft/QC.
- Согласованное отображение mean/max/SD/coverage и provenance в UI/PDF/CSV;
  никакой молчаливой записи одной mean-линейки в старый протокол.
- Независимые реальные примеры и нативная GUI-приёмка.
