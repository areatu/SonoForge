# ML.4: локальная offline SSL-адаптация (экспериментально)

Реализация [#692](https://github.com/areatu/SonoForge/issues/692), поверх ML.3.
Это инструмент разработчика, **не клинически валидированная модель и не включение AI в UI**.
Нужен собственный локальный ML.3 checkpoint: полезные обученные веса не поставляются.
Внешние датасеты и скачивание весов не используются.

## Запуск

Установите проект с optional extras `training` (как для ML.3), затем:

```bash
python scripts/train_self_supervised_echo.py \
  --checkpoint /local/ml3/checkpoint.pt \
  --manifest /local/raw_manifest.json \
  --gold /local/gold/lv.json --gold /local/gold/la.json --gold /local/gold/rv.json \
  --output /local/ssl-run-001 --epochs 2 --input-size 224
```

`--input-size` должен совпадать с checkpoint. Выходная папка должна быть **новой**;
внутри checkout разрешён только путь, исключённый проектным `.gitignore`, например
`.cache/ssl-run-001`. Не используйте каталоги с пациентскими данными внутри Git.
Никаких checkpoint, DICOM или псевдометок коммитить не надо.

Альтернатива manifest — `--dicom-dir /local/raw`: рекурсивный поиск `*.dcm`,
детерминированный patient-group split с `--seed`. Для маленькой коллекции лучше
явный manifest: случайное распределение может не дать validation-клипов.

```json
{
  "schema_version": 1,
  "clips": [
    {"path": "raw/a.dcm", "patient_group_id": "local-group-a", "split": "train", "view": "A4C"},
    {"path": "raw/b.dcm", "patient_group_id": "local-group-b", "split": "val", "view": "A4C"},
    {"path": "raw/c.dcm", "patient_group_id": "local-group-c", "split": "test", "view": "RV_A4C"}
  ]
}
```

Пути относительны manifest. `view`, `patient_group_id`, `split` необязательны;
без `view` нужен уверенный прогноз учителя. Не подменяйте group для копий одного
пациента: SOPInstanceUID и PatientID/Issuer проверяются дополнительно в памяти.
При отсутствии PatientID и явного group все неизвестные пациенты — одна группа.
Gold использует существующий формат `gold_store`, с явными `split`,
`patient_group_id`, `instance_path`, `view`, `chamber`, `frames`.
Gold `train` используется для rehearsal; gold `val` — только для оценки.
Идентичности пациентов/экземпляров не могут пересекать train/val/test, включая gold.
Пиксели `test` не декодируются: заголовки читаются только для проверки утечек.

`--smoke` разрешает отсутствие val/gold для технической проверки запуска, но
**никогда не ослабляет критерий принятия**. Exit code 0 означает, что кандидат и
отчёт успешно записаны; принятие определяется только `ssl_report.json.accepted`.

## Обучение и fail-safe

- EMA Mean-Teacher: учитель видит очищенный сектор, ученик — шум/TGC только в
  тканевом канале. I/Y/X contract сохранён; интенсивности z-score не обрезаются
  ошибочно до [0,1]. BN/dropout заморожены. Есть якорь исходной модели против collapse.
- Узлы LV/LA/RV переносятся существующим NCC-трекером. Нужны NCC ≥0.65 **в обе
  стороны**, round-trip ≤1.5 px, полный неоднотонный patch внутри сектора.
  Дополнительно: уверенный вид, видимые опоры, корректная топология и границы.
  Плохое окно не создаёт псевдометки.
- Физиология включается только при confidence поля **и полного цикла ≥0.6**,
  конечной монотонной φ и известных ED/ES. Частичные циклы не экстраполируются.
  LV/RV: ED maximum, ES minimum, положительный FAC. LA: ED minimum, ES maximum,
  монотонный reservoir до ES. Гладкость второй разности и мягкие границы скорости/
  ускорения опор используют реальный FrameTime; без времени кинематика отключена.
  Низкая уверенность даёт **ровно ноль, включая градиенты** физиологии.
- Межцикловые `[ED, mid, ES]` сближаются в пространстве прототипов; нужен минимум
  два полных цикла. При недостатке циклов этот лосс тоже нулевой.
- Геометрия непрерывно интерполирует ED→ES→ED. Вне достоверных циклов используется
  отделённый от градиентов phase-head учителя, а не фиктивный ED.
- Опциональная NCC-регистрация на изображение среднего атласа **не реализована**;
  отчёт содержит `optional_atlas_image_ncc_loss: false`.

По умолчанию: epochs=2, max-clips=64, max-frames=48, lr=1e-5, EMA=.99, CPU/1 thread.
Декодирование одного cine ограничено оценкой 128 MiB, поддерживаются uint8/16
MONOCHROME2 и RGB/YBR, не инвертированный MONOCHROME1. Обработка клипов последовательная.
Уменьшение cine до 384 px и до 48 первых кадров — технические ограничения, а не
клиническая частота кадров или доказательство наличия полного цикла.

ECG-маска, подавление цветных/отдельно стоящих наложений и общий сектор вычисляются
**только в RAM**. Это эвристика, **не гарантированный pixel anonymizer**:
надпись внутри ткани может остаться. Поэтому не сохраняются даже очищенные
изображения, crops, SOP/PatientID, пути, группы или per-frame псевдометки.
Отчёт содержит только агрегаты; checkpoint — веса, числовой атлас с фиксированным
provenance и результаты gate (без optimizer/batches/исходных метаданных).

## Приёмка кандидата

1. На held-out raw `val` фиксируются узлы, confidence и NCC исходного учителя.
   Сравнивается ошибка межкадрового перемещения относительно переноса спекла,
   а не просто величина движения: настоящее сокращение не считается jitter.
   Нужно ≥3 валидных узла на ≥3 переходах, улучшение **и LA, и RV ≥1%**.
   Кандидат не может выиграть, скрыв сложные узлы своим новым confidence.
2. На том же held-out gold считаются IoU отдельно LV/LA/RV и средняя ошибка узлов
   в px. Ни одна метрика не должна ухудшиться (кроме 1e-9 численного шума),
   охват gold неизменен. Отсутствие камеры/доказательств — отказ.
3. Сохраняется лучшая прошедшая эпоха как `checkpoint.pt`. При отказе — только
   `candidate_rejected.pt`; стандартный ONNX exporter не принимает такой SSL
   checkpoint. Даже принятый кандидат остаётся `clinical_validated: false`,
   никогда автоматически не активируется.

## Проверено и чего это не доказывает

- Полный Qt-free regression manifest с training extras: **965 passed**;
  целевые SSL-тесты: **27 passed**.
- Отдельная чистая среда без установки приложения, Qt и ML extras, только с
  закреплёнными в `uv.lock` pytest, pytest-timeout, numpy, scipy, pydicom и
  opencv-python-headless: `python scripts/run_pure_core_tests.py -q` —
  **959 passed, 6 skipped** (только optional ML-тесты). Подпроцесс import/help
  явно получает путь к `src`: editable-установка не должна скрывать ошибку
  импорта, отсутствующую лишь в окружении разработчика.
- Positive-control smoke использует синтетические raw DICOM разных групп и
  модель с одним намеренно внесённым scanner-jitter параметром. Через реальный
  цикл `train()` (EMA, NCC, optimizer, validation и checkpoint) за 4 эпохи:

  | Метрика | До | После |
  |---|---:|---:|
  | LA flow-compensated jitter, px | 4.276 | 0.838 |
  | RV flow-compensated jitter, px | 4.346 | 0.913 |
  | Gold LV IoU | 0.7811 | 0.9408 |
  | Gold LA IoU | 0.7882 | 0.9435 |
  | Gold RV IoU | 0.7859 | 0.9465 |
  | Gold node error, px | 2.154 | 0.431 |

  Это тест работоспособности алгоритма на контролируемой помехе, **не качество
  обученного MobileNet и не клиническая валидация**. Фаза в этом тесте ненадёжна:
  работает именно независимый NCC-лосс; физиология проверяется отдельными циклами.
- Дополнительно выполнен настоящий CLI smoke с MobileNet, случайной инициализацией,
  синтетическими train/val DICOM и отдельным gold LV/LA/RV: прогнозы не дали
  уверенных warp-узлов, обучение пропущено, кандидат **отклонён**. Gold не изменился.
  Gate не ослаблялся ради положительного результата.
- **Приёмка улучшения настоящей ML.3-модели на реалистичных cine пока не доказана.**
  Для этого нужны полезный локально обученный checkpoint и независимый gold.
  Этот результат нельзя подменять positive-control тестом или объявлять #692
  клинически завершённой задачей.

Воспроизведение тестов (с установленными training extras):

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest --pure-core -p pytest_timeout \
  -o addopts= -q tests/unit/test_echo_ssl_objectives.py tests/unit/test_echo_ssl_data.py \
  tests/unit/test_echo_ssl_training.py tests/unit/test_echo_ssl_smoke.py tests/unit/test_echo_ssl_gates.py
```
