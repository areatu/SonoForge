# ML.1: связанный анатомический атлас

Реализация [#689](https://github.com/areatu/SonoForge/issues/689), этап §4.3
[единого spec-plan](superpowers/specs/2026-11-25-echo-ml-template-training-spec-plan-ru.md).

## Статус и границы

Это **аналитический, клинически не валидированный prior**, а не новая сегментационная
нейросеть, не нормативная база ASE/EACVI и не доказательство достижения IoU/Dice.
Клинические размеры в seed — параметры геометрического шаблона, не интервалы нормы.
Внешние публичные клинические датасеты, предобучение и сетевые загрузки не используются.
Локальных клинических аннотаций в этой реализации не было: тестирование синтетическое.

- `cardiac_atlas.py`: `CoupledShapeModel`, `ShapeFit`, `MeanAppearanceTemplate`,
  ridge-посадка, сериализация числового артефакта, адаптер трёх опорных точек.
- `cardiac_atlas_geometry.py`: обратимый репер, полярные координаты относительно
  вершины сектора, bilinear image warp и проверка пересечений.
- `cardiac_atlas_templates.py`: аналитические проекционные ED/ES seed-меши и моды.
- `cardiac_atlas_pca.py`: общее выравнивание локальной разметки и masked PCA.
- `scripts/fit_cardiac_atlas_pca.py`: явный офлайн-вход локальных JSON, без чтения DICOM.

Все вычислительные модули — pure-core (NumPy, для image warp — SciPy), без Qt,
torch, ONNX runtime и инфраструктурных импортов.

## Репер и топология

Координаты точек — `(x, y)`, `pixel_spacing_mm` — **DICOM `(row_mm, column_mm)`**.
`CanonicalFrame.from_landmarks(septal, lateral, apex)` сначала учитывает анизотропный
шаг пикселя, затем строит ортонормированные оси. Начало — середина клапанного
кольца, Y — к верхушке, положительное направление X выбирается латеральным якорем.
С калибровкой координаты в мм, без неё — в единицах хорды кольца
(`units="annulus_span"`), не в выдуманных миллиметрах. Вырожденные/нечисловые якоря
и неположительная калибровка отвергаются. `image_to_atlas` / `atlas_to_image`
проверены на анизотропных и повёрнутых данных с погрешностью меньше `1e-6`.
`warp_image` явно принимает метрические/безразмерные bounds и размер сетки;
полярные функции используют θ=0 вдоль положительной оси Y луча.

Один массив узлов хранит все структуры; `structures` содержит **индексы**, а не
копии координат. Это сохраняет идентичность общей хорды МК у LV/LA и общей части
МЖП у LV/RV даже после PCA-деформации. Контуры камер замыкаются по клапанной хорде;
`IVS` остаётся открытой интерфейсной линией.

| Вид | Структуры |
|---|---|
| `A4C`, `RV_A4C` | LV (32), LA (24), RV (24), RA (24), общая IVS; ТК смещён апикально на 5 мм в ED seed |
| `A2C` | LV (32), LA (24); IVS не видна и не добавляется |
| `A3C`, `PLAX` | LV, LA, LVOT, AO, IVS |
| `PSAX` | замкнутый LV и серповидный RV с общей септальной дугой |

`RV_A4C` имеет увеличенную свободную стенку ПЖ. Seed не содержит выпячиваний
устьев лёгочных вен/ушка ЛП или искусственных отверстий для трабекул ПЖ.
Это геометрическое приближение, а не полная модель клапанных створок/миокарда.
`SUBCOSTAL` и нестандартные виды на этапе ML.1 намеренно не подменяются A4C.

ED/ES интерполируются периодически: ES находится на φ=0.38, предсердия расширяются
противофазно сокращению желудочков. Четыре начальные моды: дилатация ЛП,
перегрузка ПЖ со сдвигом общей МЖП, ремоделирование ЛЖ, продольное сокращение.
Коэффициенты ограничены `±3√λ`; при самопересечении/перекрытии полостей деформация
возвращается вдоль той же модальной прямой к безопасному среднему. Неправильный
импортированный средний шаблон отвергается, а не молча исправляется.

## Посадка и dropout

```python
from echo_personal_tool.domain.services.cardiac_atlas import build_cardiac_atlas

atlas = build_cardiac_atlas("A4C")
mesh = atlas.synthesize([0.3, 0.2], phase="ES")
# observed: N×2 в том же каноническом репере; NaN или нулевой вес = нет наблюдения.
fit = atlas.fit(observed, weights=node_weights, phase="ES", ridge=1.0)
```

`fit` решает взвешенную ridge-задачу с prior по собственным дисперсиям. Невыявленная
свободная стенка ПЖ не заменяется нулевыми координатами: её продолжает описывать
гладкий связанный шаблон. `fit.coefficients` соответствует фактически ограниченной
форме, `rms` считается только по доступным наблюдениям. Без наблюдений возвращается
средняя форма. Временной гейт `<1 мс` не заявлен: отдельного CPU-бенчмарка не проводилось.

`build_mean_appearance(atlas)` создаёт сетки `128×128`: тёмные полости,
яркие границы/кольца, дисперсию и пониженную уверенность границы свободной стенки ПЖ.
Это аналитическая карта ожидаемой эхогенности, **не среднее реальных изображений**
и не физический УЗ-симулятор (это последующий ML.2).

## Обратная совместимость

Параметр `atlas_model=None` сохраняет старую геометрию:

- `mbs_lite_service.fit_contour_from_landmarks(..., atlas_model=atlas)` — явная
  замена seed с сохранением пользовательских septal/lateral/apex и числа узлов.
- `rv_shape_template.warp_rv_crescent_open_arc(..., atlas_model=atlas)` —
  опциональный гладкий атласный prior вместо прежних коэффициентов Безье.
- `la_segmentation_service.la_mask_to_contour(..., atlas_model=atlas)` —
  наблюдаемая граница маски остаётся главной; атлас используется только при
  неудаче извлечения границы, вместо fallback-суперэллипса.

Одиночный адаптер `fit_chamber_landmarks` аффинно сажает **одну** камеру по трём
точкам. Он не обещает согласования других камер, поставленных независимо.
Связанное восстановление следует выполнять через один репер и `atlas.fit`.
Нет автоматической загрузки нового JSON в UI, замены ручных контуров или
автоматического принятия результата. Источники и существующие review-гейты не изменены.

## Локальное PCA-уточнение

```bash
python scripts/fit_cardiac_atlas_pca.py \
  --input /local/gold/lv_reviewed.json \
  --input /local/gold/la_reviewed.json \
  --view A4C --max-modes 8 --output /local/models/atlas_a4c.json
```

Файлы задаются **явно**, не сканируются по всему диску. Gold должен содержать
`frames`-список с `phase` (`ED`/`ES`), `view`, `chamber`, открытой дугой `points`,
проверенными `mitral_annulus` и `apex_landmark`. Калибровка опциональна;
без неё уточняется нормированная форма, а не реальные размеры. Старая разметка
без опорных точек не получает выдуманные якоря — её надо подготовить/проверить.

Для связанных многокамерных наблюдений используйте один `atlas_samples`-record:

```json
{
  "atlas_samples": [
    {
      "view": "A4C",
      "phase": "ED",
      "reference_chamber": "LV",
      "pixel_spacing_mm": [0.3, 0.3],
      "anchors": {"septal": [100, 200], "lateral": [200, 200], "apex": [150, 50]},
      "contours": {"LV": [[100, 200], [120, 100], [150, 50], [180, 100], [200, 200]]}
    }
  ]
}
```

Пример показывает контракт; **одного record недостаточно для PCA** (нужны ≥2).
Открытые дуги должны идти septal→apex/roof→lateral без базального замыкания.
В едином record все камеры выравниваются одним репером; противоречивые общие
узлы (>3 мм) отвергаются. Точная топологическая разметка с числом узлов seed
сохраняет соответствия; иные дуги пересэмплируются по длине и требуют проверки
соответствий, особенно вдоль МЖП. Для PSAX/уже зарегистрированных данных доступно
`canonical_points_mm: [[x,y], ...]` вместо `anchors`/`contours`: порядок узлов
строго из `atlas.to_dict()`, пропущенный узел — `[null,null]`.

PCA обновляет среднее отдельно для ED и ES. Ненаблюдавшаяся фаза остаётся seed,
ненаблюдавшиеся узлы не становятся fake-labels. Пропуски заполняются masked EM/SVD;
знаки собственных векторов фиксированы для воспроизводимости. При нулевой
дисперсии сохраняются аналитические моды с отдельным provenance. Результат —
версионированный JSON с числовой геометрией, модами, дисперсиями и сводными счётчиками;
без путей, patient/study UID, пикселей или исходных записей. Артефакты хранить вне Git.
Для воспроизводимости нужно фиксировать входы и версии NumPy/BLAS; побайтовая
идентичность между разными BLAS при кратных собственных значениях не гарантируется.

### Учебные prepared_anatomy sidecar

Приложение продолжает считать их учебным слоем, не измерениями и не входом ИИ.
Офлайн-инструмент принимает их **только по явному opt-in**:

```bash
python scripts/fit_cardiac_atlas_pca.py --teaching-manifest /local/reviewed.json \
  --view A4C --output /local/models/teaching_atlas.json
```

`reviewed.json` содержит `teaching_samples`-список: каждый элемент — `path`
(относительно manifest), `frame_index`, проверенный `phase`, `reference_chamber`,
`anchors` в пикселях, опциональный `pixel_spacing_mm`, и `node_order` вида
`{"LV": [0,1,2,3,4]}`. Индексы выбирают из нормированного учебного полигона
проверенную открытую дугу; базальная хорда не включается. Sidecar не содержит
фазы и семантики узлов, поэтому они **не угадываются**. Оригиналы не переписываются,
медиа не открывается, приватные ссылки из sidecar не копируются в артефакт.

## Проверка

`test_cardiac_atlas.py` и `test_cardiac_atlas_training.py` включены в guarded
pure-core lane вместе с существующими тестами RV/MBS-lite/LA. Проверяются
обратимость, анизотропия, общая хорда/МЖП, отсутствие пересечений, фазность,
сохранение дуги при dropout, ridge/PCA, воспроизводимость JSON, opt-in teaching
и совместимость сервисов. Клинические выборки и популяционные метрики — отдельная
следующая проверка, не результат этих unit-тестов.
