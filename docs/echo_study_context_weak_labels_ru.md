# ML.5: контекст исследования, слабые метки и Active Mining

Backend для [#693](https://github.com/areatu/SonoForge/issues/693), поверх ML.1–ML.4.
Это **не клиническая валидация, не автоматическое обучение и не активация AI в UI**.
Подключение интерфейса/ежедневного архива относится к ML.6 и #697.

## 1. Контекст видов: pure-core API

`domain/services/study_view_resolver.py` принимает `StudyViewClip` для каждой
2D-серии. Порядок вероятностей фиксирован: `TTE_STANDARD_VIEWS` —
`PLAX, PSAX, A4C, RV_A4C, A2C, A3C, SUBCOSTAL`; сумма каждой строки — 1.

- `resolve_study_views(clips, manual_decisions=..., cues=...)` возвращает результаты
  **в исходном порядке**, не читает файлы и ничего не сохраняет.
- Мягкий forward/backward приор допускает самопереход, пропуск видов и обратный
  порядок. Он применяется по `AcquisitionTime` (DICOM TM), если время известно
  для всех серий, иначе по `InstanceNumber`, если номера известны для всех.
  При неполной информации хронологический приор **отключён**: имя файла не
  становится выдуманным временем. Даты пациента не читаются.
- Контекст измерений: `plax_linear` → PLAX; `rv_measurement` → A4C/RV_A4C;
  `la_biplane` → A4C/A2C. Повторение одинаковых измерений не усиливает приор.
  Default log-strength: protocol=.45, measurements=.8, верхние пределы .5 и 1.
  Это ограниченные эвристики, не калиброванные клинические вероятности.
- Любой визуальный прогноз с p ≥ threshold (по умолчанию .6) сохраняет свой
  вид и confidence, даже при противоречащем протоколе/измерениях.
- Явный `visual_view="UNKNOWN"`, OOD или max p <.35 **не повышается** контекстом
  до известного вида. Неоднозначный прогноз принимается только если posterior
  достигает threshold; иначе остаётся UNKNOWN.
- `MANUAL` — жёсткая граница, включая ручной UNKNOWN и виды вне TTE-матрицы.
  Автоматические решения никогда не становятся ручными якорями.
  Изменённый контекстом результат получает `AUTO_STUDY_CONTEXT`
  (`"auto_study_context"` при сохранении), а не MANUAL.

`application/study_view_context.py::study_measurement_cues(data, instance_to_series)`
адаптирует `StudyMeasurementData`, не вводя импорт application в domain:

- только SOP-привязанные пространственные калиперы (Ao/LA/LVIDd/IVS, TAPSE/RV);
- принятые контуры RV/RV_FW и пара LA A4C+A2C; pending/невалидная геометрия исключена;
- study-wide числа без источника не присваиваются произвольной серии;
- mapping должен относиться к рассматриваемым 2D-сериям. M-mode/Doppler серия
  сама по себе не превращается в 2D-клип. Doppler-калиперы исключены.

`ViewRecognitionWorkflow.suggest_study(...)` загружает ручные решения через
`IViewDecisionStore`, проверяет их идентичность и возвращает предложения **без
записи**. `save_decision()` и `JsonViewDecisionStore.save()` дополнительно
не позволяют автоматической записи заменить уже сохранённый MANUAL. Ручное
исправление другим ручным решением остаётся разрешённым. Как и существующий
JSON-store, это последовательный workflow, не новая многопроцессная CAS-база.
Старые документы без `source` по-прежнему считаются manual.

## 2. Сбор трёхточечных weak targets

```bash
python scripts/harvest_weak_labels.py \
  --index /local/study-index.json \
  --measurements-dir /local/measurements \
  --view-decisions-dir /local/view-decisions \
  --output /local/weak-run-001
```

Входы — уже существующие `MeasurementRepository` и `JsonViewDecisionStore`,
только чтение. Явный локальный index связывает их без сканирования DICOM:

```json
{
  "schema_version": 1,
  "studies": [
    {
      "study_uid": "1.2.3",
      "instance_to_series": {"1.2.3.4": "1.2.3.5"},
      "sectors": {"1.2.3.4": "anonymous-sector.npy"}
    }
  ]
}
```

`sectors` необязателен. Если предоставлен — это заранее подготовленный
**анонимный grayscale B-mode** массив `.npy` формы `[frames,height,width]`,
с координатами соответствующих рабочих измерений. `allow_pickle=False`, mmap,
предел 128 MiB/файл и 1024 px по каждой пространственной оси. Не подставляйте
сырой DICOM или кадр с пациентской надписью: этот инструмент не anonymizer.
`--require-gradient` исключает примеры без сектора вместо atlas-only fallback.
`--atlas /local/atlas.json` (повторяемый) позволяет использовать собственный
числовой ML.1-атлас; иначе применяется аналитический атлас.

Критерии отбора:

1. `review_pending=False`, явные frame/ED/ES, LV/LA/RV, кольцо и apex.
   Отсутствующая опора **не выводится** из плотной обводки.
2. Вид подтверждён **MANUAL** в store и совпадает с видом измерения. AUTO и
   AUTO_STUDY_CONTEXT не превращаются в учительские ручные метки.
3. Повторяющиеся одинаковые якоря дедуплицируются. Противоречащие повторы,
   а также разные LV/LA митральные кольца одного кадра исключаются, а не усредняются.
4. Атлас строит только измеренную камеру; не создаёт несуществующую разметку
   соседних камер. При наличии сектора выполняется ограниченная градиентная
   посадка двух половин дуги с неподвижными тремя реальными опорами. Проверяются
   вырождение, пересечения, границы изображения и величина смещения.

Выход `weak_shapes.json`: 81 узел в канонических безразмерных `annulus_span`
координатах; три реальные опоры имеют вес 1, интерполяция — .15. Индексы опор
заданы в порядке septal/lateral/apex. `source="weak_three_point_atlas"`,
`gradient_refined` явный; **не gold, не миллиметры и не плотная обводка врача**.
Сохраняются только allowlisted геометрия/веса/вид/фаза и агрегаты. Operational
Study/SOP/Series UID используются для соединения store только в RAM: в выходе
нет UID, хэшей UID, путей, имён, демографии, timestamps или изображений.
DICOM не открывается. Эти локальные производные клинические данные всё равно
следует защищать; наличие нормализованных координат не является сертификатом
полной деидентификации.

**Ограничение:** это weak **shape** targets для геометрических/атласных задач,
не готовый корпус изображений для CNN. Автоматический join с архивом кадров,
подключение к ML.3/ML.4 train loop и UI не включены. Слабая интерполяция не должна
подмешиваться в независимый gold или считаться новым клиническим подтверждением.

## 3. Active Uncertainty Mining

Реальное локальное inference (нужен optional `onnxruntime` и проверенный bundle):

```bash
python scripts/mine_uncertain_clips.py \
  --manifest /local/raw-manifest.json --bundle /local/template-bundle \
  --allow-unvalidated --top-k 10 --output /local/review-run-001
```

Manifest — формат ML.4 из [руководства SSL](echo_ssl_ru.md). Экспериментальный
bundle требует явного `--allow-unvalidated`; внешние веса не скачиваются.
Считаются только `train` записи: `val/test` нельзя незаметно добывать в обучающую
очередь. Заголовки val/test читаются лишь общим inventory для защиты split.
Пиксели проходят RAM-only очистку ML.4, ограничение max-clips=64/max-frames=24.
Предположение ED/ES из головы модели здесь — оценка, не измеренная клиническая фаза.

Индекс для клипа:

- `d = (1 - max(mean_t(cosines_t))) / 2`: расстояние от ближайшего прототипа [0,1];
- `e`: средняя NCC-взвешенная ошибка `prediction(t+1)` относительно перенесённых
  узлов `prediction(t)`, делённая на диагональ изображения;
- `U = .5*d + .5*min(e/.02, 1)`.

Используется реальный доменный NCC/round-trip tracker ML.4 (NCC≥.65 в обе стороны,
closure≤1.5 px, текстура/сектор/видимые опоры), без сглаживания целевого движения.
Если недостаточно валидных узлов, `warp_disagreement=null` и flow-вклад отсутствует:
это **не** утверждение, что движение согласовано. Результат сортируется по убыванию
U, равенства — по исходному `clip_index`. Редкость вида сама по себе не награда:
сложный A4C также может оказаться полезнее уверенного A3C.

Для воспроизводимой проверки без ONNX можно подать `--evidence /local/numeric.json`
вместо manifest/bundle. Schema 1, `clips` — записи с **только** полями
`clip_index`, `cosines` (вектор либо frames×prototypes), `warp_disagreement`
(уже нормализованное e или null), `valid_warp_nodes`.

Выход — `review_queue.json`, **только для проверки экспертом**, не новые labels.
Содержит `clip_index`, score и числовые компоненты. Исходный manifest остаётся
локальным и используется для нахождения клипа по индексу; пути/идентификаторы
в очередь не копируются. Не меняйте порядок manifest после ранжирования.
Нет импорта в gold, автоматического обучения или активации модели.

## Проверки и ограничения

- 45 новых целевых тестов: порядок серий, контекст измерений, неизменность MANUAL,
  UNKNOWN/OOD, JSON-source round-trip, точность и веса трёх опор, градиентная
  посадка, read-only harvest из настоящих локальных store, ranking/ties,
  настоящий NCC на числовых восьмиголовых выходах и dropout.
- Полный pure-core набор в **чистой среде без установки приложения, Qt и ML**:
  **1004 passed, 6 skipped** (старые optional ML-тесты). Проверка опор включает
  разные численные ядра для трёх опор и полной дуги: абсолютный допуск 1e-12
  в канонических координатах и обратное преобразование с допуском 1e-10 px;
  нулевая координата не сравнивается только относительным допуском.
  Import/help обоих CLI
  отдельно проверены без Qt/torch/ONNX runtime.
- Настоящие CLI в той же чистой среде: синтетический harvest дал один weak target
  с тремя точными опорами и `gradient_refined=true`; numeric mining выбрал `[1,2]`
  со score `[.725,.525]`. Файлы smoke находятся только в ignored `.cache/`.
- Это доказательство backend-контрактов на синтетике, **не** клинического прироста
  распознавания видов, качества новых весов или полезности экспертной очереди.
  Готовые клинические веса, patient dataset и автоматический UI-сценарий не поставляются.
