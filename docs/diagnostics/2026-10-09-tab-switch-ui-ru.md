# Шаг 4 / Ф4: замер переключения вкладок

## До правок

База: `a0c1c64` (шаг 2, PR #132). Замер сделан **до правок Ф4**.
Linux, Qt offscreen, окно 1200×800, шрифт по умолчанию. Скрипт:

```sh
QT_QPA_PLATFORM=offscreen python bench/tab_switch_probe.py --output build/tabs-before.json
```

В sandbox добавляется `LD_LIBRARY_PATH="$PWD/.venv/qt-runtime"` — локальные
игнорируемые библиотеки Qt, не часть приложения.

Два синтетических сценария: 3 вкладки папок и 3 вкладки серверного кэша;
6 переключений в каждом. Задержка загрузки 80 мс, завершение через настоящий
сигнал `studies_loaded`. Файлов, сетевого PACS и декодирования кадров нет;
загрузчик и выбор клипа подменены. Счётчики `QEvent` установлены на конкретные
виджеты, а не суммируются по всем детям. Они учитывают события из Qt/C++, в
отличие от Python-hook `QWidget.update`. Захват экрана в замере не применяется:
`grab()` сам вызывает Paint и исказил бы счётчики.

| Метрика, сумма на 6 переключений | Папки, до | Серверный кэш, до |
|---|---:|---:|
| `addTab` / `removeTab` | 36 / 36 | 36 / 36 |
| Высота полосы, min…max (логические px) | 25…25 | 25…25 |
| Смена страницы main stack | 12 | 12 |
| Скрытие / показ панели инструментов | 6 / 6 | 6 / 6 |
| Paint панели инструментов | 12 | 12 |
| Paint полосы / QTabBar | 12 / 12 | 12 / 12 |
| Paint SystemBar / status bar | 0 / 0 | 0 / 0 |
| Paint / UpdateRequest верхнего окна | 24 / 24 | 24 / 24 |
| LayoutRequest верхнего окна | 24 | 24 |

**Выводы:** гипотеза изменения высоты не подтверждена — шаг 2 уже фиксирует её.
Пересоздание вкладок подтверждено: две перестройки по три вкладки на одно
переключение. Главная подтверждённая причина мигания инструментов — смена
страницы `_main_stack`: инструменты находятся внутри `_content_widget`, поэтому
заглушка прячет не только просмотр, но и весь этот контейнер. Мигание SystemBar
и status bar в этом изолированном сценарии не воспроизведено. Paint верхнего
окна **не означает** перерисовку всей его площади: Qt использует dirty regions.

## План по результату

1. При прежнем порядке tab_id менять только текущий индекс и действительно
   изменившиеся подписи/tooltip, не удалять вкладки и их кнопки закрытия.
2. Для переключения с уже показанного исследования на загруженную вкладку
   оставлять контент на месте, поверх просмотра показывать индикатор загрузки.
   Прежнее изображение нельзя редактировать во время смены исследования.
3. Собирать синхронные изменения просмотра/галереи с локально выключенными
   updates и гарантированным восстановлением; не блокировать paint всего окна,
   инструментов или асинхронный event loop.
4. Не вызывать выход из special layouts, когда оба режима уже выключены.

## Ограничения приёмки

Настоящее видео **до/после на Windows/macOS с тремя PACS- и тремя локальными
вкладками не записано**: в окружении нет нативного рабочего стола, живого PACS
и клинического корпуса. Синтетический замер не заменяет этот пункт приёмки.
Ожидаются необходимые перерисовки изменившихся подписей, статуса, параметров
нового исследования и активной вкладки — их нельзя запрещать ради нулевых
счётчиков. Цель Ф4 — убрать скрытие/показ и массовую перестройку неизменного UI.

## После правок

Та же среда и тот же скрипт, `--output build/tabs-after.json`. Результаты
папок и серверного кэша совпали (цифры на 6 переключений):

| Метрика | До | После |
|---|---:|---:|
| `addTab` / `removeTab` | 36 / 36 | **0 / 0** |
| Высота полосы, min…max | 25…25 | 25…25 |
| Смена страницы main stack | 12 | **0** |
| Скрытие / показ панели инструментов | 6 / 6 | **0 / 0** |
| Paint панели инструментов | 12 | **0** |
| Paint полосы / QTabBar | 12 / 12 | 6 / 6 |
| LayoutRequest полосы / QTabBar | 12 / 12 | **0 / 0** |
| Paint SystemBar / status bar | 0 / 0 | 0 / 0 |
| Paint / UpdateRequest верхнего окна | 24 / 24 | 18 / 18 |
| LayoutRequest верхнего окна | 24 | 12 |

Оставшийся Paint полосы — необходимая смена выделенной вкладки, а не её
перестройка. Верхнее окно продолжает получать частичные Paint/UpdateRequest
для изменившейся области контента; искусственно подавлять их нельзя.

Индикатор размещён поверх `_viewer_stack`, без переключения main stack, без
`setEnabled(False)` для всего UI. Пока он виден, события ввода этого окна
фильтруются: нельзя измерять по прежнему изображению или запустить инструмент
горячей клавишей во время смены исследования. Другие окна/диалоги, paint и
асинхронные сигналы не блокируются. Фильтр удаляется при окончании/отмене/ошибке
загрузки и скрытии окна; при повторном показе во время загрузки восстанавливается.

`setUpdatesEnabled(False)` применяется только синхронно к просмотру и галерее,
с восстановлением прежних флагов в `finally`, в том числе при вложенных вызовах
и исключениях. Во время ожидания асинхронной загрузки обновления включены.
Первичная загрузка, открытие нового источника и пустые вкладки сохраняют заглушку.
Для ранее не посещённой вкладки без выбранного клипа прежние пиксели очищаются
без сигналов изменения измерений, чтобы не выдавать старое изображение за новое
исследование; выбор миниатюры остаётся за пользователем, как в исходном пути.

## CI #37989629129: тайм-аут теста шрифта

Linux остановился по `pytest-timeout` в `test_strip_height_tracks_caliper_control`
при `QApplication.setStyleSheet`, а не на проверке геометрии. Последний Python
frame в CI был `StudyLoadingOverlay.eventFilter`, но это само по себе не
доказывает проблему фильтра: глобальное переоформление вызывает множество
Qt callbacks. Lint и non-GUI наборы Windows/macOS этого запуска прошли.

Локально воспроизведён исходный прогон с coverage от начала `tests/unit` до
этого теста (порядок сохранён). Перед вариантом `[12]` в QApplication было
**48 255 виджетов / 65 MainWindow**, перед `[18]` — **49 061 / 66**.
Вариант `[18]` завершился тем же тайм-аутом в `app.setStyleSheet`, на этот раз
с последним callback `ThumbnailDelegate.sizeHint`. Изолированная исходная
пара тестов проходила; зависимость от предшествующего Qt-состояния подтверждена.

Исправление ограничено тестом и диагностикой CI: как в `test_ui_scale`, реальный
путь применения настроек проверяется в свежем процессе QApplication. Настройки,
каталог измерений и PACS-кэш изолированы временным каталогом; окно закрывается
и DeferredDelete обрабатывается. Процесс ограничен 45 секундами, общий тайм-аут
pytest 60 секунд не меняется. Проверяются высоты полосы, QTabBar, tabRect,
нулевой верхний отступ и фактический размер шрифта Caliper.

Проверки после изменения:

- **55 passed** с coverage: `test_main_window_tabs`, `test_tab_strip`,
  `test_pytest_failure_annotations`.
- **2 passed** с coverage при `QT_SCALE_FACTOR=1.5` (обе проверки шрифта).
- Стресс-проверка: в родительском Qt-процессе удерживались **49 062 виджета**;
  исправленная пара прошла за 6,92 с (вызовы: 2,85 / 2,95 с). Stylesheet и шрифт
  родительского QApplication не изменились. Это синтетический контроль изоляции,
  не повтор всего полного набора после исправления.
- Линт/форматирование, `git diff --check` и синтаксис bash-шага CI — OK.

В CI `-v` раньше компенсировался `-q` из pyproject: вместо test nodes печатались
точки по модулям. Теперь используется `-vv`, а существующий annotation filter
сохраняет последний node id, который публикуется при ненулевом выходе pytest.
Новый полный CI должен отдельно подтвердить результат на hosted runner.
