# Локальный обучающий архив рабочих измерений

Реализация [#697](https://github.com/areatu/SonoForge/issues/697). Это **локальный
источник примеров**, не online-обучение, не автоматический gold и не активация
новых весов. Первый этап [#699](https://github.com/areatu/SonoForge/issues/699)
добавляет dev-UI сбора/просмотра/курирования и локальный перенос между Windows и
Debian: [руководство рабочего места ML](local_ml_workbench_ru.md). Мастер обучения,
независимая оценка и активация остаются следующими этапами #699.

## Настройки сбора для разработки

В разрешённом dev-запуске полного профиля сбор **включён по умолчанию**.
Начальный каталог — `measurement-training` рядом с `SonoForge/local-ml.json`
в каталоге конфигурации пользователя (вне Git checkout); квота 4096 МиБ.
Каталог уже заполнен в окне «Локальное рабочее место ML», поэтому флажок можно
сохранить без предварительного выбора папки. Явно сохранённое выключение
сохраняется при повторном открытии и перезапуске; данные не удаляются.
Изменение настроек подключения сборщика применяется после перезапуска.
Альтернатива для CLI — одновременно два параметра окружения; каталог должен
быть абсолютным, вне любого Git checkout, отдельно от логов и исследований:

```bash
SONOFORGE_LOCAL_TRAINING_ARCHIVE=1 \
SONOFORGE_LOCAL_TRAINING_ARCHIVE_DIR="$HOME/SonoForge-local-training" \
uv run sonoforge
```

PowerShell:

```powershell
$env:SONOFORGE_LOCAL_TRAINING_ARCHIVE = "1"
$env:SONOFORGE_LOCAL_TRAINING_ARCHIVE_DIR = "$HOME\SonoForge-local-training"
uv run sonoforge
```

Явная env-конфигурация приоритетна над UI; `SONOFORGE_LOCAL_TRAINING_ARCHIVE=0`
выключает сбор. После удаления переменных применяется сохранённый выбор UI
(если его нет, сбор включён по умолчанию). Сам UI после сохранения показывает
сохранённый выбор, а не подменяет его переменными окружения; сообщение после
сохранения напоминает о runtime-приоритете окружения. Накопленные данные не удаляются.
Presenter, hermetic test composition и frozen-бинарники игнорируют opt-in:
включение в публичный релиз ещё **не принято**. Само включение не создаёт файлы
и не сканирует старые исследования. Архив появляется при работе с контурами.

Файл: `measurement-training.sqlite3`. В нём таблицы `samples`, `frames`, `settings`.
Каталог создаётся с Unix mode 0700, файл — 0600; на Windows нужны обычные локальные
права доступа и при необходимости шифрование диска. Не кладите каталог в
синхронизируемую облачную папку, сетевой ресурс, package resources или diagnostics.

## Что считается подтверждением

Общий application use-case — `MeasurementArchiveCapture`, подключённый через
composition. Он принимает законченные domain-контуры в общем
`AppController.on_contours_changed`, а не движения мыши/черновик инструмента.
Скопированные пиксели берутся из декодированного source-кадра controller, **не**
из viewport, скриншота или графического overlay.

- Завершение валидного инструмента любым существующим жестом/Enter: после
  финального snap повторно читается весь окончательный список контуров viewer
  и вызывается общая операция подтверждения.
- Явное принятие AI review: сначала сбрасывается `review_pending`, затем та же
  операция подтверждения. Принятие не превращает AI в MANUAL.
- Переход на другой кадр **того же клипа** подтверждает уже законченный,
  не ожидающий AI-review контур. Исходный кадр скопирован **до** перехода.
  Переключение клипа/исследования не является неявным подтверждением.
- Незаконченная линия, Esc, отменённый AI review и пустой/невалидный контур не
  создают пример. Навигация не достраивает черновик и не принимает pending AI.
- Правки узлов накапливаются до следующего подтверждения, без независимых
  обучающих примеров на каждое движение. Enter после правки либо переход кадра
  сохраняет последнюю завершённую геометрию.
- Повторное применение неизменного результата — no-op. Замена контура той же
  камеры/проекции/фазы в клипе (включая выбор другого кадра для этой фазы) —
  новая `revision` того же `sample_id`, как в study session.
- Полный список контуров клипа авторитетен для архива: удалённый контур получает
  `excluded=true`; актуальный экспорт его не содержит. Undo + подтверждение
  восстанавливают тот же ID с новой revision. Сброс измерений исследования исключает
  все его примеры и удаляет ожидающие записи. Это не журнал промежуточных форм.

Нет отдельного согласия на каждый пример, вопросов о диагнозе, камере или уже
известной проекции. Generic AREA/VOL без камерного ID **не** интерпретируются
по переведённым подписям как LA/RA и не архивируются как камерные метки.

При ошибке файловой системы/SQLite clinical-измерение остаётся рабочим; статическое
сообщение `Local training archive skipped; clinical measurement unchanged` попадает
в лог без идентификаторов, путей и текста исключения. Неуспешный явный Apply можно
повторить, пока кадр открыт. Не обещается восстановление пропущенного примера
после ухода с кадра или закрытия приложения; при сбое архив может сохранить только
предыдущую успешно подтверждённую revision. Архив не заменяет clinical storage.

## Схема и координаты

Схема 1 сохраняет:

- source pixels как NPY BLOB без pickle, их SHA-256 и полный размер/тип;
- исходные points, доступные annulus/apex, камеру LV/LA/RV/RA, view, frame index;
- стабильный ID вида инструмента (`chamber_open_arc:LV` либо
  `chamber_polygon:RA` и т. п.), фазу и её семантику из domain-контекста;
- доступный spacing под геометрией (выбор frame/region calibration, а не соседней
  панели); при неоднозначности — `null`, без выдуманных mm/px;
- `source_to_saved = identity(3)`: сохраняется полная source-grid, без crop/resize.
  Zoom/pan viewer не меняют координаты; viewport-координаты вне кадра отвергаются;
- schema/app version, phase mapping version, stable sample/measurement keys,
  revision и статус исключения;
- локальные HMAC-связи patient/study/series/instance/measurement со случайной
  солью архива (в #699 её можно явно перенести на второй пустой архив до сбора). Исходные UIDs, PatientName, PatientID, birth date,
  описания исследований, пути и подписи измерений не записываются в JSON.

Запись кадра и метаданных атомарна в одной SQLite-транзакции. Одинаковые кадры
хранятся один раз. Хранятся актуальные revision, не полные исторические контуры;
исключение — логическое: байты старых кадров могут оставаться в БД. Для полного
удаления локального материала закройте приложение и удалите выделенный каталог
архива (включая возможные SQLite sidecars), согласно локальным правилам хранения.

### Фазы предсердий — не желудочковые подписи

| Камера и имеющийся контекст | Собственная семантика | Явное отображение в GLOBAL atlas |
|---|---|---|
| LV/RV ED | ventricular_end_diastole | ED |
| LV/RV ES | ventricular_end_systole | ES |
| LA/RA ES камерного объёмного инструмента | atrial_maximum | ES |
| LA/RA ED камерного объёмного инструмента | atrial_minimum | ED |
| Неспецифичная/неизвестная фаза | unspecified | экспорт ED/ES запрещён |

Имеющиеся atrial area-length инструменты задают ES для максимального объёма.
Это не утверждение, что «систола предсердия = ES желудочка» или «диастола
предсердия = ED желудочка». Таблица отображает **смысл измерения** на глобальные
желудочковые кадры. `atlas_phase()` — отдельная тестируемая функция; неизвестную
фазу она не угадывает. `phase_mapping_version=1` фиксирует правило экспорта.

### Происхождение и сила метки

`MANUAL`, `AUTO_EDITED`, `AUTO_ACCEPTED` хранятся отдельно от факта подтверждения.
Ручная правка AI/model-контуров фиксируется в `auto_edited`; LA-assist дополнительно
несёт `auto_generated`, даже когда клинический `source` исторически равен `manual`.
Эти поля проходят через clinical codec и не сбрасываются при сохранении.

`geometry_kind=landmark_prior` явно маркирует существующие fitter-контуры из трёх
кликов, в том числе у «ручного» инструмента. Они могут храниться в архиве, но
**не становятся сильной меткой** ни из-за подтверждения, ни из-за review. Экспорт
сильного corpus/PCA требует реального trace. Это не подмена контура weak-label
реконструкцией из #693. Старые документы не сканируются/не импортируются в gold;
при работе с унаследованными контурами требуется проверка происхождения при review.

Нет проверки «похожести на средний атлас»: патологический/частичный trace хранится
как есть. Отсутствующая камера — `UNKNOWN_NOT_NEGATIVE`, не фон и не средний prior.
Технически некорректные/nonfinite координаты и выход за source-grid отвергаются.

## Офлайн-экспорт, review и отсутствие утечки

Первый экспорт — инвентаризация локальных примеров, **без** автоматической gold-метки:

```bash
uv run python scripts/export_measurement_archive.py \
  --archive "$HOME/SonoForge-local-training/measurement-training.sqlite3" \
  --output "$HOME/SonoForge-corpus-review-01" --acknowledge-local-phi
```

Выход — новая внешняя директория: `manifest.json`, сохранённые `*.npy`, а при
наличии reviewed train-арок — `atlas-A4C-train.json` и аналогичные файлы по view.
Источник открывается read-only, clinical storage и рабочие веса не изменяются.
Существующий output и Git-каталог запрещены. `prepared_anatomy` не используется.

Отдельный локальный review JSON связывает **sample_id с точной revision**:

```json
{"64_hex_sample_id_from_manifest": 2}
```

После проверки кадров, контуров и происхождения явно передайте `--review review.json`
в новый экспорт. При любом изменении/revision старый review недействителен.
Переход из обычного рабочего измерения в archive не требует review; review нужен
позже для curated gold-quality training/PCA, а не дополнительного вопроса врачу.

Перед PCA/обучением все записи объединяются по patient, study и идентичным пикселям
(транзитивно), затем целым группам детерминированно назначается `train/val/test`.
Повторные одинаковые метки дедуплицируются **после** объединения. При отсутствии
patient identity хотя бы в одном исследовании весь экспорт консервативно является
одной группой: независимый holdout доказать нельзя. Малый архив не обязан содержать
все три split; не перемещайте записи вручную ради обхода проверки validation.
Связи ограничены известными приложению идентичностями, не решают межсистемный MPI.

Сохраните полный manifest как версию датасета. При добавлении связующих исследований
или смене seed split может измениться: независимую оценку нужно версионировать,
а не смешивать произвольные экспорты/старые checkpoints.

```bash
uv run python scripts/fit_cardiac_atlas_pca.py \
  --input "$HOME/SonoForge-corpus-reviewed-01/atlas-A4C-train.json" \
  --view A4C --output "$HOME/atlas-A4C-reviewed-v1.json"

uv run python scripts/train_echo_template_multitask.py \
  --measurement-corpus "$HOME/SonoForge-corpus-reviewed-01/manifest.json" \
  --output "$HOME/SonoForge-training-reviewed-01" --allow-random-init
```

Для реального обучения нужны зависимости ML и независимые train/val группы;
`--allow-random-init` здесь только явное разрешение начальной инициализации,
**не** клиническая рекомендация. Dataset читает сохранённый NPY-кадр, исходный DICOM
больше не нужен; только проверенные реальные labels идут в gold-stage. Никакого
обучения или активации при сборе/экспорте нет. Атласный адаптер отклоняет heldout,
устаревший review, prior, неопределённую фазу и неготовые correspondences.

**RA уже собирается и экспортируется в локальный corpus.** Данный reviewed
training/PCA adapter пока явно сообщает `RA ... training adapter not yet supported`;
RA не подменяется LA/RV и не исчезает из архива. Закрытые atrial area-length
полигоны доступны в segmentation corpus; текущий node-head/PCA adapter явно
отказывается от них без reviewed open arc с
анатомическими ориентирами; адаптер не выдумывает их автоматически.

## Приватность и границы доказательств

Архив **не объявляется обезличенным**. В пикселях может быть вшитый текст, ECG,
дата/имя пациента. HMAC не является pixel de-identification. Локальный оператор
отвечает за доступ/резервную копию и подготовку данных перед любым обменом.
Облачного сервиса, сетевой отправки, телеметрии и автоматической диагностической
упаковки нет. Diagnostics остаётся allowlist только безопасных log-событий;
Git ignore дополнительно закрывает имя БД и типовой каталог. Код не сохраняет
пациентские кадры внутри package, поэтому build/release их не собирают.

Исторические проверки при завершении #697 (не статус всей #699):
`test_training_archive.py` (54 synthetic backend cases),
`test_training_archive_runtime.py` (5 real controller/viewer lifecycle tests),
полный pure-core набор (1058 passed, 6 skipped в чистой среде без Qt/ML), strict mypy и архитектурные ратчеты. GUI-тесты в bare sandbox
проверяются offscreen с существующим developer-only qtstub harness; это не проверка
реального GPU/rendering или packaged OS. Клинический прирост, реальные обученные
веса, UI рабочего места ML, межмашинный clinical exchange и автоматический public
opt-in этой задачей не доказываются.
