## 0. Краткий вывод ( executive summary)

SonoForge уже находится **выше уровня большинства open-source DICOM-вьюеров** и **на уровне
младших коммерческих рабочих мест по 2D-эхокардиографии** благодаря: ASE-ориентированным
расчётам, ИИ-сегментации (EchoNet ONNX), полноценному STE (bull's eye, кривые деформации, GLS,
QC), PACS (DICOMweb + DIMSE + TLS), исходящему интеропу (HL7/FHIR/DICOM SR/CDA) и локальной
ЭП/аудиту.

Главные **разрывы до «больших» коммерческих платформ**:
1. **Нет 3D/4D-эхокардиографии** и **MPR/объёмного рендеринга** (классика радиологии).
2. **Нет авто-распознавания вида** (A4C/A2C/PLAX) и «однокнопочного» Auto-EF — workflow ещё ручной.
3. **Нет модуля стресс-Эхо** (17-сегментный WMSI, rest/stress, контраст-перфузия) — только детекция стресс-исследований.
4. **Нет контраста (LVO/MCE), эластографии, CEUS-кривых, педиатрии/Z-score, TEE-многоплоскостности**.
5. **Безопасность «на пороге»**: нет шифрования at-rest, квалифицированной ЭП, централизованной авторизации, входящего MWL/SR.

По **плагинам**: архитектура *уже* наполовину плагинная (декларативные реестры калькуляторов,
каталог измерений, профили исследований, domain-порты, build-профили). Добавить runtime-загрузку
**можно с малыми жертвами**, и выгода реальная — прежде всего **регуляторное разделение**
сертифицируемого ядра и исследовательских/вендорных модулей (это прямо отвечает решению #331).

### 1.2 Что у SonoForge уже на уровне или выше коммерческих аналогов

- **STE-конвейер** (speckle tracking, bull's eye 17 сегм., кривые деформации, GLS, ручная
  коррекция ядер, QC) — концептуально паритет с коммерческие эхо-платформы, причём с
  документированным соответствием консенсусу EACVI/ASE (`docs/STE_IMPROVEMENT_PLAN.md`).
- **Исходящий клинический интероп** (HL7 v2 `ORU^R01` с MLLP/TLS, FHIR R4, DICOM SR TID 5200,
  CDA R2) — многие «младшие» рабочие места им не обладают.
- **Локальная ЭП + неизменяемый audit-чейн** (Ed25519, `audit.jsonl` без PHI) — редкость для
  open-source; коммерческие аналоги часто требуют серверной части.
- **Офлайн + переносимость** (Presenter на флешке, шифрованные секреты) — сильнее, чем у
  вендор-привязанных решений.
- **Reference Constructor** (редактор справочников ASE, импорт Excel/YAML) — у коммерции это
  закрытые базы данных.

### 1.3 Чего не хватает, по категориям

#### А. Эхокардиографические платформы (коммерческие эхо-платформы)
- **Auto view recognition** — коммерция распознаёт A4C/A2C/PLAX автоматически; в SonoForge вид
  выбирает пользователь. Без этого «однокнопочный» Auto-EF невозможен.
- **3D/4D объёмная количественная оценка** — полнообъёмная 4D-количественная оценка (LV/RV/AV/MV), полнообъёмная ЛП. SonoForge
  строго 2D (задокументированное ограничение STE).
- **Расширенная автоматизация**: Easy AutoEF (1 клик), Easy AFI LV (EF+strain за ~15 c),
  Myocardial Work (pressure-strain), авто-распознавание спектра. У SonoForge — ИИ только ЛЖ/ЛП.
- **Стресс-Эхо как workflow**: 17-сегментный WMSI, сравнение rest/stress, контрастная перфузия,
  добутаминовые протоколы. Есть только *детекция* dobutamine/stress-исследований
  (`study_enrichment.py`), аналитики нет.
- **Контраст**: LVO (opacification ЛЖ), MCE (количественная); TEE-многоплоскостная реконструкция.
- **Правый желудочек**: 3D RVEF, RV-strain, RV масса — частично (FAC/TAPSE/RV S' есть, 3D/стрэйн — нет).
- **Диастология «под ключ»**: авто-извлечение E/A, e', E/e', скорости TR, лёгочных вен, IVRT в
  единый авто-градуируемый блок с обработкой «indeterminate».

#### Б. DICOM-вьюеры и лучевая диагностика (радиологические DICOM-вьюеры)
- **MPR (мультипланарная реконструкция)** и **3D volume rendering / VR** — ядро радиологии;
  у SonoForge только `ctmr_stack` (послойный CT/MR без полноценного MPR/VR).
- **PET/CT, ОФЭКТ, мультимодальная fusion** — отсутствуют.
- **Радиологические ROI-инструменты**: Cobb, гистограммы, SUV, time-intensity curves, ROI-статистика.
- **DICOM SR (чтение/импорт)** и **Graphic Annotation Presentation State (GSPS)** — аннотации не
  сохраняются как DICOM-объект; входящий SR в #626.
- **Hanging protocols** (авто-раскладка по modality/series) — у SonoForge раскладки есть, но без
  правил на основе метаданных.
- **DICOMDIR / CD-DVD импорт**, вторичный захват — возможно частично через скан папки.

#### В. CVIS / отчётные платформы (коммерческие эхо-платформы / коммерческие CVIS-системы / коммерческие EHR-системы / коммерческие CVIS-системы)
- **Worksheet → preliminary → final** с обязательными полями и handoff-верификацией лаборатории
  (у SonoForge lifecycle `draft/signed/amended` есть, но не полный worksheet-конвейер).
- **Голосовой ввод / диктовка** (коммерческие CVIS-системы) — отсутствует.
- **Педиатрия/Z-score, фетальное Эхо, growth charts** — у SonoForge взрослые ASE-нормы; педиатрия
  практически отсутствует.
- **Интеграция с заказами/работой**: входящий **MWL** (worklist) и **MPPS** (#626 в планах).
- **Популяционная аналитика лаборатории**, QC-метрики, авто-кодирование (ICD-10/CPT).

#### Г. Кросс-срез / безопасность (см. также раздел 3 и §2.5)
- **Шифрование at-rest** измерений/DICOM-кэша/экспортов (в README заявлено как non-goal).
- **Квалифицированная ЭП** (eIDAS/УКЭП) вместо локальной Ed25519.
- **Централизованная авторизация** (LDAP/AD/OIDC/SAML) — сейчас только локальный multi-user.
- **Полноценная деперсонализация по DICOM PS3.15** (Basic + clean-pixel + burned-in теги) — сейчас
  есть `phi_mask`/`phi_text_detector`, но не профиль PS3.15 клинических испытаний.

## 2. Новые полезные функции (реализуемая «фантазия»)

Оценка реализуемости: **S** (<2 нед), **M** (до ~1.5 мес), **L** (квартал+). Везде — опираемся на
существующее ядро, чтобы не ломать архитектурные инварианты.

### 2.1 Глубина эхокардиографии

1. **Auto View Recognition (ONNX-классификатор первого кадра клипа).** ● Реально: дообучить лёгкую
   CNN на тех же клипах, что и LV/LA-сегментация; результат подставляется в `StudyProfile` и
   фильтрует панель. Это ключ к «однокнопочному» EF. (M)
2. **One-click Auto-EF.** Композиция из (1) + LV-сегментации + temporal fusion + biplane Simpson:
   кнопка «Auto EF» выдаёт EDV/ESV/EF с возможностью ручной правки. Прямой аналог Easy AutoEF. (M)
3. **Модуль стресс-Эхо.** 17-сегментный WMSI (rest/stress), авто-сравнение визитов, шаблоны
   добутаминового протокола, опционально — контрастная перфузия (qualitative scoring). Детекция
   dobutamine/stress уже есть в `study_enrichment.py`. (M–L)
4. **Myocardial Work (pressure-strain).** ● Прогрессивно и реально: из GLS + плечевого АД ( cuff
   pressure) + тайминга клапанов строятся петли давление–деформация → глобальная работа миокарда
   (GWI, GCW, GWW, GWE). Не зависит от нагрузки сильнее, чем strain. Чистая математика поверх
   существующего STE. (M)
5. **LA strain + RV strain + послойный стрэйн (endo/mid/epi).** Частично: слой-селектор уже в UI;
   нужны маски/трекеры для ЛП и ПЖ. (M)
6. **Диастология-под-ключ.** Авто-извлечение E/A, e', E/e', TR, PV, IVRT в единый блок с
   авто-градацией и честной обработкой «indeterminate» (есть `diastology_grade.py`). (M)
7. **Контраст LVO / MCE и CEUS TIC.** ● Из киноклипа — time-intensity curve, peak enhancement,
   TTP, WiAUC (как в радиологические вьюеры). Реализуемо как обычный ROI-трекинг поверх кадров. (M)
8. **Педиатрия/Z-score + фетальное Эхо.** Добавить педиатрическую базу норм и BSA-индексированные
   Z-score; фетальные биометрию/кардио по аналогии с коммерческие fetal-strain решения. (M)

### 2.2 УЗИ и смежная радиология

9. **Эластография (SWE) для щитовидной/печени.** SonoForge уже имеет профиль «щитовидная железа»;
   добавить измерение shear-wave velocity/stiffness и качественную шкалу. (S–M)
10. **Акушерство (fetal biometry).** HC/AC/FL/BPD, EFW (Hadlock), допплер артерии пуповины,
    околоплодные воды. Огромный клинический спрос, ложится в существующий каркас профилей. (M)
11. **MPR + 3D VR для CTMR.** Достроить `ctmr_stack` до мультипланарной реконструкции и
    volume-rendering (как минимум MIP/VR на Numpy + PyQtGraph). Закрывает разрыв с радиологические вьюеры. (L)
12. **ABVS / молочная железа, МСК/нервные блоки** — по запросу, через те же профили. (S–M)

### 2.3 Удобство и продуктивность

13. **Протокол-ориентированные guided-экзамены.** Расширить существующие «guided protocols» до
    ASE-complete-study чек-листа с прогресс-баром и авто-переходом к следующему измерению. (S–M)
14. **Пакетная обработка (batch pipeline).** Прогнать папку исследований сконфигурированным
    конвейером (seg → Simpson → strain) и выдать сводный batch-отчёт. Ядро уже потокобезопасно
    (workers). (M)
15. **Локальный индекс архива + тренды визитов.** Индексировать локальные исследования в SQLite
    (уже есть `audit`/`measurement` store) и рисовать тренды EF/LAVi по визитам — аналог population
    view внутри одной машины. (M)
16. **Command palette (Ctrl+Shift+P, стиль VSCode).** Глобальный палец команд поверх существующего
    поиска в панели. Дёшево, сильно повышает скорость. (S)
17. **Облако-независимый «study capsule».** Экспорт зашифрованного бандла (измерения + кадры +
    подпись) для second opinion — связывает безопасность и удобство. (M)
18. **Однокликовый PDF с брендингом учреждения** (логотип, шапка) — поверх существующего report. (S)

### 2.4 Инновации интерфейса

19. **AI co-pilot overlay: оценка качества кадра в реальном времени.** Правило/лёгкая модель
    сигнализирует о недостаточной глубине, гейне, off-axis, выпадении sector'а. Реально как
    лёгкий детектор поверх кадра. (M)
20. **Контекстно-адаптивная панель.** Панель сама подсвечивает «вероятное следующее измерение» по
    заполненности исследования (надстройка над `tool_panel_view`). (S–M)
21. **Diff-view между визитами** с наложением контуров ЛЖ прошлого и текущего. (M)
22. **Colorblind-safe палитра для strain/bull's eye** + high-contrast тема (accessibility),
    расширение существующей темы-системы. (S)
23. **Таймлайн с маркерами фаз (ED/ES от ECG).** Детектор R-пиков и cardiac-cycle уже есть —
    визуализировать фазы прямо на scrubber'е. (S)
24. **Touch/перо для Presenter** (планшеты) — расширение существующего портативного режима. (S–M)

### 2.5 Безопасность и комплаенс (прогрессивно, но реально)

25. **Шифрование at-rest** measurement store + DICOM-кэша + экспортов (age-шифрование, опц.
    мастер-пароль/KDF — см. #621). Закрывает главный declared non-goal. (M)
26. **Квалифицированная ЭП через плагин** (eIDAS/УКЭП-провайдер) поверх существующего
    `SignerPort`. (M, через плагин — см. §3)
27. **Деперсонализация по DICOM PS3.15** (Basic + clean-pixel + burned-in), надстройка над
    `phi_mask`. (M)
28. **Политика consent/retention** — авто-экспирация кэша по политике учреждения. (S–M)
29. **Воспроизводимые сборки + GPG-подпись `SHA256SUMS`** (#421) и публичное зеркало attestation. (S–M)
30. **PHI-aware лог-редактирование «по умолчанию»** (расширить существующий PHI-aware tag filter). (S)

## 3. Плагинная архитектура: можно ли и есть ли выгода?

### 3.1 Что уже есть (латентные точки расширения)

SonoForge **уже наполовину плагинный** — расширение идёт через декларативные реестры и порты:

- `domain/calculators/registry.py` — **калькулятор = данные** (входы/выходы/формулы). Добавить
  калькулятор = добавить `CalculatorSpec` + чистую формулу, **без UI-кода**. Это по сути плагин.
- `domain/measurement_catalog.py` (`MEASUREMENTS`, `CATALOG`, `SECTIONS`) — стабильные ID, RU/EN
  лейблы, единицы; единый источник для панели/оверлея/отчёта/PDF.
- `domain/study_profiles.py` — профиль исследования как *фильтр* секций (не перезаписывает layout).
- `domain/ports.py` — Protocol-порты (`IImageReader`, `IVideoReader`, `IDicomReader`,
  `IWorklistSink`) — чёткие швы под замену адаптеров.
- `infrastructure/profile.py` — build-профили (`full`/`presenter`) как feature-flags; Presenter —
  это «плагин-в-обратную сторону» (исключение модулей без удаления кода).
- `infrastructure/vendor_profiles/` — реестр вендор-специфичных профилей (производители УЗ-систем).

**Вывод:** швы есть. Не хватает **runtime-обнаружения и загрузки** плюс **стабильного публичного
API-контракта** (`sonoforge.ext`).

### 3.2 Можно ли без сильных жертв?

**Да, преимущественно формализацией того, что уже есть.** Чистая архитектура (0 рёбер
`presentation→infrastructure` и `domain→infrastructure`, замороженные направления слоёв в `lint`)
— идеальная почва: плагин цепляется к domain-портам, не нарушая инвариантов. Главные риски и
компромиссы:

- **Стабильность API.** Появление плагинов = обязательство поддерживать `PluginAPI` (semver +
  политика deprecation). Решается: явная версия API, freeze-периоды.
- **Безопасность.** In-process Python-плагины = полное исполнение кода. Решается: подписанные
  плагины (связь с ЭП/code-signing), allowlist, в Presenter — загрузка плагинов выключена по
  умолчанию.
- **CI-гейты.** `lint`/mypy/coverage/«0 приватных ссылок в viewer-тестах» должны распространяться на
  плагины или плагины несут свои тесты. Решается на уровне фреймворка плагинов.
- **PyInstaller/Presenter.** Лайт-сборка исключает модули; загрузчик плагинов нужен как хук,
  плюс возможность грузить плагины из соседней папки. Управляемо.

### 3.3 Варианты реализации (по возрастанию риска)

| Вариант | Суть | Жертвы | Когда |
|---|---|---|---|
| **A. Registry-first** | Консолидировать существующие реестры в публичный `sonoforge.ext`; first-party «плагины» = модули, регистрирующиеся в реестрах | минимальные (уже есть) | сейчас |
| **B. Entry-point плагины** | `importlib.metadata.entry_points(group="sonoforge.plugins")`; сторонний pip-пакет регистрирует плагин; авто-обнаружение при старте | средние (нужен контракт жизненного цикла init/activate/deactivate + sandbox-ревью) | фаза 1 |
| **C. Recipe/скрипты** | Встроенный Python/Lua/JS API для макросов: протоколы-скрипты, шаблоны отчётов как код | низкие | фаза 1 (параллельно) |
| **D. Out-of-process** | Плагин в отдельном процессе/через IPC для не доверенных | высокие (сериализация numpy-кадров) | опц., фаза 3 |

### 3.4 Есть ли выгода — и какая

1. **Регуляторное разделение (главный аргумент).** Решение #331 разделяет «клинический путь» и
   «research-инструмент». Плагины = чистый способ **заморозить сертифицируемое ядро** (ASE-измерения,
   устоявшиеся расчёты) и поставлять **исследовательские/экспериментальные модули** (новые ИИ-модели,
   novel strain-варианты, экспериментальная гемодинамика) как opt-in. Без плагинов такое разделение
   упирается в форки.
2. **Вендор-специфичные адаптеры.** Квирки производители УЗ-систем (калибровка, парсинг) инкапсулируются
   в плагин, ядро не раздувается. `vendor_profiles` уже к этому ведёт.
3. **Сообщество / контрибьюция.** CONTRIBUTING прямо хочет «new measurement tools, AI models,
   reference DBs». Плагин-система снижает барьер и держит ядро стройным (не плодит #if-ы).
4. **Гибкость развёртывания.** Больнице нужен свой шаблон отчёта / свой HL7-фид / свой EHR —
   поставляется плагином, а не форком.
5. **Скорость итераций.** Плагин обновляется независимо от монолитного релиза.

### 3.5 Риски и митигация (сводно)

- API-stability → semver + deprecation policy + явный `PluginAPI` version.
- Безопасность in-process → подписанные плагины, allowlist, отключение в Presenter по умолчанию.
- Архитектурные инварианты → плагин цепляется только к domain-портам/`sonoforge.ext`, проверяется
  тем же `check_layer_directions`.
- Тестовые гейты → плагин несёт свои тесты; CI проверяет контракт публичного API.
- Presenter/PyInstaller → plugin-loader как хук + опц. внешняя папка плагинов.

### 3.6 Рекомендованный поэтапный план

- **Фаза 0 (уже частично):** выделить публичный `sonoforge.ext` из существующих реестров
  (calculators, measurement_catalog, study_profiles, vendor_profiles, ports).
- **Фаза 1:** официальный контракт плагина для **самых дешёвых и ценных** точек — Калькуляторы,
  Инструменты-измерения, Источники справочных данных, Шаблоны отчётов, Вендор-профили, и
  **Workflow/Recipe-скрипты**.
- **Фаза 2:** опциональный внешний загрузчик через entry-points + UI-менеджер плагинов
  (вкл/выкл, версия, подпись).
- **Фаза 3 (опц.):** out-of-process/sandbox для недоверенных плагинов.

Это **не требует переписывания**: вы формализуете существующие швы и добавляете обнаружение, а не
меняете ядро. И это напрямую поддерживает стратегию #331 (клиника vs research) и roadmap-решение
«не планировать веб/плагины как монолит» — плагины здесь не противоречат, а усиливают чистую
архитектуру.

## 4. Заключение и следующие шаги

SonoForge — редкий open-source проект, который уже сопоставим с младшими коммерческими рабочими

## Дополнение (по экспертной обратной связи, 2026-11-20)

### А. ЭКГ-независимая фазовая сегментация и Myocardial Work **без ЭКГ**

**Проблема пользователя (некоторые УЗ-системы и аналоги):** полоса ЭКГ вшита в пиксели кадра, DICOM-теги
`TriggerTime`/(0018,1096)/(0042,0010) отсутствуют → внешнюю ЭКГ использовать нельзя, а качественных
исследований (PLAX/SAX/A4C/A3C/A2C) много. Следствие: STE нельзя привязать к фазе → нельзя ни
валидировать, ни калибровать, ни считать strain ЛП/ПЖ, ни Myocardial Work.

**Что есть в коде уже сейчас (проверено):**
- `domain/services/cardiac_cycle_detector.py` — *«Cardiac cycle detection without ECG: FFT-based HR and
  ED/ES auto-detection»* по средней интенсивности миокарда во времени.
- `domain/services/cine_phase_image_signals.py` — image-прокси фазы (dark-pool area, intensity, motion)
  с компенсацией переменного гейна.
- `ecg_ed_es_mapper.py`, `ecg_rpeak_detector.py` — путь ЭКГ, когда теги есть.

То есть фундамент ЭКГ-независимого гейтирования **уже заложен**; он вторичен и недоделан до
надёжного первичного пути. Правильный план — **повысить image-based гейтирование до первичного**
для loops без ЭКГ и сделать его гибридным (ЭКГ, если теги есть; иначе — кадр).

**Как это решает остальное:**
1. *Валидация/калибровка STE* — по извлечённой фазе φ(t) можно привязать трекинг к ED/ES, считать
   метрики качества и сравнивать с золотым стандартом.
2. *Strain ЛП и ПЖ* — те же view (A4C/A2C для ЛП, RV-focused для ПЖ) трекаются с фазовой привязкой
   поверх того же кадра; отдельной ЭКГ не требуют.
3. **Myocardial Work без ЭКГ — реально.** MW строится из: (а) кривых strain (из STE, без ЭКГ) +
   (б) **манжетного АД** (SBP/DBP — одно число, вводит пользователь/берётся из протокола) + (в)
   **событий клапанов**, которые извлекаются **из изображения** (MVc — старт систолического движения
   кольца/восходящий участок strain; AVc — конец систолы = мин площади полости/пик производной
   strain; MVo — пик наполнения; AVo — старт изгнания). Шаблон нормированной кривой давления ЛЖ
   «натягивается» на эти 4 события; ЧСС берётся из длительности цикла. Именно так работает
   image-based MW (и то, что пользователь видел в одной из коммерческих систем). ЭКГ давала только тайминг — его заменяет
   image-derived тайминг. → Блокер MW — **не** отсутствие ЭКГ, а (а) качественный strain и (б)
   image-derived тайминг клапанов + манжетное АД.
4. *Немедленная митигация:* вшитая полоса ЭКГ обычно — фиксированная нижняя полоса кадра; её можно
   **авто-обрезать/исключить из ROI**, чтобы она не портила optical flow и STE-трекинг.

**Предлагаемое решение (исследовательское, но осуществимое офлайн):** обучить **learned cardiac
phase field φ(t)∈[0,1)** — энкодер, выдающий непрерывную фазу каждого кадра, обученный
**самоконтролируемо на периодичности** неразмеченных клипов (никакой ЭКГ и никакой разметки не
нужно даже для обучения). Это делает гейтирование первичным, точным и вендор-независимым.

### Б. О границах текущей ИИ-сегментации (EchoNet)

Сбалансированный ответ на скепсис пользователя:
- **EchoNet-Dynamic объективно неплох *в своей нише*** — A4C, взрослые, стандартное качество,
  сопоставимые популяции. Dice LV ~0.9+, корреляция EF высокая. Для рутинного A4C он «очень неплох».
- **Но в SonoForge он эффективно A4C-only** (подтверждено: `view_hint="A4C"` везде, логика
  annulus/apex — под A4C; A2C-авто в ROADMAP отложено). Для биplane (A2C) нужна **отдельная модель
  или transfer**. На разных УЗ-системах разных производителей, на плохом качестве, атипичной анатомии,
  контрасте, ТЕЕ — обобщение слабее, и эксперт-сонограф видит сбои, которые EchoNet пропускает.
- **Вывод:** интуиция «нужна разметка большого числа исследований» **верна для широты** (мультивью +
  мультивендор + робастность к качеству), но **не для стандартного A4C**. Поэтому:
  - не переписывать модель с нуля, а держать EchoNet как *proposal-движок для A4C* + существующий
    гибридный refine (`active_contour_refine`, `temporal_fusion`, `stepped_border_refine`), который уже
    компенсирует слабости;
  - добавить **A2C-модель** (transfer) и сделать view-rec **до/вместе** с сегментацией, чтобы
    Auto-EF не брал не тот вид/модель;
  - разметку собирать **локально на машине пользователя** через active-learning (см. раздел В ниже) —
    без выхода PHI в облако.

### В. Действительно новые / исследовательские идеи (фантазия, часть 2)

> Эти идеи — не «давно применяемые, просто не внедрено», а frontier, который *естественно ложится*
> на офлайн/open-source/исследовательско-клинический профиль SonoForge и на решение #331
> (клиника ↔ research). Помечено: [R] research-grade, но осуществимо офлайн; [I] инкрементально.

1. **[R] Learned cardiac phase field φ(t) на самоконтроле по периодичности** — первичный ЭКГ-независимый
   гейтинг (см. раздел А). Бьёт главную боль пользователя.
2. **[R] Privacy-preserving few-shot «echo foundation model»** — лёгкий vision-энкодер (masked temporal
   autoencoder), дообучаемый **на собственных неразмеченных клипах пользователя на его же ПК**;
   крошечные fine-tune для view-rec/сегментации/качества/гейтинга. Решает «нужно много разметки» **без
   облака и без утечки PHI**. Идеально под офлайн-ДНК проекта.
3. **[R] On-device active learning / «персонализированный ИИ»** — приложение помечает low-confidence
   сегментации, сонограф 1 кликом правит, правки копятся локально, модель **дообучается за ночь на
   машине пользователя**. Персональный, офлайн, приватный. Подключается к реестру моделей-плагинов.
4. **[R] Федеративная лёгкая модель эхо** — сайты учат локально, шлют только дельты градиентов (без
   PHI) на хаб, который усредняет. Приватно-сохранённая общественная модель. Амбициозно, но на 100%
   в духе open-source медицины.
5. **[R] «Консистентность / физический валидатор»** — перекрёстная проверка всех производных индексов
   (EF ↔ GLS ↔ объёмы ↔ MW) на физиологическую правдоподобность; несогласованность = сигнал об ошибке
   трекинга/измерения **или** о конкретной патологии. Самопроверяющееся эхо. Ново.
6. **[I/R] Reader машины-HUD** — CV-модель читает вшитый в кадр интерфейс УЗ-аппарата (depth, gain,
   TGC, подпись вида «A4C») → автозаполнение вида **и калибровки** (восстановление масштаба глубины!).
   Резко снижает ошибки ручной калибровки и помогает view-rec. Практично и ново.
7. **[R] Uncertainty-native / вероятностная отчётность** — каждое измерение несёт confidence, который
   пропагируется в протокол и в флаг «уверенности решения» («этот EF — высокая неопределённость →
   ретест»). Байесовские измерения. Ново для эхо.
8. **[R] Долготовая карта эволюции / раннее предупреждение** — временной граф всех индексов по истории
   пациента с детекцией аномалий («ЛВИЭ −8% против ожидаемой вариабельности»). Шаг дальше diff-view.
9. **[R] Zero-label синтетический эхо-харнесс регресс-тестов** — дифференцируемый фантом сердца,
   генерирующий физически правдоподобные клипы для **непрерывной валидации STE/MW/сегментации в CI без
   PHI**. Ложится на существующую инфраструктуру gold/bench. По-настоящему новый подход к тестированию.
10. **[R] Офлайн-ассистент пре-чтения на локальном LLM** — маленькая модель **локально** черновикует
    заключение из измерений, проверяет полноту «complete study» по ASE и предлагает недостающие виды
    («A2C требуется, не найден»). Полностью офлайн. Ново для отчётности эхо.
11. **[I] Стерильное мультимодальное управление** — речь + ножная педаль + простой жест/eye-gaze для
    hands-free в кабинете (сонограф в перчатках). Связано с command palette.
12. **[I] Второе мнение без облака** — зашифрованные «study capsules» + P2P (WebRTC/local) консультация
    эксперта. Офлайн-дружественно.
13. **[R] Цифровой двойник механики миокарда** — объединение STE+MW+объёмов в простую механическую
    модель, предсказывающую ожидаемый strain из объёмов (и наоборот), подсвечивающую физио-несогласованные
    результаты. Родственно п.5, но как digital twin.
14. **[R] Адаптивная физика УЗ-изображения** — использование восстановленных параметров съёмки для
    улучшения/нормализации кадра (gain/depth/тканеспецифично), улучшая downstream-ИИ.

### Г. Детализация UI-идей (п.4 исходного запроса)

**AI co-pilot quality overlay.** Всегда включённый ненавязчивый индикатор в углу вьюера (кольцо/бейдж)
или тонкая цветная рамка, отражающий адекватность съёмки/качество в реальном времени. Источники:
image-метрики (SNR, детекция выпадения sector'а, off-axis/неистинный apex, пережатый gain, неподходящая
глубина, foreshortening — ЛЖ не вся в кадре), уверенность STE-трекинга (NCC/coverage), уверенность
гейтинга («слабая ЭКГ / гейтинг по кадру»). Не прерывает работу, а *подсказывает* («глубина мала —
увеличь»). По клику раскрывается в боковую панель-чеклист; связан с обучением и ASE-полнотой.

**Command palette.** Ctrl+Shift+P (как в VSCode) — центрированная строка нечёткого поиска. Набираете
любое действие: «Simpson biplane», «export PDF», «load from server», «toggle W/L», «A4C preset»,
«sign report», «switch study tab». Маппится на тот же контракт `action/view/phase/extra`, который уже
эмитит Measures-меню (D-09). Выгоды: скорость с клавиатуры, discoverability, единая точка для команд
плагинов. Реализация — ещё один реестр (`CommandRegistry`), согласованный с темой плагинов.

**Контекстно-адаптивная панель.** Текущая панель (`tool_panel_view`) уже фильтрует по профилю +
контексту (2D/M/Doppler/Vessels). Сделать её *адаптивной*: она смотрит, что уже измерено в исследовании
и что требует ASE «complete study», и (а) подсвечивает/поднимает **следующее вероятное измерение**,
(б) гасит сделанное, (в) показывает прогресс («LV-квантификация 4/7»), (г) предлагает **следующий вид
для захвата**, если данных не хватает. Stateful-панель, «знающая, где вы находитесь».

**Diff-view визитов.** Два исследования одного пациента (подтверждение по `PatientID`+issuer, как в
README) бок о бок; поверх текущего клипа — «призрак» эндокардиального контура ЛЖ прошлого визита +
дельта-ридоут (ΔLVEF, ΔLAVi) и спарклайн индекса во времени. Для динамики (кардиотоксичность онкологии,
пост-ИМ, ответ на CRT). Опирается на существующие study comparison + модели контуров; расширяется в
«карту эволюции» (п.8 раздела В).

### Д. Безопасность (п.5) — согласовано, делать обязательно
at-rest шифрование storage/кэша/экспортов · квалифицированная ЭП через плагин (eIDAS/УКЭП поверх
`SignerPort`) · деперсонализация по DICOM PS3.15 · политика retention/consent с авто-экспирацией кэша.
