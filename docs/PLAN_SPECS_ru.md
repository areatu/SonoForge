## А. Ядро эхокардиографии (1–14) — подробные спеки

### 1. Auto View Recognition
- **Назначение:** автоматически определять вид клипа (A4C/A2C/PLAX/SAX/A3C/PSAX, опц. TEE) и
  подставлять `StudyProfile` + фильтр панели.
- **Объём:** ONNX-классификатор на опорных кадрах; метка вида + `confidence`; UI-подсказка при загрузке.
- **Ключевые компоненты:** `domain/services/view_recognition.py` (чистый домен) + порт `IViewRecognizer`;
  инфраструктурный ONNX-адаптер (переиспользует `infrastructure/onnx_engine.py`); обучение (transfer с
  ImageNet или энкодера EchoNet) → `models/`; датасет из метаданных (`ProtocolName`, view-теги) + разметка gold store.
- **Зависимости:** `onnx_engine`; ROI-кроп (`domain/services/segment_roi.py`).
- **Критерии приёмки:** accuracy ≥ 0.95 на val; confidence отображается; ручное переопределение работает; тесты + bench.
- **Хронология (шаги):**
  1. *Данные* — собрать корпус (метаданные + ручные метки из gold store/`for_pero`), train/val split, аугментации.
  2. *Модель* — baseline CNN (EfficientNet-B0 / small ViT), transfer-learning, экспорт ONNX, оценка на val.
  3. *Интеграция (домен)* — `view_recognition.py` + `IViewRecognizer`, без Qt.
  4. *UI* — хук при загрузке серии → предложить профиль+вид, бейдж confidence, override, сохранение выбора.
  5. *Качество* — unit + bench (точность/задержка), интеграция в CI lint/typecheck.

### 2. One-click Auto-EF
- **Назначение:** один клик → EDV/ESV/EF (biplane Simpson) с ручной правкой.
- **Объём:** оркестрация view-rec + A4C/A2C-сегментация + temporal fusion + biplane Simpson; кнопка + карточка результата.
- **Ключевые компоненты:** `application/services/auto_ef_pipeline.py`; переиспользует `segmentation_service`
  (нужна **A2C-модель**), `lv_temporal_fusion`, `chamber_simpson` (biplane), `result_provenance`.
- **Зависимости:** п.1 (view-rec); A2C-модель сегментации (см. примечание); temporal fusion.
- **Примечание:** текущая сегментация `view_hint="A4C"` (A4C-only); для biplane нужна A2C-модель (transfer) — отдельная подзадача внутри п.2.
- **Критерии приёмки:** EF в пределах ±5% от ручного на val; редактирование контуров работает; provenance сохранён.
- **Хронология (шаги):**
  1. *A2C-модель* — дообучить/transfer A2C-сегментацию, зарегистрировать в `segmentation_service`.
  2. *Пайплайн* — detect views (п.1) → segment A4C+A2C → temporal fusion → biplane Simpson → EF.
  3. *UI* — кнопка «Auto EF» + результат с редактированием; пересчёт при правке.
  4. *Валидация* — сравнение с ручным золотым стандартом (gold store), метрики, тесты.

### 3. ЭКГ-независимая фазовая сегментация (learned phase field)
- **Назначение:** непрерывная фаза φ(t)∈[0,1) на кадр без ЭКГ, для ED/ES/ЧСС и всех downstream.
- **Объём:** self-supervised phase model на периодичности; либо pragmatic: комбинация image-сигналов
  (площадь полости из seg / интенсивность миокарда / optical-flow) + лёгкий регрессор.
- **Ключевые компоненты:** `domain/services/phase_field.py` (опирается на `cine_phase_image_signals.py`,
  `cardiac_cycle_detector.py`); обучение self-supervised (contrastive/temporal periodicity) на неразмеченных
  клипах; кардиальный сигнал из LV-маски если есть.
- **Зависимости:** п.4 (primary gating routing); существующие image-сигналы.
- **Критерии приёмки:** φ(t) монотонна внутри цикла; ED/ES совпадают с ЭКГ-разметкой (где есть) в ±1 кадр; confidence метрика.
- **Хронология (шаги):**
  1. *Сигналы* — извлечь кандидатов (cavity area из LV-seg, myocardial intensity FFT, optical-flow magnitude), нормализация.
  2. *Модель* — self-supervised phase encoder (periodicity loss), экспорт ONNX.
  3. *Вывод* — φ(t) на клип; детект ED (max cavity)/ES (min cavity); confidence.
  4. *Мост* — адаптер к `cardiac_cycle_service` / `ecg_ed_es_mapper` (image-source).
  5. *Тесты* — invariant-тесты (сдвиг фазы, инверсия не меняет strain), bench.

### 4. Image-based гейтинг как первичный путь
- **Назначение:** единый источник фазы (ЭКГ | image | hybrid); предпочтение ЭКГ при валидных тегах.
- **Объём:** абстракция `PhaseSource` + маршрутизация; унифицированные ED/ES/HR для STE/strain/диастологии/MW.
- **Ключевые компоненты:** `domain/services/phase_source.py` (порт), routing в `cardiac_cycle_service`; UI-индикатор источника.
- **Зависимости:** п.3; `ecg_*` модули.
- **Критерии приёмки:** переключение источников прозрачно; все потребители получают единый контракт; индикатор источника в UI.
- **Хронология (шаги):**
  1. *Абстракция* — `PhaseSource` (ecg | image | hybrid), общий выход ED/ES/HR/confidence.
  2. *Маршрутизация* — при валидных ЭКГ-тегах → ecg, иначе image (п.3).
  3. *Потребители* — STE/strain/диастология/MW берут фазу из `PhaseSource`.
  4. *UI* — индикатор «гейтинг: ЭКГ/кадр», возможность force-source.

### 5. Авто-обрезка вшитой полосы ЭКГ
- **Назначение:** исключить фиксированную полосу ЭКГ из ROI/трекинга.
- **Объём:** детект нижней полосы (шаблон/край/сигнатура), исключение из STE ROI и optical flow; override + persist.
- **Ключевые компоненты:** `domain/services/burned_ecg_mask.py`; интеграция в ROI сегментации + маску `speckle_tracking`.
- **Зависимости:** нет жёстких; желательно п.3/4.
- **Критерии приёмки:** полоса исключена (IoU с разметкой ≥0.9 на тестах); override работает; маска сохраняется.
- **Хронология (шаги):**
  1. *Детект* — эвристика (фикс. нижняя зона, цветовая/текстовая сигнатура) + опц. лёгкая модель.
  2. *Применение* — маска вычитается из ROI сегментации и STE-трекинга.
  3. *UI/persist* — переключатель, ручная правка, сохранение в метаданные исследования.

### 6. Strain ЛП (LA strain)
- **Назначение:** LA strain (reservoir/conduit/booster) поверх A4C/A2C.
- **Объём:** трекинг контура ЛП по циклу с фазовой привязкой; метрики strain; интеграция в strain window + отчёт.
- **Ключевые компоненты:** переиспользует `la_segmentation_service` (уже есть) + `speckle_tracking` (новый трекер ЛП) + `strain_computation`; фаза из п.3/4.
- **Зависимости:** п.3/4 (фаза), `la_segmentation_service`.
- **Критерии приёмки:** кривые strain ЛП; значения в overlay/отчёте; согласие с референсами (gold).
- **Хронология (шаги):**
  1. *Маски ЛП* — уверенные LA-маски на энд-систолических и промежуточных кадрах.
  2. *Трекинг* — адаптировать `speckle_tracking` под контур ЛП, привязка к фазе.
  3. *Метрики* — reservoir/conduit/booster strain.
  4. *UI/отчёт* — кривые/сводка ЛП, секция отчёта.

### 7. Strain ПЖ (RV strain)
- **Назначение:** RV strain (free-wall GLS) на RV-focused видах.
- **Объём:** контур ПЖ (free wall) + трекинг + GLS; summary.
- **Ключевые компоненты:** новый contour model (`domain/models/speckle.py` расширить), RV-focused view (нужен view-rec п.1 или ручной), `strain_computation`.
- **Зависимости:** п.1 (вид ПЖ) или ручной выбор; п.3/4.
- **Критерии приёмки:** RV free-wall strain; интеграция в сводную таблицу; тесты.
- **Хронология (шаги):**
  1. *Вид* — детект RV-focused (п.1) или ручной выбор.
  2. *Контур* — RV free-wall model + трекинг.
  3. *Метрики/UI* — RV GLS, сводка, отчёт.

### 8. Послойный стрэйн (endo/mid/epi)
- **Назначение:** strain по слоям endo/mid/epi.
- **Объём:** многослойные маски ЛЖ; per-layer трекинг; отчётность.
- **Ключевые компоненты:** расширить LV seg на слои (толщина стенки), `speckle_tracking` per-layer.
- **Зависимости:** базовая LV seg + п.3/4.
- **Критерии приёмки:** кривые по слоям; выбор слоя в UI (селектор уже есть); тесты.
- **Хронология (шаги):**
  1. *Маски* — эндо/эпи контуры ЛЖ (mid интерполяция).
  2. *Трекинг* — per-layer kernels.
  3. *UI/отчёт* — вывод по слоям.

### 9. Myocardial Work без ЭКГ
- **Назначение:** pressure-strain петли и GWI/GCW/GWW/GWE без ЭКГ.
- **Объём:** strain (базовый + п.6/7) + манжетное АД + image-derived тайминг клапанов → P(t) → MW.
- **Ключевые компоненты:** `domain/services/myocardial_work.py` (чистый домен); valve-event детектор из
  фазы/аннулярного движения; cuff BP ввод из отчёта/ручной.
- **Зависимости:** п.3/4 (фаза → valve events), strain (базовый + п.6/7).
- **Критерии приёмки:** MW совпадает с референсом (где есть) в допуске; GWI/GCW/GWW/GWE в отчёте.
- **Хронология (шаги):**
  1. *Тайминг клапанов* — MVc/AVo/AVc/MVo из φ(t) + движения кольца/морфологии strain.
  2. *P(t)* — шаблон нормированного давления ЛЖ, «натянутый» на 4 события, амплитуда из SBP/DBP.
  3. *MW* — −∫P·dε; агрегаты GWI/GCW/GWW/GWE.
  4. *UI/отчёт* — петли давление–деформация, секция MW.

### 10. Диастология «под ключ»
- **Назначение:** авто-извлечение E/A, e', E/e', TR, PV, IVRT + авто-градация с indeterminate.
- **Объём:** пайплайн извлечения из Doppler/TDI → панель → градация.
- **Ключевые компоненты:** переиспользует `doppler_*` сервисы (envelope, calibration, repeats), `diastology_grade.py`;
  новый orchestrator `diastology_workflow.py`.
- **Зависимости:** Doppler extractors (есть), п.3/4 (фаза для e').
- **Критерии приёмки:** авто-заполнение полей; корректная градация норма/нарушение/indeterminate; секция отчёта.
- **Хронология (шаги):**
  1. *Извлечение* — E/A из mitral inflow, e'/a' из TDI, TR velocity, PV, IVRT (через Doppler-сервисы).
  2. *Панель* — агрегация + авто-градация (`diastology_grade`), обработка indeterminate.
  3. *Отчёт* — секция диастологии с выводами.

- **Хронология (шаги):**

## Б. DICOM / радиологические возможности (15–19)

### 15. DICOM SR чтение/импорт
- **Назначение:** парсинг пришедшего Structured Report (TID 5200) в доменную модель; импорт измерений/заключений.
- **Ключевые компоненты:** `domain/services/interop_sr.py` (есть content model) + `infrastructure/dicom_sr_reader.py` (новый парсер SR); маппинг в `measurements`/`report`.
- **Зависимости:** существующий SR-контент-модель (#625 outbound).
- **Приёмка:** корректный парсинг репрезентативных SR; импорт в overlay/отчёт; round-trip тесты.

### 16. Graphic Annotation Presentation State (GSPS)
- **Назначение:** сохранение калиперов/контуров/аннотаций как DICOM-объекта (переносимость между системами).
- **Ключевые компоненты:** `domain/models/annotation_state.py` (сериализуемая модель) + `infrastructure/dicom_gsps.py` (encapsulated/GSPS writer); связь с viewer overlays.
- **Зависимости:** существующие overlay/контуры.
- **Приёмка:** экспорт/импорт GSPS; аннотации восстанавливаются на том же кадре; тесты.

### 17. Hanging protocols
- **Назначение:** авто-раскладка серий по правилам modality/series/view.
- **Ключевые компоненты:** `domain/services/hanging_protocol.py` (rule engine на метаданных) + UI-применение к layout/tabs.
- **Зависимости:** layout engine, мета-парсер.
- **Приёмка:** правила применяются при открытии study; редактор правил; тесты.

### 18. DICOMDIR / CD-DVD импорт
- **Назначение:** чтение носителей со структурой DICOMDIR, массовый импорт.
- **Ключевые компоненты:** `infrastructure/dicomdir_reader.py` (парсер DICOMDIR) + интеграция в `IStudyScanner`.
- **Зависимости:** DICOM session/scan.
- **Приёмка:** импорт с CD воспроизводит иерархию; тесты на фикстурах.

### 19. Вторичный захват (secondary capture)
- **Назначение:** экспорт текущего вида как DICOM Secondary Capture с аннотациями.
- **Ключевые компоненты:** `infrastructure/dicom_secondary_capture.py`; переиспользует рендер кадра + overlay.
- **Зависимости:** frame export, overlay serialization.
- **Приёмка:** SC открывается в стороннем вьюере с аннотациями; тесты.

## В. Workflow / интеграция / отчётность (20–26)

### 20. Входящий MWL + MPPS (#626)
- **Назначение:** приём worklist из HIS/RIS и статусов выполнения процедуры.
- **Ключевые компоненты:** `domain/ports.py` `IWorklistSink` (есть заглушка) + `infrastructure/mwl_listener.py` (MLLP/MLLP+TLS), `mpps_scp.py`; UI worklist browser.
- **Зависимости:** interop HL7/SCP инфраструктура (#625).
- **Приёмка:** worklist отображается; MPPS шлёт статусы; тесты.

### 21. Worksheet → preliminary → final
- **Назначение:** обязательные поля, handoff-верификация лаборатории, сборка черновика из структурированных измерений.
- **Ключевые компоненты:** расширение lifecycle (`report_signature.py` draft/signed/amended) → worksheet contract; UI этапов; проверка заполненности.
- **Зависимости:** report engine, роли (#623).
- **Приёмка:** этапы preliminary/final с верификацией; блокировка неполных полей; тесты.

### 22. Голосовой ввод / диктовка
- **Назначение:** STT-ввод полей протокола/заметок (локально, офлайн-движок).
- **Ключевые компоненты:** `application/services/speech_input.py` (локальный STT-движок, без облака) + UI-поля с микрофоном; опц. hotkey.
- **Зависимости:** офлайн STT-модель (plugin/внешняя).
- **Приёмка:** диктовка заполняет поля; worklist-фильтр; тесты на моках.

### 23. Интеграция с заказами/работой
- **Назначение:** связь с order-системой (через MWL/ORM), контекст направления.
- **Ключевые компоненты:** мост MWL/ORM → `StudyMetadata` (order context); UI-контекст направления.
- **Зависимости:** п.20.
- **Приёмка:** контекст направления виден; тесты.

### 24. Популяционная аналитика лаборатории + QC
- **Назначение:** агрегаты по когорте пациентов, метрики качества лабы.
- **Ключевые компоненты:** `application/services/lab_analytics.py` (чтение measurement store/индекса) + UI-дашборд; QC-метрики.
- **Зависимости:** п.26 (индекс архива).
- **Приёмка:** агрегаты/тренды по лабе; экспорт; тесты.

### 25. Пакетная обработка (batch pipeline)
- **Назначение:** прогон папки сконфигурированным конвейером (seg → Simpson → strain) с сводным отчётом.

## Д. Исследовательские / frontier-идеи (36–48)

### 36. Echo foundation model
- **Назначение:** self-supervised vision-энкодер, дообучаемый на собственных неразмеченных клипах on-device; few-shot для view-rec/сегментации/качества.
- **Ключевые компоненты:** `domain/services/foundation_model.py` (masked temporal autoencoder) + on-device fine-tune; переиспользуется п.1/сегментацией.
- **Зависимости:** вычислительные ресурсы локальной машины; п.1.
- **Приёмка:** предобученный энкодер улучшает downstream few-shot; тесты на фикстурах.

### 37. On-device active learning
- **Назначение:** флаг low-confidence сегментаций, 1-клик-правка, ночное дообучение локально.
- **Ключевые компоненты:** confidence-сигнал из сегментации + UI правки + локальный fine-tune job (offline).
- **Зависимости:** сегментация, п.36 (опц.).
- **Приёмка:** накопление правок; дообучение без выхода PHI; тесты.

### 38. Федеративная модель
- **Назначение:** локальное обучение, обмен только дельтами градиентов (без PHI) через хаб.
- **Ключевые компоненты:** `application/services/federated.py` (агрегация дельт) + протокол обмена; opt-in.
- **Зависимости:** п.37.
- **Приёмка:** агрегация дельт улучшает модель; ни одного PHI-поля в обмене; тесты.

### 39. «Физический валидатор» (consistency engine)
- **Назначение:** перекрёстная проверка EF↔GLS↔объёмы↔MW на физиологическую правдоподобность.
- **Ключевые компоненты:** `domain/services/consistency_validator.py` (правила согласованности) + UI-флаги.
- **Зависимости:** базовые расчёты, п.9.
- **Приёмка:** несогласованности помечаются; тесты на синтетических case'ах.

### 40. Reader машины-HUD
- **Назначение:** CV-чтение вшитого UI аппарата (depth/gain/подпись вида) → авто-вид и калибровка.
- **Ключевые компоненты:** `domain/services/machine_hud_reader.py` (OCR/CV вшитых меток) + маппинг в view/калибровку.
- **Зависимости:** п.1 (view), auto-calibration.
- **Приёмка:** извлечение depth/label; авто-калибровка; тесты.

### 41. Uncertainty-native отчётность
- **Назначение:** каждое измерение несёт confidence, пропагируется в протокол и флаг «ретест».
- **Ключевые компоненты:** расширение `result_provenance`/`measurements` (confidence) + UI/отчёт.
- **Зависимости:** confidence из сегментации/измерений.
- **Приёмка:** confidence сквозь отчёт; флаг низкой уверенности; тесты.

### 42. Долготовая карта эволюции / раннее предупреждение
- **Назначение:** граф индексов по истории с детекцией аномалий.
- **Ключевые компоненты:** поверх п.26 + `domain/services/anomaly_detection.py`.
- **Зависимости:** п.26, п.30.
- **Приёмка:** аномалии подсвечиваются; тесты.

### 43. Zero-label синтетический эхо-харнесс
- **Назначение:** дифференцируемый фантом для CI-валидации STE/MW/сегментации без PHI.
- **Ключевые компоненты:** `bench/synthetic_echo.py` (генератор физически правдоподобных клипов) + regression-тесты.
- **Зависимости:** существующий bench/gold инфраструктура.
- **Приёмка:** тесты STE/MW на синтетике в CI; тесты.

### 44. Офлайн-LLM пре-чтение
- **Назначение:** локальная модель черновикует заключение, проверяет ASE-полноту, предлагает недостающие виды.
- **Ключевые компоненты:** `application/services/llm_preadvice.py` (локальный LLM, без облака) + prompt по измерениям/ASE.

- **Приёмка:** черновик + список недостающих видов; тесты на моках.

### 45. Стерильное мультимодальное управление
- **Назначение:** речь + педаль + жест/eye-gaze для hands-free в кабинете.
- **Ключевые компоненты:** интеграция п.22 (речь) + педаль/жест-источники → команды (п.28).
- **Зависимости:** п.22, п.28.

### 46. Второе мнение без облака
- **Назначение:** P2P-консультация эксперта поверх encrypted study capsule.

- **Зависимости:** п.35, п.49.
- **Приёмка:** передача/приём капсулы; тесты.

### 47. Цифровой двойник механики миокарда
- **Назначение:** объединение STE+MW+объёмов в механическую модель, подсветка физио-несогласованных результатов.
- **Ключевые компоненты:** `domain/services/myo_digital_twin.py` (предсказание ожидаемого strain из объёмов и наоборот).

### 48. Адаптивная физика УЗ-изображения
