# Базовая линия допплера без DICOM-тегов (Samsung)

## Проблема

На GE / Philips / Siemens нулевая линия берётся из тегов региона:

```
baseline_y = RegionLocationMinY0 + ReferencePixelY0
```

Samsung RS85 размечает PW/CW как `RegionSpatialFormat=1` (2D) с непригодными
`PhysicalDeltaX/Y`, а `ReferencePixelY0` либо отсутствует, либо равен `0`.
`SamsungProfile.compute_baseline` в этом случае возвращает `frame_height/2`
с `confidence=0.0` (`src/.../vendor_profiles/samsung.py`), и дальше
срабатывают пиксельные fallback-и.

Сегодня эти fallback-и — набор независимых одиночных эвристик, каждая из
которых ломается на своём типе кадра:

| место | эвристика | когда врёт |
|---|---|---|
| `doppler_baseline.detect_baseline_line_y` | тонкая (≤8 px) однородная полоса на всю ширину ROI | спектр нарисован поверх линии → покрытие падает ниже порога `max(0.5, 0.75·peak)` |
| `doppler_baseline.detect_baseline_y` (fallback) | самая тёмная строка внутри выпуклой оболочки сигнала | попадает в wall-filter notch или в зазор между панелями |
| `vendor_calibration_bridge` (ветка Samsung tick) | «median plateau» + бонус за близость к краю ROI, штраф −50 за зоны B-mode/линейки | на dual-spectrum кадрах плато даёт край B-режима; коэффициенты (2.0 / 5.0 / −50 / 0.15 / 0.95) подобраны под конкретные файлы |
| `dicom_doppler_calibration._detect_baseline_fallback` | самая яркая строка (argmax сглаженного профиля) | выигрывает линейка времени или яркая огибающая |

Общий дефект: **побеждает одна эвристика, остальные не участвуют**, и
результат отдаётся наружу без оценки достоверности — калибровка молча
применяется даже когда линия найдена неправильно.

## Предложение: слияние независимых признаков (evidence fusion)

Вместо «первая сработавшая эвристика выигрывает» — несколько дешёвых
независимых признаков голосуют за строку, голоса размазываются гауссианой
(σ ≈ 2 px) и суммируются с весами; побеждает argmax, наружу отдаётся
**оценка + confidence + разбивка по признакам**.

Реализация-прототип: `src/echo_personal_tool/domain/services/doppler_baseline_evidence.py`
(тесты — `tests/unit/test_doppler_baseline_evidence.py`, 15 шт., зелёные).

### Признаки

1. **`line` (вес 1.0)** — существующий `detect_baseline_line_y`. Переиспользован
   как *один голос*, а не как единоличный победитель. Там, где вендор рисует
   сплошную нулевую линию (Philips), он по-прежнему доминирует.

2. **`foot` (вес 1.0) — гистограмма «пяток» огибающей. Ключевой признак для Samsung.**
   Спектральный поток всегда *начинается* от нулевой скорости: для каждого
   столбца `c` сигнал занимает интервал `[a_c, b_c]`, и одна из этих границ
   лежит на базовой линии почти во всех столбцах. Гистограмма `a_c`/`b_c` даёт
   резкий пик на базовой линии, тогда как внешняя граница (огибающая) размазана
   по всей форме волны. Признак **не требует, чтобы линия была нарисована**,
   и работает и на однонаправленном, и на двунаправленном спектре.
   Сила признака = контраст пика к остальному профилю + доля покрытых столбцов;
   уточнение до субпикселя — центр масс окрестности пика.

3. **`static` (вес 0.8) — временной признак (мультикадровый).**
   Базовая линия *нарисована прибором*, поэтому в пределах клипа она не
   меняется, а спектр мерцает от кадра к кадру. Строка с минимальной временной
   дисперсией среди строк, содержащих контент (чистый фон исключается) — это
   линия. Достаточно 5–10 кадров с шагом (например, каждый 5-й).
   Этот признак сейчас в коде вообще не используется, хотя данные есть.

4. **`grid` — лестница шкалы скоростей.** Горизонтальные линии сетки
   эквидистантны, и ноль — одна из них. Используется **только для «примагничивания»**
   итога (`snap_to_grid`, допуск 4 px), никогда не выбирает строку сам.
   Источник линий — уже существующий `detect_doppler_grid_lines`.

5. **`tag` (вес 0.4) — `ReferencePixelY0`, только слабый приор.**
   Принимается, лишь если попадает строго внутрь ROI (отступ 5% высоты), то есть
   самсунговский `0` отбрасывается. На GE/Philips корректный тег усиливает
   пиксельные признаки, но сам по себе (вес 0.4 против порога 0.5) уверенным
   решением не становится — это проверяется тестом
   `test_weak_tag_alone_cannot_be_confident`.

Ни один признак не является вендор-специфичным. Samsung просто опирается на
`foot`/`static`, потому что `line`/`tag` у него отсутствуют.

### Confidence

```
agreement     = голоса за победившую строку / суммарная масса голосов
evidence_mass = min(1, суммарная масса / (w_line + w_foot))
confidence    = 0.35·evidence_mass + 0.65·agreement·evidence_mass   (+0.05 если snap)
```

Смысл: один слабый признак не выглядит так же надёжно, как три согласных;
противоречащие признаки (`test_conflicting_cues_lower_confidence`) сбивают
confidence вместо того, чтобы молча выбрать один из них.

### Как встраивать

Пороговая политика вместо текущего «всегда что-то вернуть»:

| confidence | действие |
|---|---|
| ≥ 0.75 | применять автоматически |
| 0.5 – 0.75 | применять, но пометить калибровку как требующую проверки (значок в оверлее) |
| < 0.5 | не калибровать молча — предложить оператору поставить линию вручную (поток ручной калибровки уже есть: baseline → диалог скорости) |

Точки интеграции (по одной строке в каждой):

1. `SamsungProfile.compute_baseline` — при отсутствии/невалидности
   `ReferencePixelY0` и наличии `frame_pixels` вызывать `detect_baseline_robust`
   и возвращать `BaselineResult(baseline_y=est.y, confidence=est.confidence,
   source=est.source)`. `_compute_baseline_with_profile` уже проверяет
   `confidence >= 0.5` — семантика совпадает.
2. `vendor_calibration_bridge.try_parse_samsung_tick_calibration` — заменить блок
   «median plateau» (~90 строк с магическими 2.0 / 5.0 / −50 / 0.05 / 0.15 / 0.95)
   на вызов `detect_baseline_robust(arr, roi, grid_lines=detect_doppler_grid_lines(...))`.
3. `dicom_doppler_calibration` — цепочка «линия → тег → интенсивность» становится
   одним вызовом; `_detect_baseline_fallback` (argmax яркости) удаляется.
4. Прокинуть несколько кадров клипа в `frames=` там, где вызывающий код имеет
   доступ к серии (для признака `static`); при одном кадре всё работает без него.

### Что это даёт

* Samsung получает работающий признак (`foot`), не зависящий ни от тегов, ни от
  того, нарисована ли линия.
* Убираются ~4 расходящиеся реализации и их подогнанные под файлы константы.
* Появляется confidence → неверная калибровка перестаёт быть «молчаливой».
* На остальных вендорах поведение не меняется: `line` + `tag` совпадают, дают
  высокий agreement, и та же самая строка выигрывает.

### Проверка перед вливанием

Прототип пока валидирован только на синтетике. Нужно прогнать на реальных
кадрах: Samsung RS85 (`q111`, `q222`, dual-spectrum), Philips (`IM_0247`,
`IM_0252`, `IM_0254`) и GE — и сравнить `est.y` с текущим значением и с
разметкой оператора. `est.cues` содержит разбивку по признакам, поэтому
расхождения сразу видны в логе.
