- `fix(ui)`: окно strain не открывалось на клипах, декодирующихся в RGB (сообщение пользователя; STE LV).
  - Симптом: после трекинга ЛЖ (A4C) статусная строка «GLS: … | QC: … | NCC: …» появлялась вверху экрана, точки-ядра рисовались на viewer, а само окно strain не появлялось.
  - Причина: снимок обзора хранит ED-кадр «как есть» из cine; клипы ряда вендоров декодируются как RGB(A) — `(H, W, 3|4)`, а рендер миниатюры `_frame_to_qimage` жёстко требовал 2-D grayscale и бросал `ValueError`. Исключение обрывало `show_result` после отрисовки статуса и оверлея, но до `self.show()` — окно оставалось закрытым, всё остальное выглядело работающим.
  - Фикс: `_frame_to_qimage` приводит цветной кадр к grayscale (среднее по каналам) вместо отказа — миниатюре нужна только яркость; прочие некорректные формы по-прежнему падают шумно (неиспользуемый кадр не замалчивается).
  - Регрессия: e2e `show_result` на RGB-клипе открывает окно с отрендеренной миниатюрой (`test_strain_window`), контрольный серый путь остался, юнит `_frame_to_qimage` на 2-D / RGB / RGBA / некорректную форму (`test_ste_overview_screen`). Доказательство: offscreen-прогон полного пути (воркер → `_on_speckle_result_ready` → окно) на RGB-клипе с ЭКГ-волной — окно открыто, миниатюра 128×128.
