- `chore(tests)`: S1-04 (аудит 2026-10-22 §13) — храповик строгих `xfail`. **Поведение теста, не продукта:** не меняется ни один клинический расчёт и ни одно числовое обещание README/HELP. Проблемный тренд аудита P2-11 — `xfail` без `strict=True` превращает ожидаемый провал в вечно зелёный тест: в день, когда дефект исправлен, маркер перестаёт защищать что-либо, а суть по-прежнему пишет «expected failure». **Конфигурация.** В `[tool.pytest.ini_options]` добавлен `xfail_strict = true` — теперь строгость является дефолтом для любого будущего `@pytest.mark.xfail(reason=...)`, а не требует явной strict=True в каждом месте. **14 маркеров** в `tests/compat/` (12 в `test_windows_paths.py`, 2 в `test_display_server.py`) переведены с `strict=False` на `strict=True`. **Строгость вскрыла 7 истлевших маркеров** в `tests/compat/test_windows_paths.py`: они помечены как «поддержка Windows-pathов», а на Linux код их **проходит** — маркер зиял пустым. Маркеры удалены, тесты стали настоящими проверками реальной защиты (Cyrillic-имена/директории, смешанный шрифт, пробелы, trailing-пробелы, `instance_path` в стике gold). Оставшиеся 5 — `test_backslash_path_open`/`_decode`, `test_backslash_in_subdirectory`, `test_unc_path_read`/`_decode` — по-прежнему строго `xfail` на не-Windows: там провал реальный (backslash-разделитель и UNC-синтаксис — Windows-semantics). **Защита от возврата.** Новый `tests/unit/test_xfail_strict_ratchet.py` (4 логических случая) — храповик, который не дает откатиться: проверяет что `xfail_strict` не удалён из `pyproject.toml`, что ни один `pytest.mark.xfail` в `tests/` не обходит строгость (обход через явный `strict=False` ловится так же, как отсутствие `strict`), плюс два self-теста детектора. Инвентарь `_BASELINE` 9061 → **9065** (`not_gui` 5239 → 5243; `gui` 3822 и `gui_files` 199 без изменений — новый файл без GUI-маркеров). **Проверки.** `ruff check src tests` и `ruff format --check` — чисто (1018 файлов); новый храповик — 4 passed; negative control (временный файл с `xfail(reason=...)` без `strict`) откликался с точным `file:line`, затем удалён; `tests/compat/test_windows_paths.py` локально — `xxxxx.......` (5 строгих xfail + 7 пройденных), exit 0; `mypy` (2.4.0, locked) — без новых ошибок (4 ошибки в `infrastructure/orthanc_client.py`/`dimse_client.py` воспроизводятся и на чистом `HEAD` со сtashed-изменениями, то есть предсуществующие). **Что уже было до этого PR и остаётся:** ruff-гейт F821/F841 (`All checks passed!`) и coverage-ratchet в `ci.yml` (`coverage report --fail-under=80` общий, `--fail-under=88` для `domain/*`, measured baseline 82.65 % / 90.40 %) — оба на месте, поэтому этот PR закрывает оставшуюся «xfail» половину S1-04. `tests/compat/` не бегает в CI (требует `ECHO_COMPAT=1`), поэтому удаление 7 маркеров не меняет CI-инвентарь. Вне объёма: `update_pytest_baseline.py --check` и GUI-прогоны не выполнены локально — среда без `libGL`/Qt (apt вне allowlist); baseline обновлён вручную по измеренному инкременту инвентаря нового файла (4 кейса, collected/eligible/selected одинаковы).
