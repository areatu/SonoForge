- `fix(orthanc)`: #554 — запись в управляемый DICOM-кэш стала атомарной, права выставляются при создании, а путь проверяется целиком. Раньше `save_instance` писал `Path.write_bytes` прямо в конечный `i-<hash>.dcm` и только потом делал `chmod 0600`: сбой диска, короткая запись или убитый процесс оставляли усечённый файл под готовым именем, который сканер читал как валидный DICOM, а каталоги создавались с umask по умолчанию. Теперь экземпляр пишется во временный `.pending-<uuid>.tmp` в том же каталоге (`os.open(..., O_CREAT|O_EXCL, 0600)` + `fchmod` до первого байта полезной нагрузки), затем `flush` → `fsync` → `os.replace` → directory fsync (POSIX). Короткий счётчик `write` — это ошибка (`ENOSPC`), а не успех; при любом отказе временный файл удаляется, предыдущая версия экземпляра остаётся нетронутой, а учёт размера сбрасывается. Каталоги (`session-<id>` и `s-<hash>`) создаются с `0700`; `chmod` после `mkdir` только латает каталоги старых сборок и на Windows молча пропускается.
  Идентификатор сессии проверяется как канонический UUID целиком (без `..`, разделителей, переводов строк и URL-кодирования) в `save_instance`, `study_path`, `session_path`, `clear_session` и при разборе `session_id_for_path`; `clear_session` с невалидным id — no-op, `clear_all(preserve_session_ids=...)` игнорирует такие значения. Перед записью проверяется вся цепочка компонентов ниже корня кэша: символическая ссылка на каталог исследования или сессии больше не уводит запись за пределы управляемого хранилища (`OrthancCachePathError`, статическое сообщение без путей и идентификаторов). Сам корень кэша ссылкой быть может — это осмысленный пользовательский выбор тома.
  Проверка: новый `tests/security/test_orthanc_cache_write_safety.py` (34 теста, внесён в `.github/required-tests/security.txt`): отказ на записи/fsync/replace/межпроцессном прерывании не публикует `*.dcm` и не оставляет `.tmp`, короткий счётчик записи отклоняется, предыдущий экземпляр сохраняется, режимы файла и каталогов проверяются на момент fsync, 16 невалидных session id отклоняются до создания каталогов, ссылки на каталог исследования/сессии отклоняются без записи наружу. Существующие `test_orthanc_cache.py`, `test_download_coordinator.py`, `test_orthanc_download_worker.py`, `test_measurement_cache_compatibility.py` и cache-тесты диалога настроек зелёные; `ruff check`/`format`, mypy по модулю, function-length/class-size/broad-excepts/untested-modules — без роста. Ограничения записаны в `SECURITY.md` и `docs/security/data-inventory.md`: это не power-loss evidence (unit-уровневое внедрение отказов), каталог `0700` на POSIX не заменяет ACL-политику развёртывания, шифрование кэша остаётся отдельным решением по модели угроз, а хеш UID в пути не анонимизирует DICOM.
