- `fix(tracker)`: серия падений workflow `Project sync` — первый реальный прогон (bootstrap из PR #170 прошёл, секрет `PROJECTS_TOKEN` настроен) умирал на каждой записи single-select поля с `GraphQL error: Type mismatch on variable $option and argument singleSelectOptionId (ID! / String)`. Причина: в схеме Projects v2 `ProjectV2FieldValue.singleSelectOptionId` — `String` (рядом `text: String`, `number: Float`, `date: Date`), а мутация `_SET_SINGLE_SELECT` объявляла `$option: ID!`; GitHub валидирует операцию целиком до выполнения, поэтому не выполнялась ни одна запись `Status`/`Gate`/`Size`, а падал каждый прогон — событийный, расписания и ручной. Исправлено на `$option: String!` (соседние `projectId/itemId/fieldId` в `UpdateProjectV2ItemFieldValueInput` действительно `ID!`); типы переменных **всех** операций скрипта (15 констант) закреплены таблицей `_EXPECTED_VARIABLES` в `tests/unit/test_project_sync.py`, снятой с живой схемы (`__type(name: ...)`), плюс тест, требующий занести в таблицу любую новую операцию — расхождение со схемой теперь валится в CI, а не в проде. Проверено без записи в доску: та же мутация с синтетическими id на `ID!` даёт ровно ошибку из CI, на `String!` — ошибку исполнения (валидация проходит).
