- `fix(ui, multiview)`: #308 / S2-04 (хвост) — удаление event-маркеров Multiview теперь спрашивает подтверждение. Участие в #308 было незамеченным: в PR #373 стояло `Closes #330 #331 #306 #307 #308`, и GitHub закрыл только #330, поэтому issue остался открытым, хотя undo/redo-стек для контуров и калиперов (`application/measurement_undo_redo.py`, Ctrl+Z/Ctrl+Y, очистка при закрытии вкладки) уже работал. Пробел остался в multiview-маркерах: `remove_marker`, `clear_markers` и `clear_all_markers` снимались необратимо, без undo и без диалога. По правилу issue «для destructive-действий без undo — подтверждение» три пользовательских пути в `comparison_coordinator.py` переведены на `_confirm` (тот же `QMessageBox.question`, что и существующий `on_warning`, default No): `on_marker_remove_requested`, `on_markers_cleared`, `on_all_markers_cleared`. Undo-стек для маркеров намеренно не делался: маркеры — события таймлайна, а не клинические измерения, их сессия переживает вкладку (spec 4.3), и смешивать два источника в одном Ctrl+Z — риск отменить чужой стек. Машиноуправляемые пути без диалога сохранены: загрузка клипа в панель (`load_instance`, spec 6.2) и `reset_session` по-прежнему чистят маркеры молча. Локализация: +6 ключей `multiview.marker.*_confirm_*` в RU и EN. Тесты: `test_comparison_coordinator.py` +7 (decline/accept для remove-marker, clear-pane, clear-all; загрузка клипа чистит маркеры без диалога). ruff check/format, colour/function-length храповики и `tests/unit/test_comparison_coordinator.py` (51) — зелёные; смежные `test_multiview_controller.py` и `test_multiview_session_qh1a2.py` (70) — зелёные. GUI-прогон песочницы невозможен (нет `libGL.so.1`/`libEGL.so.1`, как в PR #373), полный GUI-набор подтверждает CI.
