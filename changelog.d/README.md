# changelog.d — записи об изменениях, ещё не вошедшие в релиз

Один файл — одна запись. Полный текст записи живёт здесь, а `CHANGELOG.md` (раздел `Unreleased`)
хранит только индекс: по одной строке на запись со ссылкой сюда (issue 329: файл на 180 тысяч
символов нельзя было читать).

## Как добавить запись

1. Создайте `changelog.d/NNN-<тип>-<область>-<ссылка>.md`, где `NNN` — следующий свободный номер
   (три цифры, по возрастанию), `<тип>` и `<область>` — из коммит-конвенции (`feat`, `fix`, `refactor`,
   `test`, `docs`, `build`, `ci`; область — `ui`, `arch`, `mypy`, ...), `<ссылка>` — номер issue или ID спеки
   в нижнем регистре (`328`, `ui-4`). Пример: `076-refactor-arch-328.md`.
2. Внутри — одна запись в прежнем формате: «- `тип(область)`: #N — что и зачем, числа до/после, где
   доказательство» (многострочная — можно).
3. Добавьте **в начало** индекса `Unreleased` в `CHANGELOG.md` строку по образцу соседних: краткая сводка
   (первое предложение записи) и в скобках ссылка «полностью» на ваш фрагмент.

`tests/unit/test_docs_links.py` следит за соответствием: каждый фрагмент имеет ровно одну строку индекса,
каждая строка индекса ведёт на существующий фрагмент, индекс остаётся индексом (короткие строки).

## При выпуске релиза

Фрагменты в порядке номеров переносятся в `changelog/YYYY-MM.md` своего месяца (новейшие сверху,
как в остальных файлах), `changelog.d/*.md` (кроме этого README) удаляются, а в `Unreleased`
остаётся строка «выпущено в vX.Y.Z».
