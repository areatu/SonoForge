- `fix(security)`: #414 / #415 / #416 — первый срез аудита 2026-11-02. Переносимые пароли больше не деградируют при недоступном `device.key`: константа-подмена удалена, чтение/создание/валидация ключа теперь либо дают ровно один 32-байтный секрет, либо поднимают `PortableSecretStoreError` со стабильным кодом (`key_invalid`, `key_write_failed`, `encryption_unavailable`, …). Создание ключа эксклюзивно (`O_EXCL`), публикуется через hard link там, где ФС его поддерживает, с `fsync` и `0600`; для FAT/exFAT остаётся эксклюзивная запись с проверкой точного формата читателем. Ключ проверяется на диске при каждом чтении/записи (кэш Fernet привязан к точным байтам ключа, а не только к корню), а при наличии уже записанных ciphertext новый ключ не создаётся — это бы сделало старые токены нечитаемыми (`key_missing_with_secrets`). Fallback на plaintext и системный keychain убран: ни при одной ошибке ключа новый пароль не сохраняется, прежний ciphertext не перезаписывается, legacy-значение не удаляется молча, в логах только код ошибки, а UI показывает `PasswordSaveStatus` с локализованным предупреждением RU/EN.

  Встроенный Storage SCP для C-MOVE стал loopback-only: `is_loopback_bind_host` принимает только разобранные loopback-литералы (`127/8`, `::1`, IPv4-mapped loopback) и ровно `localhost`, отказывая `0.0.0.0`, `::`, DNS-именам и look-alike адресам. Отказ происходит до создания AE и до открытия сокета (`StorageSCPBindError`), форма настроек и `UserPreferencesDialog` не дают сохранить удалённый bind, а `CMoveRetrieveAdapter` превращает отказ в `RetrieveError(code="scp_bind_rejected")`. AE title не считается аутентификацией; удалённый приём в 0.x объявлен неподдерживаемым, а не молча разрешённым. `SECURITY.md` получил рабочий приватный канал disclosure: Private Vulnerability Reporting включён в репозитории, ссылка из `.github/ISSUE_TEMPLATE/config.yml` ведёт прямо на `/security/advisories/new`, описаны состав отчёта без PHI/учётных данных и координированное раскрытие без невыполнимого SLA.

  Доказательство: 31 новый security-тест (`tests/security/test_portable_credentials.py`, `tests/security/test_scp_bind_policy.py`) — повреждённый/отсутствующий ключ, отказ создавать новый ключ при наличии ciphertext, проверка что кэш Fernet не переживает удаление ключа, read-only носитель, сбой записи, параллельный первый запуск (24 потока → один ключ), сохранение legacy-значения, стабильный код отказа, отсутствие пароля в файлах и логах, отсутствие вызова `keyring.set_password`, loopback C-MOVE без регрессии; оба файла добавлены в `.github/required-tests/security.txt`.
