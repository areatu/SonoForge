- `fix(setup)`: #326 (закрытие остатка) — диалог первого запуска больше не отвечает «успех» всегда, а установка зависимостей говорит, что именно случилось. **Диалог врал о результате.** `show_setup_dialog()` возвращал `worker.isRunning() or not worker.isRunning()` — то есть `True` при любом исходе: сломанное окружение выглядело установленным. Теперь `SetupWorker` хранит итог (`self.result`), диалог возвращает `worker.result is True`, а после `exec()` ждёт поток, если окно закрыли раньше — прервать pip нельзя, и брошенный за спиной поток означал бы половину установленного окружения. Сама последовательность вынесена в `run_setup_tasks(status, progress, *, frozen)`: зависимости → модели, первая неудача останавливает цепочку, `frozen`-сборки ставят только модели; функция юнит-тестируема без Qt. **Ошибки стали различимыми.** Было одно сообщение на все случаи, а провал создания venv не доходил до пользователя вовсе. Добавлены стабильные коды причин и таблица фраз (`venv_failed`, `pins_missing`, `pip_missing`, `mode_invalid`, `pip_failed`, `pip_failed_network`, `pip_failed_hash`, `pip_failed_unavailable`, `verify_failed`) плюс классификатор `_pip_failure_reason(stderr)`: «нет сети», «пакет не прошёл проверку хеша» и «пакета нет в индексе» требуют разных действий и теперь звучат по-разному. Вывод pip (пути, индексы, хеши, трассировка) не показывается никогда — только код в лог и одна фраза пользователю. **Проверка импортов честнее.** `check_deps()` считает отсутствующим и модуль, который импортируется, но не грузит нативную библиотеку (`OSError`: нет `libGL`, нет VC-рантайма, обрезанная нативная сборка) — раньше такой модуль проходил проверку, и диалог объявлял «Dependencies installed.» над окружением, падающим при первом использовании. **Гейт в `main.py` сознательно остался дешёвым** (файловая проверка моделей): полная проверка импортов стоит ~1.5 с прогретого кеша на каждом запуске, а первый запуск всегда идёт без моделей, поэтому диалог открывается и ставит зависимости до скачивания моделей; решение и цифра записаны комментарием рядом с гейтом. **Тесты:** +24 логических в `tests/unit/test_runtime_setup.py` — идемпотентность (повторный запуск не пересоздаёт venv), «в argv pip нет имён модулей» (`cv2`, `yaml`, `PIL`, `fitz`, любой элемент `_REQUIRED_MODULES`), классификация пяти видов stderr, единственная строка без трассировки для каждой из девяти причин, отказ при отсутствии пинов, провал создания venv, неисполняемый pip, провал верификации после успешного pip, порядок «зависимости → модели» и короткое замыкание, `frozen` без установки, `OSError` при импорте = отсутствующая зависимость, готовое окружение не строит диалог.
