- `feat(profiles)`: профиль исследования открывает свой блок панели и свой отчёт — «Анатомия и патология» по умолчанию раскрывает блок профиля («Почки», «Брюшная полость», «Щитовидная железа», «Сосуды»; эхокардиография остаётся на «Общих»), а отчёт печатает измерения только выбранного исследования: в одном снимке эхо и щитовидная железа больше не смешиваются, и протокол щитовидной железы не содержит КДР/КСР и чисел Тейхольца, выведенных из чужих измерений. Сохранённые измерения не меняются — возврат профиля возвращает весь отчёт.

  **Почему.** Владелец прислал снимок экрана: в шапке выбрано «Щитовидная железа», а в панели активна вкладка «Общие», и отчёт «УЗИ щитовидной железы» содержит «Расчёты» (Тейхольц: КДО/КСО/ФВ/УО), хотя щитовидную железу измеряли отдельно. Смысл переключения типа исследования — измерять этот орган; и протокол должен рассказывать про одно исследование, а не про папку целиком.

  **Панель.** В доменной модели появился `PanelView.default_section`: профиль органа или сосуда раскрывает свой блок, эхокардиография — «Общие» (общее исследование сердца). Контекст без такого блока (M-режим у почечного профиля) раскрывает первый доступный, пустой — не раскрывает ничего. Ручной выбор врача сохраняется: смена профиля очищает запомненный блок (`ToolPanelV2.set_preferences` сравнивает `study_profile`), внутри одного профиля поведение прежнее.

  **Отчёт.** Новый домен-сервис `domain/services/report_scope.py`: измерение принадлежит исследованию, если каталог отображает подпись его калипера на инструмент этого профиля (`CALIPER_TO_MEASUREMENT` → инструменты-производители → `StudyProfile.allows`/`allows_tool`). Для некардиологических профилей дополнительно убираются производные эхокардиографические результаты (Тейхольц, Симпсон, ФВ, допплер, индексирование, расчёты) — иначе цифры остались бы в протоколе без своих измерений. Свободный калипер с неизвестной каталогу подписью остаётся (это наблюдение об органе на экране), «Площадь» есть во всех профилях, сплайновый «Объём» — только в эхокардиографии. Сужение применяется один раз в `build_report_document(study_profile_id=…)` до сборки групп, поэтому предпросмотр, PDF, CSV и JSON видят один документ; главное окно передаёт профиль вкладки всегда, пустой `study_profile_id` сохраняет прежнее поведение для вызовов, которые о профилях не знают.
