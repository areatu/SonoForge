- `fix(calibration)`: #547 — масштаб выбирается по геометрии измерения, а не по активному клипу. `ViewerState.calibration_for_points` / `select_calibration_for_points` выбирают frame/panel-контекст под контуром; пересечение границы панелей и неоднозначный scoped-масштаб дают отказ, а не чужую калибровку.
  Потребители завершены: площадные/объёмные контуры, Simpson/LA/RA/RV и `merge_simpson_areas` считают каждый контур по его собственному масштабу; `calculation_contours` переводит контуры чужих клипов в сетку активного только по их собственному frame/panel-контексту и выбрасывает неоднозначные из физического результата. Сохранение больше не подставляет spacing первого источника: если контуры записи не сводятся к одному масштабу, `simpson_basis` не замораживается, а refresh-статус остаётся unverified.
  Политика `ASSUMED` явная: `CalibrationContext.assumption` (`isotropic_manual`, `imager_plane`, `nominal_scanned`, `seconds_as_length`), `needs_assumption_note`; `MEASURED` не может нести assumption, `UNKNOWN` не считается калибровкой. Вендорная эвристика «секунды вместо длины» остаётся только для 2D tissue region и помечается как предположение.
  Проверка: новый `tests/unit/test_calibration_consumers.py` — матрица потребителей (геометрия, planimetry, Simpson, persistence, area curve, frame/panel selection, политика assumption). M-mode оси пока остаются на собственном `MmodeCalibrationState` и в этот контракт не входят; видимая подпись assumption в UI — отдельный следующий шаг.
