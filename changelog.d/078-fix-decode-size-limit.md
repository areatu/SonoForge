- `fix(decode)`: #313 / S3-04 (отмена) — исследование больше не отклоняется по размеру. **Что было сломано.** В `3316c7e` появился `infrastructure/pixel_budget.py` с жёстким порогом `MAX_DECODED_PIXELS = 200_000_000` и двумя проверками в `DicomSession._open_impl` (до и после восстановления `NumberOfFrames`). Легитимная длинная петля — минута 512×512 при 30 fps, то есть ~1564 кадра и ~410 Мпикс, — отсекалась до декодирования: в статус-баре было «Исследование слишком велико для декодирования: 410 Мпикс при пределе 200 Мпикс», а в галерее «Frame loading failed». Для 16-битных данных тот же цикл — ~820 Мпикс, для RGB — втрое больше на кадр; порог срабатывал на обычных клинических исследованиях, а не на патологических заголовках. **Что сделано.** Модуль `pixel_budget.py` удалён, проверки и метод `_enforce_pixel_budget` убраны из `DicomSession`, отдельная ветка отказа и `_study_too_large_message` — из `DicomDecodeWorker`, ключ `status.study_too_large` — из `en.json`/`ru.json`. В `_open_impl` оставлен комментарий-предупреждение: размер исследования не является критерием отказа; память ограничивают frame cache и memmap-путь для несжатых пиксельных данных, а не порог в заголовке. Заодно снят лимит 500 МБ в `dicom_validator.validate_dicom_header`: по умолчанию `max_size_bytes=None` (необязательный guard остаётся для явных вызовов), чтобы длинная 16-битная петля не отсекалась на этапе валидации файла. **Тесты.** `tests/unit/test_pixel_budget.py` (23 кейса, проверявших сам порог) удалён; вместо него `tests/unit/test_dicom_decode_large_study.py` — 7 кейсов: открытие 410-Мпикс 8-битной петли (512×512×1564), той же петли в 16 бит (~820 Мпикс), RGB-петли на 236 Мпикс, отсутствие хука `_enforce_pixel_budget`, отсутствие ключа `status.study_too_large` в обеих локалях, отсутствие ветки отказа в worker'е и отсутствие лимита по умолчанию в `validate_dicom_header`. Все три крупных фикстуры открываются и рапортуют полное число кадров; baseline инвентаря pytest пере-базирован: 9881 → 9865 (`not_gui` 5928 → 5912; 23 удалённых кейса заменены 7, `gui` и `gui_files` без изменений). **Проверки:** новый набор зелёный (`pytest tests/unit/test_dicom_decode_large_study.py`), `test_dicom_session` и `test_i18n` — без регрессий; `ruff`/`mypy` по изменённым модулям — чисто.
